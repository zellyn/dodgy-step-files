## OCCT source pointer + prose

- **Path**: `src/ModelingAlgorithms/TKShHealing/ShapeFix/ShapeFix_FixSmallFace.cxx`
- **Line range**: 442–474 (endpoint-pair merge logic inside the strip-face shared-edge constructor).
- **Branch (prose-laundered)**: When constructing the shared edge between a small "strip" face and its neighbour, ComputeSharedEdgeForStripFace inspects the four endpoint pairs (start-start, start-end, end-start, end-end) for proximity. The check is done sequentially: the first pair is tested for `dev < tol` and merged immediately if it passes; the second pair is then tested independently with no information about whether the first merge succeeded. If pair 1 (V1↔V3) is within tolerance but pair 2 (V2↔V4) is not, the result is a "shared" edge with one matched vertex and one unmatched — geometrically incoherent.

- **Result**: The endpoint-mismatch geometry is correct, but the fixture's wires are *single-edge* loops. The ComputeSharedEdgeForStripFace branch only fires inside the strip-face fixing pipeline, which traverses multi-edge wires looking for sliver pairs. A single-edge wire is too thin a setup to invoke the strip-face path.

## Why it's hard

ComputeSharedEdgeForStripFace is downstream of strip-face *detection*. The healer first has to classify the face as a strip (long, thin, with specific aspect-ratio constraints) before reaching the shared-edge construction logic. So a fixture has to (a) make the face strip-classifiable AND (b) carry the endpoint-asymmetry geometry. Both layers need to be right.
