## OCCT source pointer + prose

Branch (prose-laundered): ShapeFix_Solid maintains internal state
across multiple Perform() invocations. The second Perform() call
may inherit stale context from the first run (e.g. cached face
orientation decisions, accumulated tolerance shifts) — producing
output that differs from a fresh Perform() on the same input.

## Why it's hard

This is a `kernel-test-pair` candidate. Demonstrating the bug
requires:
1. Load the fixture's shell
2. Construct `ShapeFix_Solid sf(shell)`
3. Call `sf.Perform()` — first pass orientation fix
4. Construct or modify *another* solid that should be processed
   cleanly
5. Pass the new solid into the same `sf` instance
6. Call `sf.Perform()` again
7. Observe the second result is contaminated by first-pass state

None of steps 2-7 can be encoded in Part-21.
