## OCCT source pointer + prose

Branch (prose-laundered): MakeBSpline reconstructs a B-spline surface
from a sampled point grid. The reconstructor uses an FFT-like
heuristic to detect periodicity (e.g. Z-wave), but the check matches
on pattern alone without verifying endpoint-height equality — so a
quasi-periodic grid whose endpoints don't actually meet is declared
periodic and the resulting surface is closed where it shouldn't be.

## Attempts

### Attempt 1 (wave 55, 2026-06-17) — INVALID

- **Approach**: B_SPLINE_SURFACE_WITH_KNOTS with quasi-periodic Z-pattern grid.
- **Refutation**: B-spline knot multiplicity invariants violated.
  Per Part-21: `sum(knot_multiplicities) = n_control_points + degree + 1`.
  The fixture's U-knot vector and V-knot vector don't sum correctly for
  the declared (degree=3 in U, degree=2 in V) and pole count.

## Why it's hard

B-spline arithmetic requires careful coordination between control-net
size, degree, knot count, and knot multiplicities. The Haiku synthesizer
seems to default to "5 uniform knots" without computing the actual
required count.

## Next directions

- Compute knot vector explicitly: for a 5x4 control net at degree (3, 2),
  U knots need `5 + 3 + 1 = 9` multiplicity sum, V knots `4 + 2 + 1 = 7`.
  Standard clamped B-spline: `(4, 1, 1, 1, 4)` for degree 3 / 5 poles
  in U gives `4+1+1+1+4 = 11 ≠ 9`. Actually for an open clamped knot
  vector with degree p and n poles: knot count is `n + p + 1`,
  multiplicities at endpoints are `p + 1`. So for 5 poles, degree 3:
  knots are `(0, 0, 0, 0, m, 1, 1, 1, 1)` — 9 knot VALUES with one
  middle. For 5 poles, degree 2: knots are `(0, 0, 0, m, n, 1, 1, 1)`
  — 8 knots.
- Add the knot-multiplicity-sum invariant check to synthesis prompt.
