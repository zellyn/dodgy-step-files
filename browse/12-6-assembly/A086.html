A086 — Step exporter not respecting `write.step.schema` configuration

§12.6 assembly

P1 — silent data loss

Description

A writer is configured to emit AP203, but the output file carries `FILE_SCHEMA` for AP214 because the schema-write code consults a module-static variable initialised at first call (lazy-init, fixed). Subsequent reconfiguration is ignored.

Reproducer recipe

Open writer, set `write.step.schema=AP203`, write file. Reopen, set `write.step.schema=AP214`, write file. Both files declare the *first* schema selected.

Expected kernel behavior

Heal and accept: every export consults the current configuration; no lazy-init module state for output schema. Must not silently ignore configuration.

Notes

Provenance tier: runtime-only — writer ignores configuration flag; runtime config behavior.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Provenance tier

runtime-only — defect not fully embodied in fixture bytes.

Byte assertions

  • contains(b'Writer ignores write.step.schema') or contains(b'write.step.schema')
