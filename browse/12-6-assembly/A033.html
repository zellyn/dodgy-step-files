A033 — `applied_external_identification_assignment` /`product_definition_with_associated_documents` name dropped

§12.6 (sub-class: product naming / external doc assoc)

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A033.stp

Sources

  • G052 (OCCT 3b739e6 / Mantis 0030789), R061 (OCCT bug30789).

Description

`PRODUCT_DEFINITION_WITH_ASSOCIATED_DOCUMENTS` carries its own `name` attribute that OCCT did not pick up; specific entity-name patterns silently dropped on import.

Reproducer recipe

STEP file using PRODUCT_DEFINITION_WITH_ASSOCIATED_DOCUMENTS instead of plain PRODUCT_DEFINITION.

Expected kernel behavior

Heal and accept: honor name from this entity in all readers; must not silently drop the name.

Notes

**See also**: A010. Synonyms: "applied_external_identification_assignment name lost", "product_definition_with_associated_documents name dropped", "external doc-id stripped on round-trip", "PLM document reference name disappears".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'PRODUCT_DEFINITION_WITH_ASSOCIATED_DOCUMENTS')
  • contains(b'APPLIED_EXTERNAL_IDENTIFICATION_ASSIGNMENT')
