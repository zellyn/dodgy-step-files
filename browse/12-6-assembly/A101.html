A101 — SubShapeBinder-derived Boolean Cut crashes downstream slicers and re-import

§12.6 assembly hierarchy

P0 — receiver crash / hang / OOM

crash assembly

View raw fixture (.stp) step-examples/12-6-assembly/A101.stp

Sources

  • FreeCAD #26994
  • bug-reporter language: "Export of PartDesign body containing Boolean Cut with SubShapeBinder is broken", "PrusaSlicer just crashes for STEP", "the very STEP exported by FreeCAD makes it crash on re-import".

Sender

FreeCAD PartDesign body whose history includes a Boolean Cut whose tool comes from a SubShapeBinder cross-document reference.

Description

A body authored as `BasePad → BooleanCut(tool=SubShapeBinder('Other_Body.Face'))` exports a STEP whose `MANIFOLD_SOLID_BREP` contains `ADVANCED_FACE`s with `EDGE_CURVE` references that point to entity numbers existing in the file but whose `EDGE_LOOP` contains an `ORIENTED_EDGE` whose `edge_element` is `*` (asterisk-implicit) without the matching parent definition — in other words, `*`-oriented edges escape into the file body. The receiver attempts to dereference and crashes (PrusaSlicer) or yields empty (FreeCAD self-import).

Reproducer recipe

STEP body where one `EDGE_LOOP` contains an `ORIENTED_EDGE('',*,*,#99,.T.)` referencing `#99` whose `edge_element` is itself `*`.

Expected kernel behavior

writer materialises every `*`-implicit reference before emission; receivers reject `*` `edge_element` with a precise diagnostic.

Notes

**See also**: A018. Synonyms: "SubShapeBinder Boolean Cut crashes slicer", "asterisk edge element escapes file body", "STEP makes PrusaSlicer crash on import", "boolean from SubShapeBinder broken on export".

Expected validation

occt=shape(1)/shape(1) gmsh=reject ifc=schema_n/a

Byte assertions

  • matches(rb'ORIENTED_EDGE\s*\([^)]*,\*,\*')
  • contains(b'EDGE_LOOP')
