A105 — Regression OCC 6.9.1 → 7.4.0: colours stop appearing on certain STEP files

§12.6 assembly hierarchy (sub-class: appearance regression across kernel versions)

P1 — silent data loss

Sources

  • OCCT MANTIS#0031809
  • bug-reporter language: "regression v.6.9.1-7.4.0 colors no longer showing on certain STEP files", "files that displayed colour in 6.9.1 are grey in 7.4.0", "appearance regression". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

STEP files emitted by older toolchains that use the `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION` route for colours rather than the per-face `STYLED_ITEM` route.

Description

A STEP file declares colours through `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION` containing `STYLED_ITEM`s that point at the assembly-occurrence level rather than per-face. The 6.9.x reader resolved these and assigned colours; the 7.4.0 reader's refactored colour pipeline only consults the per-face route, so the file's colours are silently dropped. A regression — the producer is unchanged; the receiver lost coverage.

Reproducer recipe

STEP file with `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION` containing one `STYLED_ITEM` pointing at a `SHAPE_REPRESENTATION`. 6.9.x renders red; 7.4.0+ renders grey.

Expected kernel behavior

heal-and-accept — every recognised colour-assignment path (per-face, per-occurrence, per-representation, draughting-presentation) must contribute to XCAF; emit `W_LEGACY_COLOUR_ROUTE` rather than dropping the assignment.

Notes

**See also**: A103, A081. Synonyms: "regression colours no longer showing on STEP files", "OCC 7.4 colour pipeline regression", "MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION colour dropped", "appearance lost across kernel versions".
