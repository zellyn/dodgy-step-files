A034 — CheckSRRReversesNAUO segfault on SDR with SHAPE_ASPECT instead of PROPERTY_DEFINITION

§12.6 (sub-class: assembly graph / SDR variant)

crash assembly

View raw fixture (.stp) step-examples/12-6-assembly/A034.stp

Sources

  • I001 (OCCT #1202).

Sender

CATIA V6 "Fast Export STEP AP214 Mapper" (1088/1267 SDRs in a real 430MB file used the SHAPE_ASPECT variant).

Description

`SHAPE_DEFINITION_REPRESENTATION` whose `Definition` member of the `RepresentedDefinition` SELECT is a `SHAPE_ASPECT` rather than `PROPERTY_DEFINITION`. OCCT's unguarded chain `SDR->Definition().PropertyDefinition()->Definition().ProductDefinition()` returns null on the SHAPE_ASPECT branch and crashes.

Reproducer recipe

AP214 file with `#27=SHAPE_DEFINITION_REPRESENTATION(#23,#26)` where `#23` is a `SHAPE_ASPECT` instead of `PROPERTY_DEFINITION_SHAPE`.

Expected kernel behavior

heal; skip SDRs whose Definition is not PropertyDefinition; emit warning; never deref blindly.

Notes

**See also**: A009. Validation observed: silent-empty rather than crash. Kernel-mishandling-by-silent-acceptance still demonstrates the defect class. Synonyms: "CheckSRRReversesNAUO crashes with SHAPE_ASPECT instead of PROPERTY_DEFINITION", "segfault during assembly check", "SDR with shape_aspect breaks reader", "STEP reader null-deref on assembly traversal".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'SHAPE_ASPECT')
  • contains(b'catia_aspect')
  • contains(b'SHAPE_DEFINITION_REPRESENTATION(#90,')
