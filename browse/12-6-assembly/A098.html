A098 — Writer-emitted STEP cannot be re-imported by the same writing process (round-trip refused)

§12.6 assembly hierarchy

P1 — silent data loss

round-trip assembly

View raw fixture (.stp) step-examples/12-6-assembly/A098.stp

Sources

  • FreeCAD #11728, #17839
  • bug-reporter language: "Once a FreeCad file is exported to step, the same step file cannot be opened in FreeCad", "Importing the step file in same RC2 only gives a single error and no imported geometry", "round-trip into the same version is broken".

Sender

FreeCAD 1.0RC2 (and earlier stretches): export pipeline emits a file that the import pipeline of the same build silently rejects.

Description

A file authored in build N, exported as STEP from build N, and re-imported into build N produces zero geometry; yet the same file imports cleanly into build N-1. The signature is a `SHAPE_REPRESENTATION` whose `AXIS2_PLACEMENT_3D` first attribute (`location`) refers to a `CARTESIAN_POINT` that was emitted *after* the `SHAPE_REPRESENTATION` in the file but referenced from within (forward reference is legal per ISO 10303-21 §11 but the build-N reader has a regression in its forward-reference resolver).

Reproducer recipe

STEP file where `#10=SHAPE_REPRESENTATION('part',(#100),#101);` appears before `#100=AXIS2_PLACEMENT_3D('',#150,#151,#152);` and `#150=CARTESIAN_POINT('',(0.0,0.0,0.0));` — every reference is forward-only.

Expected kernel behavior

forward references are spec-legal; the importer must do a two-pass parse. Reject with a clear diagnostic rather than silent-empty if forward resolution fails.

Notes

Synonyms: "self-import refused", "round-trip with same version broken", "freecad cannot read its own export", "RC2-exported STEP fails RC2 import".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Byte assertions

  • contains(b'SHAPE_REPRESENTATION')
  • matches(rb'#10\s*=\s*SHAPE_REPRESENTATION')

Tier-3 assertions

  • shape_null == False
  • n_faces_total == 1
  • n_edges_total == 4
  • n_vertices_total == 8
