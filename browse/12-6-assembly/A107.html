A107 — `BinXCAF` regression: documents with colour cannot be re-loaded after save

§12.6 assembly hierarchy (sub-class: persistence-format regression)

P1 — silent data loss

round-trip assembly

Sources

  • OCCT MANTIS#0031324
  • bug-reporter language: "regression to OCCT 7.4.0 cannot read BinOcaf document with colour", "BinXCAF colour read fails after 7.4 upgrade", "binary OCAF format colour regression". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

OCCT's own `BinXCAFDrivers` persistence layer when saving a document that has colour assignments and reading it back with a different (newer) kernel build.

Description

A document with `XCAFDoc_ColorTool` assignments is saved to `BinXCAF` (binary `.xbf`). When reloaded by 7.4.0+, the colour-driver registration order changed: the binary stream is parsed but the colour records hit an unknown driver tag and are silently discarded. The geometry reloads, the colours do not. This is a forward-compat regression in the persistence format; round-tripping through STEP exposes the same colour-loss path.

Reproducer recipe

Document with one box, one colour assignment. Save BinXCAF in 6.9.x. Reload in 7.4.0+. Colours absent.

Expected kernel behavior

heal-and-accept — the persistence layer registers all historical driver tags; emit `W_UNKNOWN_DRIVER_TAG` and skip rather than corrupting the file. Round-trip through STEP must preserve colour.

Notes

**See also**: A105, A081, U036. Synonyms: "regression cannot read BinOcaf document with colour", "BinXCAF colour driver tag unknown", "persistence format regression after 7.4", "OCAF colour lost on reload".
