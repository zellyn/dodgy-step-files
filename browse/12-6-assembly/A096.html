A096 — `STEPCAFControl_Writer` skips a shape when it has identity location and partner shapes have non-identity locations

§12.6 assembly hierarchy (sub-class: writer drops identity-located instance)

P1 — silent data loss

Sources

  • OCCT MANTIS#0030998
  • bug-reporter language: "STEPCAFControl_Writer will not export shape with Identity Location if there are other partner shapes with diff Location", "writer drops identity-placed instance from assembly", "STEP export skips master shape". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

OCCT's `STEPCAFControl_Writer` when exporting an assembly with multiple instances of the same part, where one instance is at the identity transform and others are placed.

Description

An assembly contains three instances of the same part: one at the world origin (identity location) and two placed by transforms. The writer's de-duplication pass mistakes "identity location" for "no instance" and skips the world-origin instance entirely. Output file has the part placed twice instead of three times. Asymmetric — the bug only manifests when at least one instance is at identity AND at least one instance has a non-identity transform.

Reproducer recipe

Assembly with one `NEXT_ASSEMBLY_USAGE_OCCURRENCE` whose location is identity, plus two more whose locations are non-identity. Output drops the identity-placed instance.

Expected kernel behavior

heal-and-accept — every distinct `NEXT_ASSEMBLY_USAGE_OCCURRENCE` corresponds to one emitted instance regardless of its location's identity; never use "is identity transform" as a skip predicate.

Notes

**See also**: A082, A104. Synonyms: "STEPCAFControl_Writer drops identity-placed instance", "writer skips identity-location instance with partners", "STEP export missing assembly instance", "identity-transform instance not exported".
