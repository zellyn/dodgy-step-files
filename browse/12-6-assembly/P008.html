P008 — Long helix represented as huge B-spline causes catastrophic import time

§12.10 scale/performance

P2 — spec deviation (no data loss)

Sources

  • FreeCAD #18735, #18151

Sender

SolidWorks (`EixoY.STEP`); thread-profile tools

Description

A single long thread/helix represented as a `B_SPLINE_CURVE_WITH_KNOTS` with thousands of control points (e.g. M10×300 thread) takes >1 hour in FreeCAD vs. <1 minute in SolidWorks/VariCAD. The helix dominates cost; rest of model is fast.

Reproducer recipe

STEP file with one helical sweep represented as a NURBS curve with 5000+ control points spanning many turns, plus minimal capping faces.

Expected kernel behavior

Heal and accept: linear scaling with face count, not catastrophic. Must not hang on long helix.

Notes

**See also**: Pf014. Synonyms: "long helix becomes huge B-spline that takes forever to import", "spring/screw thread import hangs", "helical curve approximation explodes file size", "catastrophic import time on long helix".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(3) ifc=schema_n/a

Byte assertions

  • contains(b'B_SPLINE_CURVE_WITH_KNOTS') or contains(b'B_SPLINE')

Tier-3 assertions

  • shape_null == False
  • n_edges_total == 1
  • n_vertices_total == 2
