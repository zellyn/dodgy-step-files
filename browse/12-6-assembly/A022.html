A022 — PRESENTATION_LAYER_ASSIGNMENT collisions / namespace abuse

§12.6 (sub-class: presentation_layer_assignment vs styled_item)

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A022.stp

Sources

  • G110 (OCCT 96049f2 / Mantis 0032049: layers with empty/identical names), G049 (empty PLA), Y014 (CST Microwave Studio uses PLA for materials), R060 (layers count mis-read).

Description

Multiple `PRESENTATION_LAYER_ASSIGNMENT` instances with identical names but different visibility flags collide; OCCT did not differentiate them. Empty PLA caused exception. Some producers (CST) use PLA to encode physical-group / material semantics rather than visibility, which OCCT XCAF only honors for visibility, silently dropping material data.

Reproducer recipe

STEP with two `PRESENTATION_LAYER_ASSIGNMENT` of identical name but different visibility flags. Or `PRESENTATION_LAYER_ASSIGNMENT('Copper', 'meshable', (#42, #43))` referencing shells.

Expected kernel behavior

Heal and accept: group layers by (name, visibility) tuple; surface PLA names as queryable group attributes; accept empty PLA.

Notes

**See also**: M043, M044, M046. Synonyms: "two layers with the same name collide", "PRESENTATION_LAYER_ASSIGNMENT name conflicts", "layer namespace clashes between subassemblies", "duplicate layer names confuse reader".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(2) ifc=schema_n/a

Tier-3 assertions

  • face[0].sliver_aspect_max_min > 1e6
  • face[1].sliver_aspect_max_min > 1e6
  • face[0].surface_type == "plane"
  • face[1].surface_type == "plane"
