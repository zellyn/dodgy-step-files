A099 — PartDesign Body export omits last-feature operation when feature is the visible Tip

§12.6 assembly hierarchy

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A099.stp

Sources

  • FreeCAD #25567
  • bug-reporter language: "STEP Export of Body leaves out last operation", "the pocket is not included even though it is visible and set as the tip", "exported file looks like the body before the last feature".

Sender

FreeCAD PartDesign Body whose visible Tip is the last operation (e.g., a Pocket) but where the document's "exported feature" pointer is one revision behind.

Description

A Body whose linear feature stack is `Pad → Fillet → Pocket` with the Tip set to `Pocket` exports as `Pad → Fillet` only. The visible result in the 3D view shows the Pocket; the STEP file has it stripped. The on-disk symptom is a `MANIFOLD_SOLID_BREP` that lacks the inner `FACE_OUTER_BOUND` corresponding to the pocket walls; every face of the pre-pocket Pad+Fillet shape is present, but no pocket-bottom face nor pocket-wall faces.

Reproducer recipe

STEP solid representing a 20 mm cube with a fillet on one edge but no pocket — even though the catalog entry claims the body is "cube, filleted, pocketed".

Expected kernel behavior

Heal and accept: writer emits the visible Tip; or warn and accept with a diagnostic when the in-memory model and the exported feature pointer disagree. Loading stale geometry without diagnostic is a coverage gap.

Notes

Synonyms: "PartDesign Tip not exported", "last feature missing from STEP", "pocket dropped on STEP export", "exported body is one feature behind the Tip".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(48) ifc=schema_n/a

  • contains(b'MANIFOLD_SOLID_BREP')
  • count_entity_def(b'ADVANCED_FACE') >= 6

Tier-3 assertions

  • n_faces_total == 6
