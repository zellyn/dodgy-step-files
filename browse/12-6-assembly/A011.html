A011 — Naming collision: same component referenced by colliding `PRODUCT.name` across sub-assemblies

§12.6 (sub-class: naming collisions / non-unique part names)

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A011.stp

Sources

  • I021/I077 (CadQuery on KiCad mobo-3D), J018 (SolidWorks/AutoCAD "Duplicate Definition of Block"), V050.

Sender

KiCad STEP writer; large-assembly producers that emit one PRODUCT per use site instead of reusing one PRODUCT with N NAUOs.

Description

STEP exports either reuse one sub-model for many capacitors etc. (KiCad), or emit the same physical component as multiple distinct `PRODUCT_DEFINITION`s (one per sub-assembly use site). Receivers keyed on label-as-primary-key (CadQuery) raise ValueError; AutoCAD reports "Duplicate Definition of Block 1 ignored". FreeCAD silently appends an index.

Reproducer recipe

STEP with N NAUO rows referencing one PRODUCT named "Cap"; load via `cadquery.Assembly.load`. Or 1000 distinct PRODUCTs named "Bolt_001" with bit-identical geometry.

Expected kernel behavior

Heal and accept duplicates by treating entity IDs (`#NNN`) as primary keys; names are descriptive; disambiguate names on import; never fail on duplicates. Detect by-geometry duplicates; offer to deduplicate on import.

Notes

**See also**: N044. Synonyms: "two parts with same name confused on import", "PRODUCT name collision between subassemblies", "duplicate component names cause wrong wiring", "import merges differently-located parts that share a name".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

  • count_entity_def(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE') == 3
  • count(b"'Cap'") >= 3

  • n_vertices_total == 8
