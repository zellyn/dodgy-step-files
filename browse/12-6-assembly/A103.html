A103 — Geometry imports correctly but every face arrives with no colour assigned

§12.6 assembly hierarchy (sub-class: appearance dropped on import)

P1 — silent data loss

Sources

  • OCCT MANTIS#0032728
  • bug-reporter language: "STEP model is imported with no colours", "all faces appear default grey", "colours present in file are not picked up by reader". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Authoring tools that emit `STYLED_ITEM` colour assignments at the assembly-occurrence level rather than per-face, or that route colour through `MECHANICAL_DESIGN_PRESENTATION_REPRESENTATION_WITH_DRAUGHTING` which the reader's first pass may skip.

Description

A STEP file has well-formed `COLOUR_RGB` records and `PRESENTATION_STYLE_ASSIGNMENT`s wired to faces, but the reader's `XCAFDoc_ColorTool::SetColor` does not pick them up. The geometry imports cleanly, but the resulting `XCAFDoc_DocumentTool` has no colour assignments at all; every face is the default grey. The producer's intent (red shaft, blue housing) is silently lost.

Reproducer recipe

STEP solid with `STYLED_ITEM` referring to `PRESENTATION_STYLE_ASSIGNMENT` containing `SURFACE_STYLE_USAGE` with `SURFACE_SIDE_STYLE` and `SURFACE_STYLE_FILL_AREA` plus `FILL_AREA_STYLE_COLOUR` pointing at `COLOUR_RGB`. Reader imports geometry but no colour reaches XCAF.

Expected kernel behavior

heal-and-accept; every `STYLED_ITEM` whose target resolves to a known shape contributes a colour assignment to XCAF; unresolved styles emit `W_UNREACHED_STYLE` but never silently disappear.

Notes

**See also**: A105, A081. Synonyms: "STEP model imported with no colours", "colours present in file lost on import", "STYLED_ITEM not reaching XCAFDoc_ColorTool", "appearance dropped during STEP read".

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'COLOUR_RGB')
