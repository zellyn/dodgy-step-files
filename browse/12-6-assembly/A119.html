A119 — `MAPPED_ITEM` with a resolvable `REPRESENTATION_MAP` + real target shape, but an unrecognized-type placement reference

deduced — OCCT uncovered-class sweep

Description

A `MAPPED_ITEM` whose `mapping_source` is a genuinely resolvable `REPRESENTATION_MAP` pointing at a real target `SHAPE_REPRESENTATION` with live geometry, but whose `mapping_target` is a plain `CARTESIAN_POINT` — neither a `CartesianTransformationOperator3d` nor an `Axis2Placement3d`. Both of `TransferEntity(MappedItem)`'s placement-resolution branches fail (`ok=False`); the reader emits `"Mapped Item, case not recognized, location ignored"` but still binds and returns the already-resolved shape UNTRANSFORMED (identity placement) rather than dropping it.

Reproducer recipe

`REPRESENTATION_MAP(#origin_placement,#real_target_shape_representation)` (resolvable) plus `MAPPED_ITEM('name',#representation_map,#cartesian_point)` where `#cartesian_point` is an ordinary `CARTESIAN_POINT`, not a placement or transform-operator type.

Expected kernel behavior

reject the `MAPPED_ITEM` as malformed (its placement reference must be one of the two recognized types), or clearly flag that the instance was loaded un-positioned rather than silently defaulting to identity.

Notes

Fixes Tfa248's gap: Tfa248 puts an empty string (`''`) where `mapping_source` belongs and the `REPRESENTATION_MAP` itself in the `mapping_target` slot — a malformed empty-string source slot that risks aborting the transfer before the identity-fallback-with-warning branch this class targets ever runs. This fixture keeps the map+shape fully valid and resolvable; only the placement TYPE is unrecognized. Live-verified (2026-07-12, OCP 7.8.1, direct probing — not mirrored/guessed): `shape_null=False`, `n_faces_total=1`; the mapped face's geometry loads at its own local coordinates (no transform applied), confirming the identity/un-positioned fallback rather than the shape being dropped. Provenance tier: bytes-sufficient. **See also**: Tfa248 (malformed-source precedent this fixture fixes). Synonyms: "MAPPED_ITEM unrecognized transform type", "placement case not recognized", "location ignored fallback", "MAPPED_ITEM loads unpositioned", "mapping_target neither CartesianTransformationOperator3d nor Axis2Placement3d".
