A100 — Importer routes Assembly-module assemblies into Part containers (Assembly graph lost)

§12.6 assembly hierarchy

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A100.stp

Sources

  • FreeCAD #18668
  • bug-reporter language: "STEP file importer doesn't support new assembly module", "whole assembly is imported into Part containers, not into Assembly container", "joints and constraints are dropped".

Sender

FreeCAD STEP importer prior to Assembly-module integration; STEP file authored by a tool that emitted joint/kinematic data alongside the geometry.

Description

A STEP assembly that carries `MECHANISM` / `KINEMATIC_JOINT` annotations alongside the geometry is imported as a flat tree of Part containers; the joint-and-kinematic graph is silently dropped. The on-disk file has a `KINEMATIC_TOPOLOGY_STRUCTURE` referencing geometry sub-shapes; the importer reads only the geometric faces and discards the kinematic graph.

Reproducer recipe

STEP file with two `MANIFOLD_SOLID_BREP`s plus a `MECHANISM('joint1', ..)` referencing them.

Expected kernel behavior

Heal and accept: importer routes assemblies with kinematic data into the Assembly container; or warn and accept by routing into Part with a diagnostic listing dropped kinematic entities. Dropping the kinematic graph without diagnostic is a coverage gap.

Notes

**See also**: P011 (PMI silently discarded). Synonyms: "Assembly module not supported by STEP importer", "joints lost on STEP import", "kinematic data discarded", "imported into Part not Assembly".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(18) ifc=schema_n/a

Byte assertions

  • contains(b'MECHANISM') or contains(b'KINEMATIC_JOINT')
  • contains(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE')

Tier-3 assertions

  • shape_null == False
  • n_faces_total == 2
  • n_edges_total == 8
  • n_vertices_total == 16
