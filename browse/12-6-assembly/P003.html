P003 — Control characters / illegal-XML bytes in name strings corrupt downstream documents

§12.1 encoding/robustness

assembly

View raw fixture (.stp) step-examples/12-6-assembly/P003.stp

Sources

  • FreeCAD #22123

Sender

KiCad or its STEP add-on (TO-92 footprint package names)

Description

A STEP file whose `PRODUCT` / `NEXT_ASSEMBLY_USAGE_OCCURRENCE` name fields contain bytes that are illegal in downstream serialization (control chars `\x00`–`\x1F`, lone surrogates, unescaped `<`/`&`/`>`, invalid UTF-8 continuation bytes) imports without complaint, but a save-and-reopen of the receiving document fails to parse.

Reproducer recipe

Produce a STEP file with names containing raw control bytes, lone surrogates, or characters that become illegal XML when serialized.

Expected kernel behavior

Sanitize/escape names at parse time; reject obviously invalid bytes with a warning.

Notes

Synonyms: "control characters in STEP name strings", "illegal-XML bytes break downstream tools", "raw 0x00-0x1F in PRODUCT.name", "XML serializer chokes on bytes from STEP".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'\\X\\[0-9A-Fa-f]{2}') or matches(rb"[\x00-\x08\x0b\x0c\x0e-\x1f]")
