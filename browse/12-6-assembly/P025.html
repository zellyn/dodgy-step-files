P025 — Body name overwritten by last-operation label on export

§12.6 assembly metadata

P1 — silent data loss

round-trip assembly

View raw fixture (.stp) step-examples/12-6-assembly/P025.stp

Sources

  • FreeCAD #24962

Sender

FreeCAD itself (regression late 2025)

Description

STEP write populates `PRODUCT.name` and `NEXT_ASSEMBLY_USAGE_OCCURRENCE.name` from the last operation's label rather than the body's label. Round-trip loses body names.

Reproducer recipe

STEP file where `PRODUCT_DEFINITION` chain has a name shadowed by a sub-feature label (e.g., "Pocket" instead of "MyPart_Body").

Expected kernel behavior

Heal and accept: maintain a stable mapping of body name to STEP product name across round-trip.

Notes

Synonyms: "body name overwritten by last operation label", "exported part name shows internal feature name", "body label corrupted by history rename", "feature name leaked as body name on export".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • count_entity_def(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE') >= 2
  • contains(b'MAPPED_ITEM')

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
