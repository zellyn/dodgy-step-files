P002 — Non-UTF-8 (GB18030 / locale code page) in string literals

§12.1 encoding

P1 — silent data loss

round-trip assembly

View raw fixture (.stp) step-examples/12-6-assembly/P002.stp

Sources

  • FreeCAD #7987, #22123

Sender

SolidWorks (Chinese-locale install) and any non-Western Windows export

Description

STEP-21 lines like `SHAPE_REPRESENTATION ('海绵2', ..)` appear in files encoded as GB18030 / Shift-JIS / CP1252 because exporters write the OS code page directly. Readers that assume UTF-8 produce mojibake in object labels and attributes; round-tripping then corrupts the saved project document.

Reproducer recipe

Generate a STEP file containing `PRODUCT`/`SHAPE_REPRESENTATION` name strings with high-bit bytes interpretable in GB18030 but not UTF-8 (or with the standard `\X2\…\X0\` Unicode escape sequences that exporters rarely emit).

Expected kernel behavior

Heal and accept: auto-detect or honor STEP-21 `\X2\` / `\X4\` escape sequences; expose a per-file encoding override; warn if bytes don't decode as declared encoding.

Notes

Synonyms: "GB18030 encoded part names corrupt after read", "non-UTF-8 string literals in STEP", "Chinese locale code page in name strings", "encoding mismatch garbles labels".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • contains(b'\\X2\\') or matches(rb"[\x80-\xff]")

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
