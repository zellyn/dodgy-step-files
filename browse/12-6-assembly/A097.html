A097 — Error transferring `.stp` model from `STEPCAFControl_Reader` to OCAF document

P1 — silent data loss

Sources

  • OCCT MANTIS#0023010
  • bug-reporter language: "error with a .stp model during transfer from STEPCAFControl_Reader to document", "parser succeeds but transfer fails", "STEP file parses OK but does not become an OCAF document". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Producers that emit `PRODUCT_DEFINITION` records whose context (`PRODUCT_DEFINITION_CONTEXT`) is not the same instance referenced from the document's `APPLICATION_CONTEXT` — the reader's two-pass design rejects the link.

Description

`STEPControl_Reader::ReadFile` returns OK and `NbRoots() > 0`; `STEPCAFControl_Reader::Transfer(doc)` returns `Standard_False` and the OCAF document is empty. The transfer pass walks `PRODUCT_DEFINITION → PRODUCT_DEFINITION_CONTEXT → APPLICATION_CONTEXT` and the chain has a mismatch (two distinct `APPLICATION_CONTEXT` instances with the same string content). The user's reasonable interpretation — "the parser said it worked" — is contradicted by the empty document.

Reproducer recipe

STEP file with two distinct `APPLICATION_CONTEXT` records. Parser accepts; `STEPCAFControl_Reader::Transfer` returns false. Document is empty.

Expected kernel behavior

heal-and-accept — transfer pass tolerates multiple `APPLICATION_CONTEXT` records by matching on string content; emit `W_DUPLICATE_APPLICATION_CONTEXT` and proceed. Parser-OK + empty-document is a contract violation.

Notes

**See also**: M165, A067. Synonyms: "error transferring STEP model to OCAF document", "STEPCAFControl_Reader Transfer returns false", "parser succeeds but transfer fails", "duplicate APPLICATION_CONTEXT breaks transfer".
