A006 — Components collapse to (0,0,0) / placement transforms lost

§12.6 (sub-class: assembly placement transform)

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-6-assembly/A006.stp

Sources

  • J007 (FreeCAD Assembly2 → Inventor), V016 (Creo → SolidWorks), V053 (CATIA V5 R21 ignores user CS), V054 (SolidWorks origin-rotation), G083 (OCCT root transform).

Sender

FreeCAD Assembly2; PTC Creo; CATIA V5 R21; SolidWorks (custom CS export); generally any tool whose SHAPE_REPRESENTATION_RELATIONSHIP transform chain is incomplete.

Description

Subassembly transforms encoded only as relative deltas in NAUO chain; receiver flattens to absolute coords using identity. Or some STEP files put the assembly transform on the root `SHAPE_REPRESENTATION` (not on NAUO/SRR), and OCCT either applies it wrong or not at all. Result: every component lands at the origin.

Reproducer recipe

NAUO chain with no resolvable `SHAPE_REPRESENTATION_RELATIONSHIP`/transform; or the transform reference points at an unresolved instance ID. Or non-identity AXIS2_PLACEMENT on the root SR.

Expected kernel behavior

Warn and accept when NAUO chain has no resolvable transform; new `read.step.root.transformation` switch; default identity but report each missing edge. Must not silently accept.

Notes

**See also**: A007. Synonyms: "subassembly snaps back to origin on import", "instance positioned at world origin instead of designed location", "imported part loses its placement", "all components stacked at (0,0,0)", "MAPPED_ITEM transform dropped".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE') >= 2
  • count_entity_def(b'SHAPE_REPRESENTATION_RELATIONSHIP') == 0
