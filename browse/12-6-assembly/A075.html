A075 — Free-shape-after-import is empty

Description

A STEP file from SolidWorks 2018 (or similar producers) is imported but the resulting document contains no shapes; only an empty XCAF root. Diagnostics report success. Common cause: the file's `PRODUCT_DEFINITION` chain is rooted in a representation type the reader silently skips (e.g., `MANIFOLD_SURFACE_SHAPE_REPRESENTATION` instead of `ADVANCED_BREP_SHAPE_REPRESENTATION`).

Reproducer recipe

STEP file whose `PRODUCT_DEFINITION` references `MANIFOLD_SURFACE_SHAPE_REPRESENTATION` carrying real geometry; reader expects only `ADVANCED_BREP_SHAPE_REPRESENTATION`.

Expected kernel behavior

Heal and accept: reader recognises every representation subtype that is geometry-bearing; if a subtype is unsupported, reject with a diagnostic listing the entity type rather than silently emptying the result.

Notes

Provenance tier: runtime-only; kernel reports no free-shape after import; defect is reader behavior.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Provenance tier

runtime-only — defect not fully embodied in fixture bytes.

Byte assertions

  • contains(b'MANIFOLD_SURFACE_SHAPE_REPRESENTATION')
  • not_contains(b'ADVANCED_BREP_SHAPE_REPRESENTATION')
