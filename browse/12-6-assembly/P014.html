P014 — `PCURVE` start point shifted in V from 3D `EDGE_CURVE` lift (UV drift beyond tolerance after Boolean)

§12.2 pcurve

round-trip assembly

View raw fixture (.stp) step-examples/12-6-assembly/P014.stp

Sources

  • FreeCAD #21216

Sender

FreeCAD post-Boolean

Description

Faces emitted after a complex Boolean cut carry `SURFACE_CURVE` whose `PCURVE` lies off the surface domain — beyond geometric tolerance. Common signature: a planar `ADVANCED_FACE` whose 3D edge runs from the origin along +X but whose pcurve seed 2D point starts at (u=0.0, v=0.5), a 0.5 mm drift in V between the 2D pcurve and the 3D edge lift. The source shape validates clean inside the producing kernel, but on STEP re-import every face/edge is flagged "invalid curve on surface" — the round-trip introduced UV drift the source did not have.

Reproducer recipe

`MANIFOLD_SOLID_BREP` where each `ADVANCED_FACE` carries `SURFACE_CURVE` with both 3D `CURVE` and 2D `PCURVE` whose pcurve drift exceeds tolerance.

Expected kernel behavior

Auto-project pcurve back to surface (within tolerance); or warn and accept.

Notes

Synonyms: "PCURVE 2D trace drifts off surface after Boolean", "UV parameter shifts beyond tolerance", "pcurve start point doesn't match 3D edge", "parametric curve disagrees with surface geometry".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • count_entity_def(b'PCURVE') >= 1
  • contains(b'SURFACE_CURVE')

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
