P001 — Schema variant: CONFIG_CONTROL_DESIGN with no PRODUCT entity

§12.1 file-format/schema-variant

P1 — silent data loss

round-trip assembly

View raw fixture (.stp) step-examples/12-6-assembly/P001.stp

Sources

  • FreeCAD #15685

Sender

re-export from unspecified application (original was AUTOMOTIVE_DESIGN)

Description

A re-exported file using the older `CONFIG_CONTROL_DESIGN` schema (rather than `AUTOMOTIVE_DESIGN`) and lacking a `PRODUCT` entity at the protocol layer is silently dropped by OCCT's reader: import returns success with zero objects, no message in console or report panel. Other readers (e.g., Rhino) accept it.

Reproducer recipe

Author a STEP-AP203 file whose HEADER declares `CONFIG_CONTROL_DESIGN`, omit the `PRODUCT`/`PRODUCT_DEFINITION` chain that AUTOMOTIVE_DESIGN tooling expects, but keep a normal `MANIFOLD_SOLID_BREP` payload.

Expected kernel behavior

Reject with explicit diagnostic identifying the missing `PRODUCT` parent, or accept successfully. Silent empty result (silent-accept) is the bug; must not silently accept.

Notes

Synonyms: "CONFIG_CONTROL_DESIGN file with no PRODUCT entity", "schema variant missing required PRODUCT", "CCD-only STEP file rejected by readers".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • contains(b'CONFIG_CONTROL_DESIGN')
  • declared_schema == b'CONFIG_CONTROL_DESIGN'
  • count_entity_def(b'PRODUCT') == 0

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
