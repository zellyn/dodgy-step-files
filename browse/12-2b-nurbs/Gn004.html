Description

Complex entity `(BOUNDED_SURFACE() B_SPLINE_SURFACE() B_SPLINE_SURFACE_WITH_KNOTS() … RATIONAL_B_SPLINE_SURFACE())` carries empty `KNOTS()` / `KNOT_MULTIPLICITIES()` lists or empty `name`. Reader null-derefs.

Reproducer recipe

A complex rational BSpline surface entity with `''` name and empty `KNOTS(())` aggregates.

Expected kernel behavior

reject the surface and skip the host face; emit a per-entity diagnostic; never crash the read.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT crashes (`signal(11)`). The crash is on the kernel side; the file is spec-conformant Part-21. **OCC behavior**: crashes (signal 11) on the empty knots/multiplicities; exactly the kernel mishandling the catalog above forbids; documented here so kernel authors know this is what OCC currently does. Synonyms: "complex BSpline surface entity with empty knots", "rational B-spline surface empty multiplicities crashes reader", "complex entity null-derefs on empty knot list", "empty KNOTS aggregate in BSpline surface complex instance", "B-spline surface with no knots crashes import".

occt=signal(11)/signal(11) gmsh=signal(11) ifc=schema_n/a
