Description

Pro/E emits 2D interpolation curves whose points have non-uniform parameter scaling (per-segment chord-length parameterization with explicit scaling tags). OCCT's reader didn't replicate the scaling and produced a different 2D curve from the source.

Reproducer recipe

Pro/E-style 2D BSpline interpolation with per-segment parameter scaling tags.

Expected kernel behavior

Heal and accept: honor scale parameters when reconstructing 2D BSpline interpolation curves.

Notes

**See also**: Gp024. Synonyms: "Pro/E non-uniform parameter scaling on 2D curves", "Geom2dAPI_Interpolate scaling tags ignored", "PRO/Engineer 2D BSpline interpolation scaling lost", "per-segment chord-length parameterisation not honored", "Pro/E 2D curve scale parameters dropped".
