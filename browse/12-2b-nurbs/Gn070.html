Reproducer recipe

Expected kernel behavior

accept: a rational (all-weight-1.0) 2D pcurve used inside a PCURVE/DEFINITIONAL_REPRESENTATION is functionally identical to a non-rational curve since every weight is 1. Bezier-basis conversion should recognize an all-unit-weight rational curve and delegate to the same path as a non-rational curve, rather than taking a rational-specific path that can degenerate the output (e.g. collapsing a span to a line segment) when it isn't actually needed.
