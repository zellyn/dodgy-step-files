Gn002 — RATIONAL_BSPLINE_CURVE / SURFACE with `NbWeights ≠ NbControlPoints`

§12.2b NURBS/knots

silent-loss geometry

Sources

  • 04-occt-translation.md (Q060 `RWStepGeom_RWRationalBSplineCurve.cxx:193-199`)
  • 08-occt-gitlog.md (G024, Mantis 0030921, OCCT 3940436/40858cc)

Description

A `RATIONAL_B_SPLINE_CURVE` (or surface) has a weights array whose length differs from the control-point list length, breaking reader contracts. OCCT's writer historically also emitted mismatched lengths.

Reproducer recipe

Emit `RATIONAL_B_SPLINE_CURVE(..,(w0,w1,w2))` paired with a 2D/3D pole list of length 4; or surface analogue with rectangular weight grid having a missing row.

Expected kernel behavior

heal; pad weights with 1.0 / truncate to match pole count; warn. Do not crash. Writers must always emit len(weights) == len(poles).

Notes

Both malformed rational entities (curve: 4 poles / 3 weights; surface: 4×4 net / 4×3 weight grid) are wired as members of a `GEOMETRIC_SET` (`#2`) reachable from the shape representation — they are genuinely part of the loaded model, not orphan definitions. **Live-oracle behaviour (OCCT 7.8.1, deterministic across reruns):** the parser accepts the file but the transfer stage silently DROPS both entities on the weight-count mismatch, so `occt` yields `shape_null` (empty); gmsh likewise yields empty. This is genuinely CAUSED by the defect: a well-formed control (curve 4 weights, surface 4×4 grid) built the same way yields a real edge+face (`occt=shape(1)`, face:1). So the fixture demonstrates the class by the observable empty-vs-nonempty contrast, not merely by byte presence. (An earlier version placed the malformed entities in an *unreferenced* `GEOMETRIC_CURVE_SET` beside a decoy point, which loaded a 1-vertex stub and demonstrated nothing — corrected 2026-07-17 to wire the defect carriers into the loaded model.) **See also**: Ad059. Synonyms: "rational B-spline weights count doesn't match poles", "weights array length differs from control points", "NbWeights ≠ NbControlPoints", "NURBS curve weight vector wrong length", "rational BSpline missing weight or has extra weight".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'B_SPLINE_SURFACE')
  • contains(b'B_SPLINE_CURVE')
  • contains(b'GEOMETRIC_SET')

Tier-3 assertions

  • shape_null == True
