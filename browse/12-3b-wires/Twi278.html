B4 wave-8 DEF-VV (LGPL-clean — pattern only, no upstream bytes copied). AP242 Ed.3 introduced explicit `POSITIVE_LENGTH_MEASURE` length-invariants on curves, edges, and topological representations so wire-harness routing and gasket-length applications can enforce a length constraint at all three abstraction levels
  • earlier editions (Ed.2, Ed.1, AP214) do not carry these entities in their schemas and their readers produce Void transfer status.

Sender

AP242 Edition 3 STEP files from CAD tools that emit length-constrained wires (wire-harness routing, gasket-length modelling); file header declares `AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }` (Ed.3 OID with hybrid AUTOMOTIVE_DESIGN name).

Description

STEP AP242 Ed.3 file containing a minimal single-face planar 1×1 mm patch (`SHELL_BASED_SURFACE_MODEL` with one `OPEN_SHELL` containing one `ADVANCED_FACE` on a `PLANE`) plus a co-present straight degree-1 `B_SPLINE_CURVE_WITH_KNOTS` (from (0,0,0) to (1,0,0)) wrapped in an `EDGE_CURVE('twi278_edge',#v_start,#v_end,#bspline,.T.)`. Three Ed.3 length-constraint entities all attach a `POSITIVE_LENGTH_MEASURE(1.0)` length-invariant at three abstraction levels: `BOUNDED_CURVE_WITH_LENGTH('twi278_bcwl',#bspline,POSITIVE_LENGTH_MEASURE(1.0))` at the curve level; `EDGE_BOUNDED_CURVE_WITH_LENGTH('twi278_ebcwl',#edge_curve,POSITIVE_LENGTH_MEASURE(1.0))` at the edge level; `EDGE_BASED_TOPOLOGICAL_REPRESENTATION_WITH_LENGTH_CONSTRAINT('twi278_ebtrwlc',(#edge_curve),POSITIVE_LENGTH_MEASURE(1.0))` at the topological-representation level. Ed.3 readers resolve all three entities and expose the length-invariant at curve, edge, and topology-representation levels; Ed.2 / AP214 readers produce Void transfer status on all three — the curve/edge still load but the length-invariant is silently absent, so a wire-harness / gasket-length application cannot enforce the constraint.

Reproducer recipe

AP242 Ed.3 header (`AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }`); single planar `ADVANCED_FACE` in `OPEN_SHELL` / `SHELL_BASED_SURFACE_MODEL`; degree-1 `B_SPLINE_CURVE_WITH_KNOTS` + `EDGE_CURVE`; `BOUNDED_CURVE_WITH_LENGTH('...',#bspline,POSITIVE_LENGTH_MEASURE(1.0))`; `EDGE_BOUNDED_CURVE_WITH_LENGTH('...',#edge_curve,POSITIVE_LENGTH_MEASURE(1.0))`; `EDGE_BASED_TOPOLOGICAL_REPRESENTATION_WITH_LENGTH_CONSTRAINT('...',(#edge_curve),POSITIVE_LENGTH_MEASURE(1.0))`.

Expected kernel behavior

AP242 Ed.3 readers must resolve all three length-constraint entities and expose the length-invariant at the curve, edge, and topological-representation levels; Ed.2 / AP214 readers must emit `W_SCHEMA_ENTITY_UNSUPPORTED(BOUNDED_CURVE_WITH_LENGTH)` / `EDGE_BOUNDED_CURVE_WITH_LENGTH` / `EDGE_BASED_TOPOLOGICAL_REPRESENTATION_WITH_LENGTH_CONSTRAINT` rather than silently discarding the length-invariant.
