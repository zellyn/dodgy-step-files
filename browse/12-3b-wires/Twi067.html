Twi067 — Lacking edge: 2D gap not absorbable by vertex tolerance

Sources

  • OCCT `ShapeAnalysis_Wire::CheckLacking` (`ShapeAnalysis_Wire.hxx:236`)

Description

Between two consecutive edges of a wire, the pcurve endpoints differ by more than the shared vertex's tolerance can cover. The 3D coordinates may agree but in UV there is a gap that requires *insertion* of a connecting edge — not just snapping.

Reproducer recipe

An edge ends at UV `(10, 0)`; the next edge starts at UV `(10.5, 0)` — pcurve gap 0.5 in UV space, but 3D distance is small because the host surface compresses parameter space at that location.

Expected kernel behavior

report DONE1 (gap too large for vertex tolerance) vs DONE2 (vector across gap is anti-parallel to neighboring pcurves); insert a synthetic connecting edge or reject. The insertion's geometry must be consistent with both neighbors.

Notes

One of the canonical "needs a degenerate seam edge" defects in periodic-surface land. Synonyms: "UV gap too big for vertex tolerance", "lacking edge in parameter space", "wire 2D gap can't be absorbed by snap", "synthesized connecting edge needed in UV".
