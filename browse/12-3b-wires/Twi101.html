Twi101 — `POLYLINE` basis curve LoadONBrep stub (BRL-CAD step-g)

§12.3b wires / loops / edges (sub-class: polyline basis unimplemented)

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-3b-wires/Twi101.stp

Sources

  • BRL-CAD `src/conv/step/step-g/Polyline.cpp` provides `Load` (parses the list of CARTESIAN_POINTs) but no `LoadONBrep` override
  • the call falls through to `BoundedCurve` / `Curve.cpp` base stub `"::LoadONBrep(..) not implemented for Polyline"`
  • bug-reporter language: "polyline basis dropped on STEP import", "broken-line chamfer disappears after step-g", "POLYLINE silently lost".

Sender

Older translators (legacy Pro/E versions, pre-2010 SolidWorks STEP exporters) that prefer broken-line representations of bevels and chamfers over arc-circle compositions; also tessellated-mesh-to-STEP converters that emit polylines.

Description

`Polyline.cpp` has a working `Load` that fills the in-memory model with the list of CARTESIAN_POINTs, but no `LoadONBrep` override exists; the call falls through to the base stub which prints `"not implemented for Polyline"` and returns false. A topology entity using POLYLINE as its underlying basis loses the geometry: only the start/end vertices remain. The receiver builds a zero-length topology entity or fails to build the wire.

Reproducer recipe

`#20=POLYLINE('chamfer_basis',(#10,#11,#12));` referenced from a topology entity via its underlying-curve slot; step-g loads the polyline points but the LoadONBrep stub drops the basis.

Expected kernel behavior

heal-and-accept; Polyline must override `LoadONBrep` to build a piecewise-linear `ON_PolylineCurve`; if more than 2 vertices, optionally promote to a degree-1 B-spline with knot multiplicity 2 at endpoints.

Notes

**See also**: Twi100, Pmi053. Synonyms: "POLYLINE basis dropped", "step-g Polyline LoadONBrep stub", "broken-line chamfer disappears on STEP import", "polyline silently lost", "Pro/E chamfer polyline drops in BRL-CAD".
