Twi066 — Closure check separately reports 3D and 2D failures (e.g., EDGE_LOOP with missing closing edge AND last edge's 3D LINE end disagreeing with declared end VERTEX_POINT)

§12.3b wires / loops / edges (sub-class: closure-analysis)

topology

View raw fixture (.stp) step-examples/12-3b-wires/Twi066.stp

Sources

  • OCCT `ShapeAnalysis_Wire::CheckClosed` (`ShapeAnalysis_Wire.hxx:220`)

Description

An EDGE_LOOP is "closed" only if its first and last VERTEX_POINTs coincide in *both* 3D and UV. Either condition can fail independently; the diagnostic must report the two outcomes separately so the caller can decide which representation to fix. Typical fixture: a 3-edge open EDGE_LOOP missing its closing ORIENTED_EDGE entirely, where additionally the last edge's 3D LINE direction/length doesn't even reach the declared end VERTEX_POINT (e.g., a LINE from (10,10,0) along -X over length 1 reaches (9,10,0) but the edge claims its endpoint is (1,10,0)).

Reproducer recipe

As Twi053 but additionally the pcurves of the first and last edges have endpoints in different parameter bands, AND/OR the last edge's underlying 3D LINE doesn't actually reach the declared end VERTEX_POINT (the wire is open in 3D *and* open in UV).

Expected kernel behavior

emit FAIL1/DONE1 for the 3D-side and FAIL2/DONE2 for the 2D-side; never collapse them into one boolean "closed".

Notes

3D-closed but UV-open is a separate defect (Twi-class on shifted pcurves). Synonyms: "wire closure check separate for spatial and parametric", "wire reports two closure flags one per dimension", "open in 3D but closed in UV or vice versa", "closure check returns spatial and parametric outcomes".

Expected validation

occt=shape(1)/shape(1) gmsh=reject ifc=schema_n/a

Closure intent

sheet — the open shell is the intended final geometry; a solid-only kernel should cleanly refuse.

Tier-3 assertions

  • n_edges_total >= 3
  • face[0].surface_type == "plane"
  • n_vertices_total >= 6
