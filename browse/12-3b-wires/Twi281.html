Twi281 — `VERTEX_LOOP` point-loop used as the sole `FACE_OUTER_BOUND` of an `ADVANCED_FACE` on a non-singular `PLANE` (loop-degeneracy flag vs flat geometry)

B4 wave-12 repair-code mining (LGPL-clean — pattern only, no upstream bytes copied). openNURBS constrains a point-loop (a loop that collapses to a single vertex) to occur only where the underlying surface has a genuine singularity (cone apex / sphere pole)
  • a point-loop as a face's boundary on a surface with no singular point is a loop-type-vs-geometry inconsistency.

Sender

BRep translator / writer that emits a face whose outer boundary is a `VERTEX_LOOP` on a non-singular surface — e.g. a healing/decomposition pass that collapsed a wire to a single vertex, or a mis-typed singular loop copied onto a planar carrier.

Description

An `ADVANCED_FACE` on a flat `PLANE` whose SOLE `FACE_OUTER_BOUND` wraps a `VERTEX_LOOP('point_loop_on_flat_plane',#v)` — a loop collapsing to a single `VERTEX_POINT` at (0,0,0). A point-loop declares "this face's boundary is a single point / the face collapses to a singular vertex", which openNURBS permits only at a genuine surface singularity; a `PLANE` has no singular point anywhere, so the loop-degeneracy flag contradicts the flat geometry. The face is transferred through an `OPEN_SHELL` / `SHELL_BASED_SURFACE_MODEL` so the malformed loop is on the live traversal path (no orphaned entities).

Reproducer recipe

`PLANE` at origin (+Z normal); `VERTEX_POINT` at (0,0,0); `VERTEX_LOOP('point_loop_on_flat_plane',#v)`; `FACE_OUTER_BOUND('',#vloop,.T.)` as the ADVANCED_FACE's only bound; `ADVANCED_FACE` on the plane; `OPEN_SHELL` + `SHELL_BASED_SURFACE_MODEL`.

Expected kernel behavior

Reject or heal loudly — a `ptonsrf`/singular loop is only well-formed at a surface singularity; on a non-singular surface the face has no bounded area and should be dropped with a diagnostic, or the point-loop coerced to a proper wire. Silently building a zero-area face masks the inconsistency.

Notes

Distinct from **Twi041 / Pf025** (`VERTEX_LOOP` as an INNER `FACE_BOUND` alongside a real outer bound — here it is the SOLE / OUTER bound) and from the Tfe writer-drop sphere-cap `VERTEX_LOOP` cluster (a `SPHERICAL_SURFACE` HAS pole singularities; a `PLANE` has none). Live oracle: OCCT builds a face on the plane bounded only by the degenerate vertex loop — `shape(1)` but with n_edges_total==0 / n_vertices_total==0 (a clean planar quad face carries 4 edges) and an empty mesh; gmsh yields `shape(1)` where a clean planar quad meshes to `shape(9)` — the distinguishable signal.
