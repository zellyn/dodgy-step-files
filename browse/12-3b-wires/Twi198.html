Expected kernel behavior

Recognize the duplicate curve, and the resulting open loop: edges `coinc_e0` and `coinc_e1` are two separate EDGE_CURVE entities that reference the exact same underlying LINE (#15) and the exact same vertex pair (#7,#9) with the same sense — the identical edge, defined twice. A kernel must detect this via curve/vertex comparison, not `Handle` identity, and treat it as one edge, not two independent sides of a boundary. Beyond that, the EDGE_LOOP's stored order also doesn't close: `coinc_e1` (the duplicate) is placed last, ending at vertex #9, but the loop's first edge started at vertex #7 — so even setting the duplicate issue aside, this loop does not return to its own starting point.
