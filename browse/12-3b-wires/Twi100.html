Twi100 — `COMPOSITE_CURVE_ON_SURFACE` LoadONBrep stub (BRL-CAD step-g)

Sources

  • BRL-CAD `src/conv/step/step-g/CompositeCurveOnSurface.cpp` `LoadONBrep` stub `"::LoadONBrep(..) not implemented for <entity>"`
  • `CompositeCurve.cpp` `PointAtStart` / `PointAtEnd` stubs
  • bug-reporter language: "composite-curve-on-surface dropped on import", "step-g LoadONBrep stub for COMPOSITE_CURVE_ON_SURFACE".

Sender

Producers that emit chains of segments stitched into a single basis — common in fillet round-corner basis where each fillet quadrant is a separate composite segment.

Description

A topology entity whose underlying basis is a `COMPOSITE_CURVE_ON_SURFACE` (a chain of `COMPOSITE_CURVE_SEGMENT`s, each carrying a transition_code, all laid out on one host) loses both its 3D geometry and its endpoint resolution: the LoadONBrep stub in `CompositeCurveOnSurface.cpp` returns false, the inherited PointAtStart/PointAtEnd stubs in `CompositeCurve.cpp` return null, and the ON_Brep ends up with a zero-length trim. Distinct from Gs054 (composite segment self-cyclic, a graph-cycle defect) and Gs037 (offset-of-extrusion iso failure): this is the wholesale unimplemented dispatch.

Reproducer recipe

`#80=COMPOSITE_CURVE_ON_SURFACE('chain',(#70,#71),.U.);` referenced from a topology entity; step-g stubs out.

Expected kernel behavior

heal-and-accept; the importer must walk the segment list, reconstruct each segment, and concatenate them into a single ON_BrepTrim; if unhandled emit `W_COMPOSITE_CURVE_ON_SURFACE_FALLBACK` and either project to 3D or reject with a precise diagnostic.

Notes

**See also**: Gs054, Gs037, Tfa036. Synonyms: "COMPOSITE_CURVE_ON_SURFACE LoadONBrep stub", "step-g drops composite-curve-on-surface", "composite basis unimplemented", "PointAtStart not implemented for composite", "fillet quadrant chain dropped from STEP import".
