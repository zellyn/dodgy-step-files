Twi099 — `EDGE_CURVE` whose start and end vertex point at the same `VERTEX_POINT`

§12.3b wires / loops / edges (sub-class: degenerate edge)

P1 — silent data loss

  • OCCT MANTIS#0027580
  • bug-reporter language: "edge curve with identical vertices reported on file generated by OCCT itself", "EDGE_CURVE with same start and end vertex", "self-loop edge written by exporter". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

OCCT's own STEP writer when round-tripping an edge whose two endpoint vertices are within tolerance and got merged upstream.

Description

An `EDGE_CURVE` references the same `VERTEX_POINT` instance for both its start and end vertex slots. This makes the edge a single-point self-loop; a degenerate edge with zero arc length. The producer is OCCT itself, so the same kernel that emits the file is the only one that fully accepts it; strict downstream readers (STEP-File-Analyzer, JSDAI) flag it as an invariant violation.

Reproducer recipe

`#10=VERTEX_POINT('',#11);` followed by `#20=EDGE_CURVE('',#10,#10,#15,.T.);` referencing the same vertex twice — start and end both `#10`.

Expected kernel behavior

reject — emit `E_DEGENERATE_EDGE` when the start and end vertex of an `EDGE_CURVE` resolve to the same vertex instance unless the underlying curve is closed (e.g., full circle); writers must collapse zero-length edges before export.

Notes

**See also**: Twi045, Tsh021. Synonyms: "edge curve with identical vertices", "self-loop EDGE_CURVE", "zero-length edge written by OCCT", "STEP edge endpoints are the same vertex".
