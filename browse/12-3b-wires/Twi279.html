Twi279 — AP242 Ed.3 `CONNECTED_EDGE_SUB_SET` semantic sub-region grouping dropped by Ed.2/AP214 readers

§12.3b wire-loop (sub-class: edition-boundary entity elision / semantic edge-loop sub-grouping)

Sources

  • steptools.com AP242 Ed.3 notes (`CONNECTED_EDGE_SUB_SET` §4.4 — one of 21 new Ed.3 entities). B4 wave-8 DEF-WW (LGPL-clean — pattern only, no upstream bytes copied). AP242 Ed.3 introduced explicit labelled, connected subsets of edges within a topological representation so downstream tools (CAM/inspection) can query semantic sub-regions of an edge-loop (e.g., "the fillet chain", "the chamfer chain")
  • earlier editions (Ed.2, Ed.1, AP214) do not carry this entity in their schema and their readers produce Void transfer status.

Sender

AP242 Edition 3 STEP files from feature-aware CAD tools that tag connected sub-regions of edge-loops (fillet chains, chamfer chains, tolerance zones on boundaries); file header declares `AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }` (Ed.3 OID).

Description

STEP AP242 Ed.3 file containing a single planar octagonal `ADVANCED_FACE` (8 straight `ORIENTED_EDGE` entries in the `EDGE_LOOP` — a regular octagon of circumradius 5.0 in the XY plane) wrapped in `OPEN_SHELL` / `SHELL_BASED_SURFACE_MODEL`. A `CONNECTED_EDGE_SUB_SET('c1_fillet_chain',(#e3,#e4,#e5))` groups edges 3-5 (three of the eight edges) as a semantic sub-region — the labelled "fillet chain" on the boundary. Ed.3 readers resolve the entity and expose the sub-grouping so CAM/inspection tools that key off the label `c1_fillet_chain` can recover it; Ed.2 / AP214 readers produce Void transfer status on the entity — the `EDGE_LOOP` still loads with all 8 edges but the semantic sub-region grouping is silently gone.

Reproducer recipe

AP242 Ed.3 header (`AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }`); single planar `ADVANCED_FACE` with 8-edge `EDGE_LOOP`; `CONNECTED_EDGE_SUB_SET('c1_fillet_chain',(#e3,#e4,#e5))`.

Expected kernel behavior

AP242 Ed.3 readers must resolve `CONNECTED_EDGE_SUB_SET` and expose the labelled sub-grouping; Ed.2 / AP214 readers must emit `W_SCHEMA_ENTITY_UNSUPPORTED(CONNECTED_EDGE_SUB_SET)` rather than silently discarding the entity.

steptools notes_ap242e3.html §4.4 (21 new Ed.3 entities). B4 wave-8 DEF-WW. Confidence: MEDIUM — accept-live-oracle. OCCT drops the Ed.3 entity and loads the geometry as if AP214 (octagonal face + loop load, sub-set grouping absent) — that IS the defect. Expected validation captured from OCCT live behavior. Edition boundary: Ed.3 entity absent from Ed.2, Ed.1, AP214 schemas.
