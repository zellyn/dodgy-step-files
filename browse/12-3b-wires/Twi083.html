Twi083 — EDGE_CURVE flagged degenerate but its 3D LINE has positive length (non-zero distance between distinct VERTEX_POINTs)

Description

An EDGE_CURVE's "degenerate" flag is set true (the edge is meant to collapse to a single 3D point — typically a pole on a surface of revolution) but the underlying 3D LINE has positive length between two distinct VERTEX_POINTs. Conversely: a positive-length curve marked as degenerate, or a true pole-edge missing the flag. Typical fixture: an EDGE_CURVE between distinct VERTEX_POINTs (e.g., (0,0,0) and (1,0,0)) on a unit-length LINE with `same_sense=.T.` — the geometry is fine and not degenerate, but a flag elsewhere claims degeneracy. Bug-reporter language: "degenerate flag wrong", "pole edge not marked", "zero-length edge marked non-degenerate", "geometry not actually degenerate".

Reproducer recipe

An EDGE_CURVE with `edge_geometry` referencing a LINE of length 1.0 between two distinct VERTEX_POINTs but the edge's degenerate flag set true. (In Part-21 terms, this is encoded in a `seam_curve` / pcurve representation discrepancy.)

Expected kernel behavior

Recompute the flag from curve length; correct it, or reject as malformed.

Notes

Synonyms: "degenerate-edge mismatch", "wrong pole flag", "edge marked degenerate but has positive length", "non-zero-length edge claims to be degenerate", "degeneracy flag wrong".
