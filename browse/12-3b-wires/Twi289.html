Twi289 — Edge with neither a 3D curve nor a usable pcurve is REMOVED from the wire (not reconstructed)

§12.3b wire-loop (sub-class: edge consistency, removal path)

P2 — spec deviation (no data loss)

topology

Sources

  • OCCT `ShapeFix_Wire::FixEdgeCurves` incomplete-edge removal (`ShapeFix_Wire.cxx:744-759`) — the sibling path to `ShapeFix_Edge::FixAddCurve3d` (Twi047, reconstruct-from-pcurve)

Description

`ShapeFix_Wire::FixEdgeCurves` has two outcomes for an edge missing its 3D curve: if the pcurve is usable, reconstruct the 3D curve by lifting it through the host surface (Twi047's mechanism); if the edge has NEITHER a 3D curve NOR a usable pcurve (its own parametric range collapses to zero length), it cannot be salvaged and is REMOVED from the wire entirely, which is then re-closed/re-connected around the resulting gap. This fixture demonstrates the removal path: a pentagon wire with five ordinary healthy edges plus one degenerate sixth edge spliced in at one corner — start vertex equals end vertex (zero 3D extent, Twi018's pattern) AND its curve is a `SURFACE_CURVE` wrapping only a `PCURVE` with no 3D curve at all (Twi047's pattern) — combined, neither representation is usable.

Reproducer recipe

`ADVANCED_FACE` on a `PLANE` (pentagon); `EDGE_LOOP` of six `ORIENTED_EDGE`s — five ordinary `LINE`-based `EDGE_CURVE`s plus one `EDGE_CURVE('',#v,#v,#surface_curve,.T.)` where `#v` is a single `VERTEX_POINT` used for both start and end, and `#surface_curve` is a `SURFACE_CURVE` whose `associated_geometry` lists only a `PCURVE` (no 3D curve).

Expected kernel behavior

detect that the edge has neither a usable 3D curve nor a usable (non-zero-range) pcurve; remove the edge from the wire and re-close/re-connect the wire across the resulting gap (here, the two healthy neighbor edges already meet at the shared corner, so removal alone suffices); or reject the wire as malformed.

Notes

**See also**: Twi047 (the reconstruct-from-pcurve path — the sibling outcome of the same `FixEdgeCurves` decision point); Twi018 (the same-vertex/zero-arc-length pattern reused here as one half of the combined defect). Verified live: the degenerate sixth edge is dropped on import — `n_edges_total` comes back as exactly 5 (the healthy pentagon), down from the 6 declared in the DATA section — confirming the removal path fires rather than a reconstruction or a load failure. Synonyms: "edge with no curve representation is dropped", "unsalvageable edge removed from wire", "wire re-closes after dropping degenerate edge", "neither 3D curve nor usable pcurve", "incomplete edge removal path".
