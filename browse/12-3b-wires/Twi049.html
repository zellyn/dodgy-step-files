Twi049 — Wire on a face self-intersects in the host surface's parameter space

§12.3b wires / loops / edges (sub-class: self-intersection)

topology

View raw fixture (.stp) step-examples/12-3b-wires/Twi049.stp

Sources

  • OCCT `ShapeFix_IntersectionTool::FixSelfIntersectWire` (`ShapeFix_IntersectionTool.hxx:69`)

Description

A single closed wire's edges, when projected to the host face's UV parameter space, cross each other (figure-eight shape). The wire is topologically closed but geometrically self-intersecting; it cannot bound a simple region.

Reproducer recipe

An EDGE_LOOP of four edges forming a figure-eight: edges from `(0,0)→(10,10)`, `(10,10)→(10,0)`, `(10,0)→(0,10)`, `(0,10)→(0,0)`. The diagonals cross at `(5,5)`.

Expected kernel behavior

detect the self-intersection point(s) in UV; either split the wire at the intersection into two simple loops, remove the inner sub-loop, or reject the face as malformed. A diagnostic citing the offending edge pair must be available.

Notes

3D self-intersection (independent of any host surface) is a separate class. **See also**: existing Twi entries on self-intersection. **OCC behavior**: the validity-checker does not flag the UV-space figure-eight wire self-intersection; tier-3 valid-flag should be ignored for this entry. The reader most likely silently fixes or ignores the self-intersection on import. Synonyms: "wire crosses itself in UV", "figure-eight in parameter space", "boundary loop crosses in face UV", "diagonals of wire intersect inside face".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(22) ifc=schema_n/a

Closure intent

sheet — the open shell is the intended final geometry; a solid-only kernel should cleanly refuse.

Tier-3 assertions

  • n_edges_total >= 6
  • face[0].surface_type == "plane"
  • face[1].surface_type == "plane"
