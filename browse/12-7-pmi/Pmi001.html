Pmi001 — Hole emitted as two half-cylinders breaks PMI feature association

§12.7 (sub-class: persistent-id / semantic-vs-graphic)

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi001.stp

Sources

  • 02-caxif (PMI v4.1 §5.1, Fig.5
  • §10.1.3.1), 02-caxif (CAx-IF Round 56J §2.6.4.3 PDC, §2.7 PDI)

Sender

any writer that emits cylindrical holes as two `advanced_face` halves

Description

A through-hole exported as two `advanced_face` instances backed by halves of a `cylindrical_surface`. PMI (diameter dimensions, position tolerances, datums) targeting the whole hole must reach both halves through a shared `shape_aspect` plus multiple `geometric_item_specific_usage`. Persistent UUIDs must be assigned to the pair as a `uuid_set_items` group, not one per half. Receivers that expect one face per cylindrical feature drop or duplicate the PMI link.

Reproducer recipe

Block with one through-hole; emit two half-`advanced_face`s sharing the same `cylindrical_surface` axis with opposite parameter ranges; attach diameter `dimensional_size` and a position `geometric_tolerance` whose `shape_aspect` is referenced by two GISUs; bind a single `v5_uuid_attribute` via `uuid_set_items` to both halves.

Expected kernel behavior

heal: recognize the two halves as one cylindrical feature (or honor multi-GISU on the shared `shape_aspect`); merge by `uuid_set_items` membership before reporting feature counts.

Notes

**See also**: N044. Synonyms: "hole emitted as two half-cylinders", "PMI feature association broken because hole is split", "split-cylinder hole loses dimension link", "diameter callout doesn't bind to hole".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(39) ifc=schema_n/a

Tier-3 assertions

  • n_faces_total == 8
  • face[6].surface_type == "cylinder"
  • face[7].surface_type == "cylinder"
  • face[6].area > 311
  • face[6].area < 317
  • brepcheck.valid == True
