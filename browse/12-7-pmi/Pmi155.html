B4 wave-8 DEF-ZZ (LGPL-clean — pattern only, no upstream bytes copied). AP242 Ed.3 introduced explicit QA-provenance records: an assessment association that asserts a simplified representation is equivalent to a full CAD model under specified criteria, plus an inspection association that records the equivalence has been inspected and passed
  • earlier editions (Ed.2, Ed.1, AP214) do not carry these entities in their schemas and their readers produce Void transfer status.

Sender

AP242 Edition 3 STEP files from QA-aware CAD tools that emit data-equivalence records for simplified-representation workflows (design-to-simulation MBD/MBE workflows, digital-thread QA); file header declares `AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }` (Ed.3 OID).

Description

STEP AP242 Ed.3 file containing a minimal single-face planar 10×10 mm carrier (`SHELL_BASED_SURFACE_MODEL` with one `OPEN_SHELL` containing one `ADVANCED_FACE` on a `PLANE`). Two Ed.3 QA-provenance entities are attached at the product's PMI representation: `DATA_EQUIVALENCE_CRITERION_ASSESSMENT_ASSOCIATION('deca_1',...)` asserts that this file's simplified representation is equivalent to a full CAD model under the criteria "geometric tolerance 0.01 mm; topology preserved; PMI count matches"; `DATA_EQUIVALENCE_CRITERION_INSPECTION_ASSOCIATION('deci_1',...)` records that the equivalence claim has been inspected and passed with result "PASSED; inspector=jsmith; 2026-06-30". Ed.3 readers expose both records via QA-provenance API; Ed.2 / AP214 readers produce Void transfer status on both — the face still loads but the equivalence assertion and inspection provenance are silently absent; QA workflows that would consume the equivalence claim silently receive nothing.

Reproducer recipe

AP242 Ed.3 header (`AUTOMOTIVE_DESIGN { 1 0 10303 442 4 1 4 }`); single planar `ADVANCED_FACE` + `SHELL_BASED_SURFACE_MODEL`; `SHAPE_ASPECT` anchor; `DATA_EQUIVALENCE_CRITERION_ASSESSMENT_ASSOCIATION('deca_1',...,#criteria,#shape_aspect)`; `DATA_EQUIVALENCE_CRITERION_INSPECTION_ASSOCIATION('deci_1',...,#deca,#inspection_result)`.

Expected kernel behavior

AP242 Ed.3 readers must resolve `DATA_EQUIVALENCE_CRITERION_ASSESSMENT_ASSOCIATION` and `DATA_EQUIVALENCE_CRITERION_INSPECTION_ASSOCIATION` and expose the QA-provenance records; Ed.2 / AP214 readers must emit `W_SCHEMA_ENTITY_UNSUPPORTED(DATA_EQUIVALENCE_CRITERION_ASSESSMENT_ASSOCIATION)` rather than silently discarding the QA-provenance chain.
