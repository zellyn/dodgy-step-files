Pmi094 — XCAF GD&T data does not round-trip to STEP AP242 PMI

§12.7 PMI / GD&T (sub-class: GD&T export coverage gap)

P1 — silent data loss

round-trip pmi

Sources

  • OCCT MANTIS#0026859
  • bug-reporter language: "export of GDT from XCAF to STEP", "geometric tolerances in XCAF document not written to STEP", "GD&T not preserved on export". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

OCCT writer when an XCAF document carries `XCAFDoc_GeomToleranceTool` or `XCAFDoc_DimTolTool` records.

Description

An XCAF document has a flatness tolerance, a position tolerance, and a datum reference attached to a face. The writer's STEP-AP242 export pass emits the geometry but not the GD&T records; the output file has no `GEOMETRIC_TOLERANCE`, no `DIMENSIONAL_LOCATION`, no `DATUM_REFERENCE`. The producer's intent is lost. Bug class: writer coverage gap on PMI side.

Reproducer recipe

XCAF document with one face and a flatness tolerance. Run `STEPCAFControl_Writer::Perform`. Output omits GD&T entirely.

Expected kernel behavior

heal-and-accept; writer emits every GD&T record present in the XCAF document; missing record types raise `W_GDT_NOT_SUPPORTED` rather than silently dropping. AP242 is the canonical schema for PMI export.

Notes

**See also**: Pmi031. Synonyms: "export of GDT from XCAF to STEP", "geometric tolerances not written to STEP AP242", "PMI lost on STEP export", "XCAF GD&T not round-tripping".
