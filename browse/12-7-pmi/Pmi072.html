Pmi072 — `DIMENSION_PAIR` with mismatched units between paired members

§12.7 (sub-class: dimension pair)

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi072.stp

Sources

  • 16-iso-spec AP242 §DIMENSION_PAIR

Description

AP242 DIMENSION_PAIR couples two dimensions that are conceptually the same measurement (often one primary, the other a secondary or check) so downstream tolerance stack-up consumes them as a unit. The spec does not forbid mismatched units between the two halves; a producer that sources one half from an inch-based legacy CAD library and the other from a millimetre-based current export emits the pair with mixed units. The pair is mathematically inconsistent unless the receiver normalises units before comparing.

Reproducer recipe

DIMENSION_PAIR(`width`,`height`); width MEASURE_REPRESENTATION_ITEM in mm; height MEASURE_REPRESENTATION_ITEM in inches via CONVERSION_BASED_UNIT.

Expected kernel behavior

convert both halves to a canonical unit before comparison; warn on mismatched units; never silently treat the two values as if they were in the same unit.

Notes

**See also**: U-family unit-mismatch entries. **OCC behavior**: silently consumes both halves of the `DIMENSION_PAIR` without unit normalisation or diagnostic; kernel mishandling; the catalog above forbids silent same-unit treatment. Synonyms: "DIMENSION_PAIR with mismatched units", "paired dimensions in different units", "dimension pair unit inconsistency".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a
