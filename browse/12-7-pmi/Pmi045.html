Pmi045 — Graphic-only PMI with no semantic backing

§12.7 (sub-class: semantic-vs-graphic)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi045.stp

Sources

  • 17-standards-bodies (M009), 06-nist-sfa (S029), 10-vendor-kbs (V013, V015), 20-general-forums (J017)

Sender

AP203/AP214 polyline PMI; pre-Creo-9 dimension/GTOL exports; SolidWorks AP242 import drops PMI silently

Description

PMI is exported only as polylines / `annotation_curve_occurrence` (graphic presentation) with no parallel semantic representation. Looks correct visually but cannot be consumed by inspection / CMM / machining downstream. Older Creo (<9.0) only emitted semantic refs for note annotations; dimensions and geometric tolerances exported only as draughting graphics. SolidWorks, Onshape, Rhino 8/9, FreeCAD silently drop semantic AP242 PMI on import.

Reproducer recipe

AP203/AP214 file with `draughting_callout` containing only `annotation_curve_occurrence`s and no `dimensional_size`/`geometric_tolerance` semantic counterpart.

Expected kernel behavior

Heal and accept: round-trip the geometry; coerce the PMI to a "graphic only" flag so downstream tools know not to trust it; warn when AP242 PMI is present but not consumed.

Notes

**See also**: M025. Synonyms: "graphic-only PMI with no semantic backing", "annotation has no machine-readable data", "presentation PMI without underlying tolerance".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • contains(b'ANNOTATION_CURVE_OCCURRENCE')
  • contains(b'COLOUR_RGB')
  • contains(b'STYLED_ITEM')

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
