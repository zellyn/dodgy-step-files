Pmi034 — placed_datum_target_feature shared DatumTargetType_Area null deref

§12.7 (sub-class: datum-targets)

P1 — silent data loss

crash pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi034.stp

Sources

  • 08-occt-gitlog (G051 Mantis 0031685)

Description

Incorrect sharing of `DatumTargetType_Area` instance across multiple `PLACED_DATUM_TARGET_FEATURE`s causes NULL dereference during translation.

Reproducer recipe

AP242 file with two `placed_datum_target_feature`s sharing one `DatumTargetType_Area` entity.

Expected kernel behavior

Heal and accept: maintain independent target-type instances; coerce null-guards on every reference. Must not crash on null target references.

Notes

Validation observed: silent-empty rather than crash. Kernel-mishandling-by-silent-acceptance still demonstrates the defect class. Synonyms: "placed_datum_target_feature shared DatumTargetType_Area null deref", "shared datum target area causes null pointer crash", "datum target area null reference segfault".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • count_entity_def(b'PLACED_DATUM_TARGET_FEATURE') == 2
  • count_entity_def(b'PROPERTY_DEFINITION') == 2
  • contains(b'DESCRIPTIVE_REPRESENTATION_ITEM')

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 1
