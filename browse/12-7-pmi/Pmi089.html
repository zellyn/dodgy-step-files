Pmi089 — `GEOMETRIC_VALIDATION_PROPERTY` claimed centroid disagrees with geometry

§12.7 (sub-class: validation property)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi089.stp

Sources

  • 02-caxif (Validation Properties Recommended Practice §6.4 — centroid validation)
  • bug-reporter language: "STEP centroid wrong"

Sender

deduced — exporters where the centroid cache becomes stale after a final translation / placement-flatten step

Description

A `GEOMETRIC_VALIDATION_PROPERTY` claims a centroid (a `CARTESIAN_POINT`) for a body; the centroid the receiver computes is at a different location. Common cause: the producer's exporter computes the centroid in the body's local frame and the file emits the body in a parent-applied placement, but the validation property is in the local frame too — the receiver compares world-frame computed centroid against local-frame claimed centroid. Bug-reporter language: "STEP centroid wrong", "validation centroid mislocated", "centroid in wrong frame".

Reproducer recipe

a 10x10x10 mm cube whose `MANIFOLD_SOLID_BREP` is placed at world `(100, 0, 0)`. The body's actual centroid is `(105, 5, 5)` in world coordinates. A `GEOMETRIC_VALIDATION_PROPERTY` claims centroid `(5.0, 5.0, 5.0)` (the local-frame value, missing the parent translation).

Expected kernel behavior

Warn and accept: compute the centroid in a documented reference frame (local or world) and compare against the validation property; emit the frame in the diagnostic so the producer-receiver disagreement on frame can be diagnosed.

Notes

**See also**: Pmi087, Pmi088. Synonyms: "claimed centroid disagrees with geometry", "validation centroid wrong", "GVP centroid coordinate mismatch".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(27) ifc=schema_n/a

  • n_faces_total == 6
  • face[0].surface_type == "plane"
  • face[0].edge_count == 4
