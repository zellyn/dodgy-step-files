Pmi012 — Identical id_attribute reused across shape_aspect / dimensional_location / dimensional_size / shape_aspect_relationship

§12.7 (sub-class: persistent-id)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi012.stp

Sources

  • 02-caxif (PMI v4.1 §5.1)

Description

AP242 imposes a global uniqueness rule on the derived `id` attribute across `shape_aspect`, `dimensional_location`, `dimensional_size`, and `shape_aspect_relationship`. Writers that scope IDs per-entity-type produce conflicting IDs that violate the rule.

Reproducer recipe

File with `id_attribute('A1', shape_aspect#1)` and `id_attribute('A1', dimensional_location#2)`.

Expected kernel behavior

Heal and accept: writers normalize IDs into a single namespace covering all four subtypes; readers warn when collisions are detected.

Notes

Synonyms: "id_attribute reused across shape_aspect entities", "duplicate id on dimensional_location and dimensional_size", "shape_aspect ID collision", "tolerance entity IDs not unique".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'ID_ATTRIBUTE') == 3
  • contains(b'DIMENSIONAL_SIZE')
  • contains(b'DIMENSIONAL_LOCATION')
