Pmi002 — Blank/hidden dimensions exported as semantic dimensions

§12.7 (sub-class: semantic-vs-graphic)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi002.stp

Sources

  • 02-caxif (PMI v4.1 §10.1.1.2)

Description

CAD users hide a dimension's value to keep extension lines as visual aids; it is purely presentational. Writers that emit those as full `dimensional_size` / `dimensional_location` instances inflate semantic-PMI counts and produce phantom semantic content with no real value.

Reproducer recipe

Native model with one real dimension and one "blank" dimension on the same feature; serialize both as semantic dimensions.

Expected kernel behavior

Heal and accept: writers normalize away blank dimensions on export; readers accept files containing them and warn about the count divergence vs validation-property PMI counts.

Notes

Synonyms: "blank or hidden dimensions exported as semantic", "hidden dimensions still exported as data", "PMI tagged as semantic when it should be cosmetic", "blanked annotation written as live tolerance".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • count_entity_def(b'DIMENSIONAL_SIZE') == 2
  • contains(b'blanked-width')
  • count_entity_def(b'SHAPE_DIMENSION_REPRESENTATION') == 2
