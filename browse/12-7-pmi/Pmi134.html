Pmi134 — `CHAMFER` with two contradictory `chamfer_angle` attributes (45 deg and 60 deg)

§12.7 (sub-class: AP242 feature definition)

P1 — silent data loss

round-trip spec-violation pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi134.stp

Sources

  • 16-iso-spec AP242 §chamfer
  • CAx-IF Recommended Practices for chamfer features

Description

AP242 `chamfer` carries a single `chamfer_angle` attribute (the angle of the cut measured from one of the adjacent faces). The implicit invariant: there is exactly one chamfer angle. A producer that emits two `DIMENSIONAL_SIZE` records both named `chamfer_angle` with different values (45 deg = π/4 and 60 deg = π/3) leaves a feature that is internally contradictory. Receivers either pick the first, pick the last, average them, reject, or silently emit one and drop the other. Round-trip differential tests fail because different kernels pick differently. Bug-reporter language: "chamfer has two angles", "AP242 chamfer attributes conflict", "feature has duplicate chamfer_angle".

Reproducer recipe

a `SHAPE_ASPECT('chamfer',..)`; two `DIMENSIONAL_SIZE` entries both named `'chamfer_angle'`, with `MEASURE_REPRESENTATION_ITEM` values `PLANE_ANGLE_MEASURE(0.7853981634)` (45 deg) and `PLANE_ANGLE_MEASURE(1.0471975512)` (60 deg).

Expected kernel behavior

reject as malformed when a feature has two `DIMENSIONAL_SIZE` records of the same `attribute_name` with conflicting values; never silently pick one.

Notes

Distinct from Pmi133 (size-vs-edge invariant); Pmi134 is duplicate-attribute contradiction. **See also**: Pmi133, Pmi092. Synonyms: "CHAMFER two angle attributes", "AP242 duplicate chamfer_angle", "chamfer feature 45 vs 60", "conflicting chamfer angle values".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Tier-3 assertions

  • n_faces_total == 1
  • face[0].surface_type == "plane"
  • face[0].edge_count == 4
  • face[0].area > 899
  • face[0].area < 901
