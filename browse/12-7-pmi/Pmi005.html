Pmi005 — Mixing Polyline and Tessellated PMI presentation in one file

§12.7 (sub-class: semantic-vs-graphic)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi005.stp

Sources

  • 02-caxif (PMI v4.1 §8.3), 06-nist-sfa (S068)

Description

Schema permits both, but most viewers pick one and silently drop the other. A draughting model that mixes `tessellated_annotation_occurrence` and curve-style `annotation_*_occurrence` for the same callout is interoperability-hostile.

Reproducer recipe

Same model with two annotations: one realized as basic polylines, the other as tessellated triangles, both under the same `draughting_model`.

Expected kernel behavior

Warn and accept: writers commit to one approach per file; readers normalize the chosen form, process whichever they encounter, and warn when both are present.

Notes

Synonyms: "polyline and tessellated PMI mixed in one file", "two presentation styles for the same callout", "viewer can't decide which PMI presentation to use".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • contains(b'TESSELLATED_ANNOTATION_OCCURRENCE')
  • contains(b'ANNOTATION_CURVE_OCCURRENCE')
  • contains(b'TRIANGULATED_FACE')

  • shape_null == False
  • n_vertices_total == 1
