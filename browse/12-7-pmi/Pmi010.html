Pmi010 — Tolerance zone form name from AP242 Ed.2 used in Ed.1 file

§12.7 (sub-class: tolerance-zone / schema)

crash pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi010.stp

Sources

  • 02-caxif (PMI v4.1 §6.9.2 Table 13)

Description

Several `tolerance_zone_form.name` values (`'within a sphere'`, `'within a cone'`, `'within a single complex surface'`) were added in AP242 Ed.2. Used in an Ed.1 file they trigger a WHERE-rule violation.

Reproducer recipe

AP242 Ed.1 file containing `TOLERANCE_ZONE_FORM('within a cone')`.

Expected kernel behavior

Writer scoped to Ed.1 must restrict zone-form names to the Ed.1 set; reader should warn rather than abort when seeing Ed.2 names in an Ed.1-declared file.

Notes

**See also**: A030. Validation observed: silent-empty rather than crash. Kernel-mishandling-by-silent-acceptance still demonstrates the defect class. Synonyms: "AP242 Ed.2 tolerance zone form name in Ed.1 file", "newer enum value used in older STEP edition", "tolerance zone form name unsupported in declared edition".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'POSITION_TOLERANCE')
  • contains(b'TOLERANCE_ZONE_FORM')
  • contains(b'DATUM_SYSTEM')
