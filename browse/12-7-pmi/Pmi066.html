Pmi066 — Compound-feature semantics (HTC counterbore/countersink/counterdrill) per Hole RP

§12.7 (sub-class: hole-feature)

P1 — silent data loss

pmi

View raw fixture (.stp) step-examples/12-7-pmi/Pmi066.stp

Sources

  • 02-caxif (CAx-IF Round 56J Test Suite §2.3.4.2), 02-caxif (PMI v4.1 §5.1.9)

Description

Compound holes (counterbore, countersink, counter-drill) must be modeled as semantic features per the draft Hole Information Recommended Practices. Files emitting each segment as an independent `dimensional_size` lose the compound-feature link.

Reproducer recipe

HTC-style model with one counterbore. Export with each segment as an independent `dimensional_size` and no compound-hole entity.

Expected kernel behavior

Heal and accept: support both the simplified (stacked dimensions) and explicit (compound hole feature) forms; readers reconstruct / repair compound features by name and proximity when the explicit form is absent.

Notes

**See also**: Pmi013. Synonyms: "compound feature counterbore/countersink/counterdrill semantics wrong", "HTC compound hole misinterpreted", "hole RP compound semantics mishandled".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

  • contains(b'PLUS_MINUS_TOLERANCE')
