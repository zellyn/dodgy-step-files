M098 — AP238 tool feedrate exceeds manufacturer rated maximum

§12.8 mixed (sub-class: AP238 tool feedrate)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M098.stp

Sources

  • deduced from ISO 10303-238 §5.8 machining_tool_feedspeed bounds

Sender

deduced — CAM post-processor copying feedrate from a different tool family

Description

A `MACHINING_TOOL_FEEDSPEED` declares a feed-rate of e.g. `50000.0 mm/min` for a 6mm carbide end-mill whose rated maximum is roughly 3000 mm/min. The controller either clips at machine maximum (silently changing the program) or attempts the rate and breaks the tool. Bug-reporter language: "AP238 feedrate insanely high", "STEP-NC tool runs too fast", "feedspeed exceeds tool limit".

Reproducer recipe

`MACHINING_TOOL_FEEDSPEED($, MEASURE_WITH_UNIT( POSITIVE_RATIO_MEASURE(50000.0), mm_per_min_unit), $)` on a 6mm end-mill.

Expected kernel behavior

range-check feedrate against tool family expected envelope; warn loudly on out-of-envelope values, reject if catastrophic.

Notes

Synonyms: "feedrate too high", "STEP-NC unrealistic feedspeed", "tool will break".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a
