M148 — AP210 same NETWORK identifier used for two unrelated nets

§12.8 mixed (sub-class: AP210 net naming collision)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M148.stp

Sources

  • 16-iso-spec ISO 10303-210 §7 (network identifier uniqueness)
  • bug-reporter language: "AP210 two nets named VCC", "PCB net name collision", "ECAD duplicate net name".

Sender

deduced — ECAD exporter that merged two PCB sub-designs without re-namespacing nets

Description

Two `NETWORK` entities both declare the name 'VCC' yet route different conductors with no common node. A net-by-name lookup returns one or the other depending on instance ordering. Connectivity tools merge unrelated traces, breaking impedance / continuity checks.

Reproducer recipe

two `NETWORK('VCC',..)` entities each with a distinct, non-overlapping `NETWORK_NODE` set.

Expected kernel behavior

validate NETWORK.name uniqueness; reject or rename one with a diagnostic.

Notes

Synonyms: "PCB net name collision", "AP210 duplicate net", "ECAD net namespace conflict".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'ELECTRONIC_ASSEMBLY_INTERCONNECT_AND_PACKAGING_DESIGN')
  • count_entity_def(b'NETWORK') >= 2
  • contains(b"NETWORK('VCC',")

Tier-3 assertions

  • shape_null == True
