Description

A "find-contiguous-edges" pass identifies free edges that *would* match across faces, but the pairs have different parameter lengths even though their 3D extents are similar. Typical fixture: two LINE entities from the same origin — one with a unit-magnitude VECTOR along a unit DIRECTION, the other with a unit-magnitude VECTOR along a non-unit DIRECTION (e.g., (0.5,0,0)) — covering the same 3D extent but with different parameter lengths. Bug-reporter language: "contiguous edges mismatched length", "free edge pair length differ", "non-unit DIRECTION breaks parameterization".

Reproducer recipe

Two LINE/VECTOR pairs both running between the same two 3D points, one along a unit DIRECTION and one along a non-unit DIRECTION — so parameterized lengths differ even though 3D extents match.

Expected kernel behavior

Reparameterize the shorter edge; emit a warning.

Notes

Synonyms: "free edge pair length mismatch", "sewn edge pair parameter length differs", "non-unit DIRECTION on edge pair", "FindContigousEdges mismatch".
