M139 — AP203 effectivity start date is AFTER its end date

§12.8 (sub-class: AP203 effectivity window malformed)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M139.stp

Sources

  • 16-iso-spec ISO 10303-203 §4 (effectivity invariants)
  • bug-reporter language: "AP203 effectivity reversed", "start after end", "PDM effectivity window empty".

Sender

deduced — PDM exporter that swapped start / end fields when the effectivity was authored backwards

Description

A `TIME_INTERVAL_BASED_EFFECTIVITY` declares `effectivity_start` later than `effectivity_end`. The interval is empty, or - taken literally - runs backward in time. No date is ever within the effectivity window, making the configuration permanently unavailable.

Reproducer recipe

`TIME_INTERVAL_BASED_EFFECTIVITY('rev','rev_A', 2025-06-01, 2024-12-31)`.

Expected kernel behavior

detect reversed interval; reject or swap the dates with a warning.

Notes

Synonyms: "AP203 effectivity backwards", "negative-duration effectivity", "empty effectivity window".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'CONFIG_CONTROL_DESIGN')
  • contains(b'TIME_INTERVAL_BASED_EFFECTIVITY')
