M116 — AP209 modal extraction count exceeds DOF rank

§12.8 mixed (sub-class: AP209 modal analysis)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M116.stp

Sources

  • deduced from AP209 §9 eigenvalue_extraction_method requested-mode count vs system DOF

Sender

deduced — FEA template requesting fixed mode count regardless of model size

Description

A modal-analysis card requests extraction of 50 modes from a model with only 18 active DOFs. The eigensolver either returns 18 real modes plus 32 NaN/garbage entries, or fails outright. Bug-reporter language: "AP209 too many modes requested", "FEM eigensolver returns NaN modes", "mode count exceeds DOF".

Reproducer recipe

A `FEA_MODEL_3D` with three free nodes (9 DOFs) but a modal extraction parameter requesting 50 modes.

Expected kernel behavior

Heal and accept: coerce the requested mode count to the system rank and warn loudly.

Notes

Synonyms: "AP209 mode count too high", "eigensolver over-request", "modal extraction count exceeds DOF rank", "more modes than DOFs", "AP209 NaN modes returned".
