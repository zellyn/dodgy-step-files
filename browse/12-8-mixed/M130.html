M130 — AP203 assembly classified at lower security level than its components

§12.8 (sub-class: AP203 security classification hierarchy)

P1 — silent data loss

Sources

  • 16-iso-spec ISO 10303-203 §5.5 (security classification)
  • bug-reporter language: "AP203 security inversion", "child confidential in unclassified parent", "PDM clearance hierarchy broken".

Sender

deduced — PDM exporter that tagged classifications per-leaf but did not propagate up to assemblies

Description

A parent `PRODUCT` carries a `SECURITY_CLASSIFICATION` level of 'unclassified' but a child component used in a `NEXT_ASSEMBLY_USAGE_OCCURRENCE` carries 'confidential'. Aggregating a classified child into an unclassified parent inverts the security clearance hierarchy: anyone permitted to read the parent now has visibility of the classified child. Bug-reporter language: "AP203 security classification inversion", "PDM access-control violation".

Reproducer recipe

parent `PRODUCT` with `SECURITY_CLASSIFICATION_LEVEL('unclassified')`; child with `SECURITY_CLASSIFICATION_LEVEL('confidential')`; both linked through `CC_DESIGN_SECURITY_CLASSIFICATION`.

Expected kernel behavior

validate classification monotonicity from leaves to root; reject or warn if any child exceeds the parent's level.

Notes

Synonyms: "AP203 clearance inversion", "ITAR/EAR hierarchy violation", "classified child unclassified parent".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'CONFIG_CONTROL_DESIGN')
  • count_entity_def(b'SECURITY_CLASSIFICATION') >= 2
  • contains(b'CC_DESIGN_SECURITY_CLASSIFICATION')
