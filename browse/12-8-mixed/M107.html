M107 — AP238 cutting tool diameter declared as zero or negative

§12.8 mixed (sub-class: AP238 tool dimension)

P1 — silent data loss

Sources

  • deduced from ISO 10303-238 §5.7 cutting_tool_dimension positivity

Sender

deduced — STEP-NC publisher emitting tool template with default zero values

Description

A milling tool's diameter `MEASURE_WITH_UNIT` carries the numeric value `0.0` (or worse, a negative). The controller either rejects the file or generates a toolpath with zero radial offset, producing contour-on-contour passes with no material removal. Bug-reporter language: "AP238 tool zero diameter", "STEP-NC milling tool size missing", "zero diameter cutter".

Reproducer recipe

`MEASURE_WITH_UNIT(POSITIVE_LENGTH_MEASURE(0.0), mm_unit)` attached as the diameter of a milling tool referenced by a `MACHINING_OPERATION`.

Expected kernel behavior

reject zero/negative tool diameters as malformed; or warn loudly.

Notes

Synonyms: "zero-diameter tool", "AP238 tool dimension missing", "milling tool diameter is zero or negative", "STEP-NC bad tool size", "cutting tool has no radial offset".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'AP238_STEP_NC_MIM')
  • contains(b'POSITIVE_LENGTH_MEASURE(0.0)')
