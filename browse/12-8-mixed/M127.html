M127 — AP203 DOCUMENT_FILE referenced with empty URI / path field

§12.8 (sub-class: AP203 document reference completeness)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M127.stp

Sources

  • 16-iso-spec ISO 10303-203 §5.4 (document references)
  • bug-reporter language: "DOCUMENT_FILE has no URI", "AP203 document reference is empty", "spec link points to nothing".

Sender

deduced — PDM exporter that elided the URI when the source document was an internal-only artifact

Description

A `DOCUMENT_FILE` is referenced as a specification document but its identifier, name, and description fields are empty strings. Consumers cannot resolve the referenced document to any URI or path; the reference is effectively unreachable.

Reproducer recipe

`DOCUMENT_FILE('','','',doc_type)` referenced via `APPLIED_DOCUMENT_REFERENCE`.

Expected kernel behavior

detect empty document references; warn, drop the reference, or reject as malformed.

Notes

Synonyms: "AP203 doc URI missing", "empty document ref", "PDM dangling spec link".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'CONFIG_CONTROL_DESIGN')
  • contains(b'DOCUMENT_FILE')
  • contains(b"DOCUMENT_FILE('','','',")

Tier-3 assertions

  • shape_null == True
