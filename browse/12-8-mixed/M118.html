M118 — AP209 non-conforming mesh: tet and hex sharing a face with mismatched node counts

§12.8 mixed (sub-class: AP209 mesh continuity)

P1 — silent data loss

Sources

  • deduced from AP209 §6 mesh-conformity invariants

Sender

deduced — multi-mesher pipeline that didn't insert MPC tying at the tet-hex interface

Description

A linear tet (3 nodes per face) and a linear hex (4 nodes per face) share the same geometric face. The tet face has 3 nodes; the hex face has 4 nodes. There is no `MULTI_POINT_CONSTRAINT` tying the fourth-node displacement to the tet's three nodes. The interface is geometrically continuous but kinematically free; the solver computes separation across the face. Bug-reporter language: "AP209 non-conforming mesh", "FEM tet-hex interface ungated", "mesh leaks at element boundary".

Reproducer recipe

A `VOLUME_3D_ELEMENT_DESCRIPTOR` for a tet sharing one face geometrically with another `VOLUME_3D_ELEMENT_DESCRIPTOR` hex; no MPCs tying the extra hex node.

Expected kernel behavior

detect non-conforming interfaces; warn, generate the necessary MPCs, or reject.

Notes

Synonyms: "AP209 hanging node", "non-conforming interface", "mesh discontinuity".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a
