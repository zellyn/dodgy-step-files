M123 — AP209 element references the same node twice in its node list

§12.8 mixed (sub-class: AP209 element node uniqueness)

P1 — silent data loss

assembly

View raw fixture (.stp) step-examples/12-8-mixed/M123.stp

Sources

  • deduced from AP209 §6 element node-set uniqueness invariant

Sender

deduced — FEA preprocessor with off-by-one in node-list construction

Description

A `VOLUME_3D_ELEMENT_DESCRIPTOR` for a linear_tetrahedron (which mandates 4 distinct corner nodes) lists nodes `(n1, n2, n3, n2)` — node 2 appears twice. The element collapses to a degenerate triangle of zero volume. Solver assembly produces NaN entries or skips the element silently. Bug-reporter language: "AP209 element repeats node", "FEM element with duplicate node", "tet has 3 unique nodes".

Reproducer recipe

`VOLUME_3D_ELEMENT_DESCRIPTOR('lin_tet', 'linear_tetrahedron', (n1,n2,n3,n2))`.

Expected kernel behavior

validate unique node references per element; reject as malformed.

Notes

Synonyms: "AP209 duplicate node in element", "degenerate element", "FEM node-list error".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'linear_tetrahedron')
  • contains(b'VOLUME_3D_ELEMENT_DESCRIPTOR')
