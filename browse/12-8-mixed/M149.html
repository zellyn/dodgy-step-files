M149 — AP210 component pin numbering doesn't match physical pin sequence

Sources

  • 16-iso-spec ISO 10303-210 §6 (terminal physical_location ordering)
  • bug-reporter language: "AP210 pin order swapped", "PCB pin numbering CCW", "ECAD pin sequence wrong".

Sender

deduced — ECAD exporter that wrote terminal records from a schematic-side index that disagrees with the physical placement order

Description

A 4-pin SOT-23 package declares pins 1, 2, 3, 4 around the package perimeter, but the geometric order of `TERMINAL` placements walks counterclockwise (1, 4, 3, 2) instead of the package datasheet's clockwise order. Soldering follows the geometric placement; the netlist's pin assignment is rotated 180 deg.

Reproducer recipe

four `TERMINAL` entries with names 'pin1' . 'pin4' placed at coordinates that walk CCW instead of CW.

Expected kernel behavior

validate terminal indexing against package datasheet conventions; reject or warn on inconsistent ordering.

Notes

Synonyms: "PCB pin order CCW vs CW", "AP210 pin sequence inverted", "pin numbering CW vs CCW", "package pin geometric order wrong". Synonyms: "PCB pin order CCW vs CW", "AP210 pin sequence inverted".
