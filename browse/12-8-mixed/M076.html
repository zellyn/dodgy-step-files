M076 — AP238 cutting-tool feedrate stated in wrong dimensional unit

§12.8 mixed (sub-class: AP238 unit dimensionality)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M076.stp

Sources

  • deduced from ISO 10303-41 dimensional_exponents

Sender

deduced — STEP-NC publisher confusing velocity and acceleration units

Description

A `MACHINING_TOOL_FEEDSPEED`'s feedrate is given as a `MEASURE_WITH_UNIT` whose unit's `DIMENSIONAL_EXPONENTS` are `(1, 0, -2, ..)` (length/time^2 — acceleration) instead of `(1, 0, -1, ..)` (length/time — velocity). A consumer mapping the value to the machine's feed register either silently scales by an unintended factor or rejects. Bug-reporter language: "STEP-NC feedrate has wrong units", "AP238 measure is acceleration not velocity", "feedspeed import scales weirdly".

Reproducer recipe

`DERIVED_UNIT` composed of `LENGTH^1` and `SECOND^-2`, used as the unit on a `MEASURE_WITH_UNIT(LENGTH_MEASURE(500.0), ..)` for feed.

Expected kernel behavior

validate dimensional_exponents against the expected dimension class for the property; reject as malformed or warn and refuse to scale.

Notes

Synonyms: "feedrate dimensional exponent wrong", "wrong physical unit on toolpath", "AP238 feedrate is acceleration unit", "feedrate units mismatch length/time". Synonyms: "feedrate dimensional exponent wrong", "wrong physical unit on toolpath".
