M154 — AP210 placement footprint pin count conflicts with library footprint

§12.8 mixed (sub-class: AP210 component package mismatch)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M154.stp

Sources

  • 16-iso-spec ISO 10303-210 §6 (component vs library consistency)
  • bug-reporter language: "AP210 footprint pin count wrong", "BGA library 84 pins placement 4", "ECAD package mismatch".

Sender

deduced — ECAD exporter that copied a placement from a small-package template while assigning a large-package PRODUCT

Description

A `NEXT_ASSEMBLY_USAGE_OCCURRENCE` places component U1 with a 4-pin layout, but the referenced PRODUCT 'BGA_84' has 84 pins in its package model. The placement footprint and the component- library footprint disagree on pin count.

Reproducer recipe

`PRODUCT('BGA_84',..)` with `library_pin_count='84'`; placement assigning only 4 `TERMINAL`s.

Expected kernel behavior

validate placement footprint pin count against library declaration; reject or warn.

Notes

Synonyms: "AP210 package mismatch", "PCB footprint vs library", "ECAD pin count contradiction".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(4) ifc=schema_n/a

Byte assertions

  • contains(b'ELECTRONIC_ASSEMBLY_INTERCONNECT_AND_PACKAGING_DESIGN')
  • contains(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE')
  • contains(b'library_pin_count')

Tier-3 assertions

  • shape_null == False
  • n_vertices_total == 4
