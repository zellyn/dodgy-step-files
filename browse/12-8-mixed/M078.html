M078 — AP209 quadratic_hexahedron with wrong node count (12 instead of 20)

§12.8 mixed (sub-class: AP209 element topology)

Sender

deduced — FEA exporter confusing linear and quadratic shape functions

Description

A `VOLUME_3D_ELEMENT_DESCRIPTOR` declares `quadratic_hexahedron` topology — which mandates 20 nodes (8 corner + 12 mid-edge) — but the descriptor's node list contains only 12. The resulting element cannot be evaluated as a quadratic hex; consumers either fall back to linear interpolation silently or drop the element. Bug-reporter language: "AP209 hex element has wrong node count", "quadratic hex with too few nodes", "FEM element drops on import".

Reproducer recipe

`VOLUME_3D_ELEMENT_DESCRIPTOR('quad_hex', 'quadratic_hexahedron', (n1.n12))` — 12 nodes for a topology requiring 20.

Expected kernel behavior

validate node-count against the declared topology; drop the element with a warning, or reject the file.

Notes

Synonyms: "AP209 hex node count wrong", "quadratic hex with 12 nodes not 20", "FEA element node count wrong for hex8", "AP209 element under-noded", "hex element missing mid-edge nodes". **See also**: M037, M109, analog, tetrahedral, the.- **Byte assertion**: contains(b'STRUCTURAL_ANALYSIS_DESIGN')
