M092 — AP238 workplan workingsteps in non-executable order

§12.8 mixed (sub-class: AP238 workplan ordering)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M092.stp

Sources

  • deduced from ISO 10303-238 §6.4 workplan execution semantics

Sender

deduced — STEP-NC publisher emitting workingsteps in authoring order rather than dependency order

Description

A `WORKPLAN` lists its `its_elements` in an order that violates feature dependencies: a finishing pass appears before the roughing pass, or a drilling step on a hole appears before the spot-drilling step that locates it. Per AP238 §6.4 a workplan's element list is the *executable* sequence; order is semantic, not editorial. A controller running the file as written produces a part with a broken/missing locator. Bug-reporter language: "STEP-NC workingsteps run in wrong order", "AP238 finishing before roughing", "workplan order doesn't make sense".

Reproducer recipe

`WORKPLAN('main',(#finish_step, #rough_step),$,$,$)` where `#finish_step` is a finishing `MACHINING_OPERATION` referencing the same feature as `#rough_step` (a roughing operation), with the finishing step listed first.

Expected kernel behavior

validate workingstep ordering against feature dependency graph; warn on suspicious orderings (finishing before roughing on the same feature) or reject as malformed.

Notes

Synonyms: "STEP-NC bad workingstep sequence", "workplan order semantically wrong", "finishing before roughing".
