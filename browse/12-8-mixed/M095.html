M095 — AP238 machining_operation declares negative execution time

Sender

deduced — STEP-NC publisher with timestamp-arithmetic bug computing end_time minus start_time with arguments swapped

Description

A `MACHINING_OPERATION`'s associated `EXECUTION_TIME` (a `TIME_MEASURE_WITH_UNIT`) carries a negative numeric value, e.g. `-12.5` seconds. STEP-NC consumers using execution time for cycle-time estimation produce nonsensical totals; some implementations roll the value modulo zero and report a one-pass cycle as multi-hour. Bug-reporter language: "STEP-NC cycle time negative", "AP238 operation duration wrong sign", "negative time in NC file".

Reproducer recipe

`MEASURE_WITH_UNIT(TIME_MEASURE(-12.5), seconds_unit)` attached to a `MACHINING_OPERATION` as its execution time.

Expected kernel behavior

reject negative time values; or take absolute value and warn.

Notes

Synonyms: "negative duration", "AP238 time goes backwards", "machining operation negative time", "execution_time below zero", "STEP-NC negative duration".
