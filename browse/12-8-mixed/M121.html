M121 — AP209 time-history loadcase with non-monotonically increasing time vector

§12.8 mixed (sub-class: AP209 transient loadcase)

P1 — silent data loss

spec-violation

Sources

  • deduced from AP209 §9 time-history representation invariants

Sender

deduced — FEA exporter sorting time-vs-amplitude pairs by amplitude rather than by time

Description

A time-varying force is encoded as a paired list of (time, amplitude) tuples whose time component is not monotonically increasing; e.g., `[(0,0), (1,5), (0.5,3), (2,7)]`. A transient solver using these as time-stamped loads either overshoots, walks backwards in time, or fails to interpolate. Bug-reporter language: "AP209 time vector out of order", "FEM transient load timestamps wrong", "time history not monotonic".

Reproducer recipe

A list of paired `(REAL, REAL)` describing time and load amplitude where the time series goes `0.0, 1.0, 0.5, 2.0`.

Expected kernel behavior

sort by time and warn; or reject as malformed.

Notes

Synonyms: "AP209 non-monotonic time", "transient load order wrong", "time series unsorted".
