M081 — AP209 integration_point_count not consistent with element_type

§12.8 mixed (sub-class: AP209 integration rule)

P1 — silent data loss

View raw fixture (.stp) step-examples/12-8-mixed/M081.stp

Sources

  • deduced from AP209 §6 element_representation rules

Sender

deduced — FEA exporter copying integration rule from a higher-order element to a lower-order one

Description

An `ELEMENT_REPRESENTATION` for a `linear_beam` (which is exactly integrated with 1-2 Gauss points) declares 5 integration points. The over-integrated element either locks (artificially stiff) or the integration points fall in regions of the parametric domain that don't exist for the element family. Bug-reporter language: "FEM element locks unexpectedly", "AP209 integration rule mismatched", "Gauss points out of range".

Reproducer recipe

`linear_beam` `CURVE_3D_ELEMENT_DESCRIPTOR` paired with `ELEMENT_REPRESENTATION` declaring 5 integration points.

Expected kernel behavior

Heal and accept: validate integration-point count against element family's exact-integration requirement; warn-and-accept or reduce.

Notes

Synonyms: "over-integration", "wrong Gauss rule", "AP209 integration point count wrong", "FEM element locks artificially stiff", "integration_point_count vs element_type mismatch".
