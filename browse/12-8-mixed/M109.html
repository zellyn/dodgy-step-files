M109 — AP209 linear_hexahedron with only 4 nodes (should be 8)

Sender

deduced — FEA exporter with element-conversion bug truncating node list

Description

A `VOLUME_3D_ELEMENT_DESCRIPTOR` declares `linear_hexahedron` topology — which mandates 8 corner nodes — but lists only 4 nodes in its node-reference list. The descriptor cannot be evaluated as a hex; consumers may treat as a degenerate tet, drop the element silently, or reject the file. Bug-reporter language: "AP209 hex element has 4 nodes", "linear hex with too few nodes", "FEM element reduces to tet".

Reproducer recipe

`VOLUME_3D_ELEMENT_DESCRIPTOR('lin_hex', 'linear_hexahedron', (n1,n2,n3,n4))` — 4 nodes for a topology requiring 8.

Expected kernel behavior

validate node-count against declared topology; drop the element with a warning, or reject.

Notes

Synonyms: "AP209 hex with 4 nodes", "linear_hexahedron node count too low", "FEA element node count wrong for hex8", "hex element missing 4 corner nodes", "hex degenerated to tet shape". **See also**: M037, M078.
