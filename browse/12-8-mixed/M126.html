M126 — AP203 effectivity periods overlap with conflicting product configurations

§12.8 (sub-class: AP203 configuration management / effectivity)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M126.stp

Sources

  • 16-iso-spec ISO 10303-203 §4 (configuration management / effectivity)
  • bug-reporter language: "STEP effectivities overlap", "AP203 configuration ambiguous on date X", "two effectivities cover the same window".

Sender

deduced — PDM exporter merging two configuration baselines without re-validating the effectivity windows

Description

Two `TIME_INTERVAL_BASED_EFFECTIVITY` entities cover an overlapping date range while binding contradictory product configurations. A configuration query at any date in the overlap window may return either configuration depending on which effectivity was scanned first; the configuration is non-deterministic. Bug-reporter language: "AP203 effectivity overlap", "two configurations effective same date", "PDM ambiguous effectivity".

Reproducer recipe

`TIME_INTERVAL_BASED_EFFECTIVITY('cfg_v1','rev_A', 2024-01-01, 2024-12-31)` and a second covering `2024-06-01 . 2025-05-31` with `rev_B`.

Expected kernel behavior

detect overlapping effectivity windows; reject the configuration set, or warn and pick the latest-released configuration deterministically.

Notes

Synonyms: "effectivity ambiguity", "configuration overlap", "AP203 PDM date conflict". **See also**: A012.
