M162 — Fillet faces re-import as rounded edge (Onshape/Rhino) but as fillet in producer

§12.8 mixed (sub-class: feature-classification / surface category)

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-8-mixed/M162.stp

Sources

  • FreeCAD #20889
  • bug-reporter language: "STEP export gives wrong results for fillets", "fillets are read incorrectly by Onshape, Rhino — rounded edge instead of fillet", "fusion and FreeCAD itself read it correctly".

Sender

FreeCAD PartDesign Fillet on the boolean union of a Box + Cylinder.

Description

A fillet between a planar face and a cylindrical face is emitted as a `B_SPLINE_SURFACE_WITH_KNOTS` cubic patch instead of an analytical `TOROIDAL_SURFACE`. Receivers (Onshape, Rhino) classify the result as "rounded edge" rather than "fillet feature" because they look for the `TOROIDAL_SURFACE` analytic type to recognize fillets as features for downstream chamfer/blend editing. Fusion 360 and FreeCAD itself recognise the geometry visually but lose the feature category.

Reproducer recipe

STEP file where a fillet between a planar face and a cylindrical face is encoded as `B_SPLINE_SURFACE_WITH_KNOTS` instead of `TOROIDAL_SURFACE`.

Expected kernel behavior

Heal and accept: writer prefers the most-specific analytical surface type when geometry permits; receivers should heal feature classification by falling back to feature-recognition heuristics rather than relying on surface-type classification. Warn and accept with W_FEATURE_CLASSIFICATION_LOST when the analytical surface cannot be recovered.

Notes

**See also**: P007. Synonyms: "fillet emitted as B-spline instead of torus", "Onshape sees rounded edge not fillet", "feature category lost on STEP export", "STEP fillet is bspline".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(11) ifc=schema_n/a

Byte assertions

  • contains(b'B_SPLINE_SURFACE_WITH_KNOTS')
  • contains(b'PLANE') and contains(b'CYLINDRICAL_SURFACE')
