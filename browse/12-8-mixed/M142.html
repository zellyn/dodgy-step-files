M142 — AP203 CHANGE_REQUEST targets revision already superseded

§12.8 (sub-class: AP203 change-request validity)

P1 — silent data loss

Sources

  • 16-iso-spec ISO 10303-203 §4.5 (action / change request workflow)
  • bug-reporter language: "AP203 ECO targets old revision", "change request on obsolete part", "PDM change against superseded rev".

Sender

deduced — PDM exporter that emitted in-flight change requests after a revision had been re-baselined

Description

A `CHANGE_REQUEST_ITEM` (`APPLIED_ACTION_ASSIGNMENT` of role 'change_request') points at `PRODUCT_DEFINITION` rev_A for which a successor rev_B has already been released (per `PRODUCT_DEFINITION_RELATIONSHIP`). Changes targeting the obsolete revision cannot be applied without re-baselining. The change request is invalid as written.

Reproducer recipe

`PRODUCT_DEFINITION_RELATIONSHIP('eco','derived_from', rev_A_pd, rev_B_pd)` plus an `APPLIED_ACTION_ASSIGNMENT(change_action, (rev_A_pd))`.

Expected kernel behavior

detect change requests against superseded revisions; warn and re-target, or reject.

Notes

Synonyms: "AP203 ECO obsolete target", "PDM change against old rev", "change request stale".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'APPLIED_ACTION_ASSIGNMENT')
  • contains(b'PRODUCT_DEFINITION_RELATIONSHIP')
