M070 — `STL` writer does not respect existing triangulation

§12.8 tessellation

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M070.stp

Sources

  • OCCT MANTIS#0025357 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

An STL writer is invoked on a shape that already has an attached triangulation. The writer ignores the existing mesh and re-tessellates from B-rep using default deflection; losing the user's carefully-tuned mesh.

Reproducer recipe

Shape with attached triangulation (e.g., from a prior `BRepMesh_IncrementalMesh` call with custom deflection); write to STL.

Expected kernel behavior

STL writer reuses any existing triangulation unless explicitly told to remesh; never silently re-tessellate.

Notes

Synonyms: "STL writer ignores triangulation", "user mesh re-tessellated", "tuned mesh lost on STL export", "writer recomputes deflection", "STL writer ignores attached triangulation". **See also**: M057, U037.

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Closure intent

sheet — the open shell is the intended final geometry; a solid-only kernel should cleanly refuse.

Tier-3 assertions

  • n_edges_total >= 4
  • face[0].surface_type == "plane"
  • n_vertices_total >= 8
