M090 — AP210 BoM line item with no PRODUCT_DEFINITION chain

§12.8 mixed (sub-class: AP210 BoM completeness)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-8-mixed/M090.stp

Sources

  • deduced from AP210 BoM completeness rules / AP242 PDM conventions

Sender

deduced — ECAD exporter writing component refdes-only listings

Description

A `NEXT_ASSEMBLY_USAGE_OCCURRENCE` in a PCB BoM names a child `PRODUCT` (e.g. `R0805_10K`) but the child has no `PRODUCT_DEFINITION_FORMATION` / `PRODUCT_DEFINITION` / `SHAPE_DEFINITION_REPRESENTATION` chain. The BoM contains only a name — no geometry, no MPN association, no footprint reference. Bug-reporter language: "PCB BoM has refdes but no part", "AP210 component without geometry", "BoM strings only".

Reproducer recipe

`NAUO('R1','R1','at_corner', parent_PD, child_PRODUCT, $)` where the child PRODUCT has no PD.

Expected kernel behavior

detect missing PD chain; either synthesize a placeholder PD, drop the line item, or reject the BoM.

Notes

Synonyms: "BoM stub", "PCB part definition missing", "AP210 NAUO has no PRODUCT_DEFINITION chain", "BoM line item is name-only", "PDM child has no geometry".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'ELECTRONIC_ASSEMBLY_INTERCONNECT_AND_PACKAGING_DESIGN')
  • contains(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE')

Tier-3 assertions

  • shape_null == True
