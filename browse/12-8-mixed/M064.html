M064 — GEOMETRIC_REPRESENTATION_CONTEXT lacks UNCERTAINTY_MEASURE_WITH_UNIT; reader-side default precision substituted

§12.8 (sub-class: missing tolerance context)

Sources

  • OCCT STEPControl_ActorRead.cxx:2116 ("No Length Uncertainty, value of read.precision.val is taken") (uncovered class evidence)

Sender

deduced — OCCT uncovered-class sweep

Description

Context lacks an `UNCERTAINTY_MEASURE_WITH_UNIT` for length; the reader substitutes a fixed precision constant. Models that genuinely need a tighter or looser tolerance silently get the wrong one. Bug-reporter language: "no tolerance in file", "kernel-default precision used".

Reproducer recipe

A `GEOMETRIC_REPRESENTATION_CONTEXT` with no uncertainty in its measures list.

Expected kernel behavior

Heal and accept: compute uncertainty from the file's geometry-extent and entity tolerances; warn that no uncertainty was declared.

Notes

Synonyms: "uncertainty defaulted", "precision guessed", "no tolerance in file", "kernel-default precision used", "UNCERTAINTY_MEASURE missing".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(2) ifc=schema_n/a

Byte assertions

  • contains(b'GEOMETRIC_REPRESENTATION_CONTEXT')
  • contains(b'no_uncertainty')
  • count_entity_def(b'UNCERTAINTY_MEASURE_WITH_UNIT') == 0

Tier-3 assertions

  • n_faces_total == 0
  • n_edges_total >= 1
  • parametric.uncertainty_values == []
