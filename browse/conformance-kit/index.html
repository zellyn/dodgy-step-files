STEP Kernel Conformance Kit

A curated subset of 80 catalog entries (~6.2% of the full corpus) that any STEP-handling kernel should pass before being considered industry-ready. Spans every defect class in the catalog's 15-tag taxonomy.

80 entries · 15 tags · bytes-sufficient · machine-checkable

How to use

For each entry, run your kernel against the fixture file (step-examples/<section>/<id>.stp). Each entry's page documents the expected kernel behavior, the OCC reference behavior, and the model-level effect.

A kernel passes the Kit if it produces an outcome in the entry's allowed set, does not produce any outcome in the disallowed set, and does not crash, hang, or leak memory on adversarial entries.

Selection rationale

  1. Distinctness — each entry targets a different defect sub-class
  2. Mechanical verifiability — every entry has byte-level or tier-3 (geometric/topological) assertions
  3. Bytes-sufficient — defect lives in the .stp file alone, not in cross-file state, sibling pairs, or runtime-only behavior
  4. Tag-coverage — at least 4 entries per taxonomy tag (mostly 5-7), spread across major catalog sections
  5. Title brevity — sub-sub-class title-bloat (>120 chars) was excluded to keep canonical exemplars
