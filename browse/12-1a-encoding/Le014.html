Le014 — Apostrophe inside a `\X2\…\X0\` block decoded as string close

§12.1a encoding/strings (sub-class: directive/quoting interaction)

P1 — silent data loss

encoding

View raw fixture (.stp) step-examples/12-1a-encoding/Le014.stp

Sources

  • T038/step-file-parser

Description

Scanner that counts apostrophe parity but does not first identify hex-escape blocks may treat hex digits like `27` (which is the ASCII apostrophe code point) as a closing quote. The recognizer must consume `\X\` (exactly two hex digits), `\X2\…\X0\`, etc. before applying apostrophe parity.

Reproducer recipe

`'pre\X\27post'`

Expected kernel behavior

Heal and accept: scanner must recognise `\X\` consumes exactly two hex digits and `\X2\` continues until `\X0\` before deciding apostrophe parity.

Notes

Synonyms: "hex 27 inside X2 escape closes string", "apostrophe code-point misread as quote", "X2 block contains 27 garbles parser", "string closes inside Unicode escape", "embedded apostrophe code in hex run".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'\\X\\27')
