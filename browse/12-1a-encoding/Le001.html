Le001 — UTF-8 BOM at start of `ISO-10303-21;`

§12.1a encoding/strings (sub-class: BOM)

spec-violation encoding

Sender

Windows-based authoring tools that round-trip through "auto-detect text" editors

Description

A leading `EF BB BF` byte sequence appears before the literal `ISO-10303-21;` start token. The spec's framing grammar requires the magic token to be the first non-whitespace content with no BOM allowance, so strict parsers fail on the first non-ASCII byte. In Ed.3 the file body default encoding is UTF-8, which makes a leading BOM harmless data but still not part of the magic.

Reproducer recipe

file beginning with bytes `EF BB BF 49 53 4F 2D 31 30 33 30 33 2D 32 31 3B …`

Expected kernel behavior

heal: silently strip a single leading UTF-8 BOM at offset 0 with a warning; reject UTF-16/UTF-32 BOMs (`FF FE`, `FE FF`, `FF FE 00 00`, `00 00 FE FF`) with a clear `E_UNEXPECTED_BOM` diagnostic.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`warn(W_BOM)`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires. Synonyms: "UTF-8 BOM before ISO-10303-21", "byte order mark at start of STEP file", "EF BB BF before magic line", "parser fails on first byte BOM", "STEP file starts with BOM".
