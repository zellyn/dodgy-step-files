Le017 — Raw control character (U+0000.U+001F) in string body

§12.1a encoding/strings (sub-class: control characters in strings)

P1 — silent data loss

round-trip spec-violation encoding

Sources

  • N014/ISO 10303-21 Ed.3 §6.4.3.4
  • A029/lexer CR/LF pitfall
  • R053/OCCT bug 33815
  • W031/CAD Exchanger CHANGES v3.24.13

Description

Control characters (tab, LF, CR, NUL, etc.) must be encoded as `\X\hh` (e.g. tab = `\X\09`); raw bytes in a string literal are illegal even under the Ed.3 UTF-8 default. Files written by tools using "binary write" of attribute strings often contain raw `\t`, `\n`, or `\0`. Some parsers tolerate raw `\n` and then index past the line buffer when computing line/column for diagnostics. Round-tripping names with quotes, backslashes, and control chars must be preserved (per OCCT bug 33815).

Reproducer recipe

`'first line<RAW LF>second'`; `#1=PERSON('line1<RAW LF>line2');`

Expected kernel behavior

reject raw control characters in literals. Tolerant readers may translate raw `\n`/`\t` to space-equivalents and warn. Identifiers carrying control chars must round-trip without corruption when the user opted in.
