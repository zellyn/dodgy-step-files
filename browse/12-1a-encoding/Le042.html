Le042 — `\Q\` payload contains non-decimal characters

§12.1a encoding/strings (sub-class: numeric character reference)

crash silent-loss encoding

View raw fixture (.stp) step-examples/12-1a-encoding/Le042.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §6.4.3 (decimal-only payload)

Description

`\Q\NNN\Q\` requires the bracketed payload to be a decimal integer. Producers occasionally emit hex (`\Q\1F600\Q\`), an `0x` prefix (`\Q\0x1F600\Q\`), or whitespace around the number (`\Q\ 65 \Q\`). A strict parser rejects; a lenient parser may silently coerce, producing the wrong character (e.g. parsing `F60` as decimal 0 then F-A-A garbage).

Reproducer recipe

`PRODUCT.name='hex=\Q\F60\Q\'`; `'px=\Q\0x41\Q\'`; `'ws=\Q\ 65 \Q\'`.

Expected kernel behavior

reject any non-decimal payload with a precise diagnostic citing the offending characters; never silently substitute 0 for a malformed payload.

Notes

**See also**: Le030, Le040. **OCC behavior**: silently accepts non-decimal `\Q\` payloads and either substitutes 0 or coerces via leading digits; kernel mishandling — the catalog above forbids silent substitution. Synonyms: "Q directive with hex digits", "Q escape with 0x prefix", "Q payload not decimal", "whitespace inside Q numeric", "non-decimal Q payload".
