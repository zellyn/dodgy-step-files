Le045 — String literal at the Edition-3 length limit (32768 characters)

§12.1a encoding/strings (sub-class: length boundary)

spec-violation encoding

View raw fixture (.stp) step-examples/12-1a-encoding/Le045.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §6.4.4 (string literal max length 32768)

Description

Edition-3 raises the maximum string-literal length to 32768 characters (Edition 1 was 256). A reader that statically allocates a 256-char buffer truncates silently or faults; a reader that allocates dynamically but checks against an off-by-one threshold may reject one too many or one too few. The boundary character itself becomes load-bearing.

Reproducer recipe

`PRODUCT.name` whose string literal is exactly 32768 characters of `'A'`.

Expected kernel behavior

accept literals up to 32768 characters; reject longer with a length diagnostic; never silently truncate. Reading should be O(N) in literal length, not quadratic.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires. Synonyms: "string literal at 32768 char limit", "STEP string at exact Ed.3 maximum", "boundary-length string literal", "off-by-one on max string length", "max-length string truncated".

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

Byte assertions

  • max_string_literal_length >= 32768
  • max_string_literal_length >= 32700
