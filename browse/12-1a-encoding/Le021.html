Le021 — Component name in non-UTF-8 locale encoding (GB18030 / Shift-JIS / cp1251 / DOS850)

Sender

SolidWorks (Chinese locale), Inventor (Japanese/Korean locales), Russian Windows toolchains, German DOS850 toolchains

Description

A producer writes the literal multi-byte octets of GB18030, Shift-JIS, EUC-JP, cp1251, or CP850 directly into `PRODUCT.name`, `PROPERTY_DEFINITION.description`, label fields, and similar string slots. Ed.1/Ed.2 mandate `\X2\…\X0\` escapes; Ed.3 added UTF-8 only in 2016. Many producers neither escape nor declare an encoding header. UTF-8-only receivers mojibake the strings; older OCCT emitted question-mark replacements.

Reproducer recipe

`PRODUCT('FOO','bar',(0xE6 0xA0 0xB8),..);` — raw multi-byte octets outside `\X2\` blocks; PRODUCT name with cp1251 bytes for "Деталь"; PRODUCT name with raw Shift-JIS `0x82A0` ("ア").

Expected kernel behavior

detect non-UTF-8 byte sequences; provide a settable code page (e.g. `read.step.codepage`); auto-detect via heuristics or warn; convert internally to UTF-8; allow caller override. Strict Ed.2 mode rejects with `E_RAW_NON_ASCII`.

Notes

**See also**: Le022, Le035. Synonyms: "GB18030 bytes raw in STEP product name", "Shift-JIS in PRODUCT.name", "Cyrillic cp1251 chars unescaped", "Japanese characters as raw bytes in STEP", "non-UTF-8 locale bytes in attribute".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb"'[^']*[\\x80-\\xff][^']*'")
  • matches(rb"PRODUCT\([^;]*[\x80-\xff]")
