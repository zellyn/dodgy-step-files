Le025 — Empty / blank / single-space NAME silently emptied

§12.1a encoding/strings (sub-class: trim/whitespace)

P2 — spec deviation (no data loss)

silent-loss encoding

View raw fixture (.stp) step-examples/12-1a-encoding/Le025.stp

Sources

  • G044/OCCT 0911d06, Mantis 27169

Description

A `PRODUCT(' ',…)` with a NAME consisting only of a single space becomes an empty XCAF attribute name after trim, losing the original sender's intent.

Reproducer recipe

`PRODUCT(' ','id','desc',(..));`

Expected kernel behavior

Heal and accept: distinguish empty `''` from whitespace-only `' '`; preserve the sender's literal value, or apply a "useful-length" trim only after explicit user opt-in. Must not silently empty.

Notes

Synonyms: "empty PRODUCT name silently dropped", "single-space NAME becomes empty", "blank string trimmed in STEP", "whitespace-only NAME loses content", "STEP attribute becomes empty after import".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb"PRODUCT\(' ',")
  • count(b"PRODUCT('") >= 1
