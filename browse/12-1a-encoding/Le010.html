Le010 — `\F\` font-shift directive consumed wrongly

§12.1a encoding/strings (sub-class: `\F\` directive)

P1 — silent data loss

spec-violation encoding

View raw fixture (.stp) step-examples/12-1a-encoding/Le010.stp

Sources

  • N009/ISO 10303-21 Ed.3 §6.4.3 Table 4

Description

`\F\` introduces a single-character alternate-font selector (used for CJK font shifts) — exactly one letter follows. Tools sometimes embed multi-character font tags as if it were an HTML tag (`\F\bold\F\`).

Reproducer recipe

`'mix\F\katakana hello'` (illegal multi-letter tag).

Expected kernel behavior

reject with diagnostic; ignoring the directive is safer than over-consuming text.

Notes

Synonyms: "F directive consumes too many bytes", "font-shift escape multi-character", "CJK font tag confused with STEP escape", "F directive treated as HTML tag", "font shift directive runs past one letter".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a
