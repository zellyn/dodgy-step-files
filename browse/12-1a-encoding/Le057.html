Le057 — Records terminated with `;\n` plus extra blank lines between records

§12.1a encoding/strings (sub-class: end-of-record / non-canonical EOR)

P1 — silent data loss

Sources

  • ISO 10303-21 §6.2 (record syntax: `
  • ` terminates a record, intervening whitespace is allowed)
  • bug-reporter language: "STEP file has blank lines between records", "extra newlines confuse parser"

Sender

deduced — producers that hand-format Part-21 for human readability, post-process with text editors, or round-trip through tools that auto-insert blank lines (some VCS line-ending normalisers, some pretty-printers)

Description

ISO 10303-21 §6.2 allows arbitrary whitespace (including newlines) between records; the record terminator is the `;`, and what follows is lexically free until the next record's leading token. A producer that emits each record on its own line plus a trailing blank line (`..);\n\n`) is technically conformant but stresses streaming tokenisers that special-case `;\n` as a "next record starts here" boundary. Mixing `;\n` and `;\n\n` and `; #NEXT=` (no separator) within the same DATA section is non-canonical: a strict tokeniser that picks one form may mis-frame the others. Bug-reporter language: "STEP file has blank lines between records", "extra newlines confuse parser", "EOR formatting inconsistent across DATA section".

Reproducer recipe

a DATA section where some records end with `;\n` and the next begins immediately, others end with `;\n\n` (blank line between), and one record runs `;` followed by another record on the same line `;#11=..`. All three are spec-conformant; the inconsistency is the defect.

Expected kernel behavior

tokenise on `;` alone; treat all whitespace (including blank lines) between records as ignorable. Never reject a file for inter-record whitespace variation.

Notes

Sibling of Le056 (Part 1, different EOR variant). **See also**: Le054, Le056, Le058. Synonyms: "blank lines in STEP DATA", "non-canonical record separator", "mixed EOR whitespace".
