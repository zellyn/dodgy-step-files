N018 — `GEOMETRIC_REPRESENTATION_CONTEXT` missing `GLOBAL_UNCERTAINTY_ASSIGNED_CONTEXT` leaf → fall back to read.precision

§12.4 (sub-class: uncertainty context)

units

View raw fixture (.stp) step-examples/12-4-tolerance/N018.stp

Sources

  • 04-occt-translation Q043, Q044

Description

When a STEP file's `GEOMETRIC_REPRESENTATION_CONTEXT` lacks the `GLOBAL_UNCERTAINTY_ASSIGNED_CONTEXT` leaf — for example carries only `GLOBAL_UNIT_ASSIGNED_CONTEXT` and no `UNCERTAINTY_MEASURE_WITH_UNIT` for the model — OCCT silently falls back to the `read.precision.val` parameter. Models from such files all share whatever precision the user happened to configure, regardless of source.

Reproducer recipe

STEP file lacking `*_AND_GLOBAL_UNCERTAINTY_ASSIGNED_CONTEXT` complex entity; reference only bare `geometric_representation_context`.

Expected kernel behavior

heal — emit explicit "no uncertainty context" diagnostic; require user to confirm fallback; do not silently default.

Notes

**See also**: U025. **OCC behavior**: silently falls back to the configured working precision with no diagnostic; kernel mishandling; the catalog above forbids silent default. Synonyms: "no UNCERTAINTY_MEASURE in file", "model precision falls back to user setting", "tolerance silently inherits read.precision", "GEOMETRIC_REPRESENTATION_CONTEXT lacks uncertainty leaf".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • not_contains(b'UNCERTAINTY_MEASURE_WITH_UNIT(')
  • contains(b'GEOMETRIC_REPRESENTATION_CONTEXT')
  • count_entity_def(b'EDGE_CURVE') == 1

Tier-3 assertions

  • shape_null == True
