Tb005 — Face area sub-tolerance squared (`tol*tol` threshold defect)

§12.4 (sub-class: comparison-threshold mismatch)

P1 — silent data loss

spec-violation

View raw fixture (.stp) step-examples/12-4-tolerance/Tb005.stp

Sources

  • synthesized time-bomb.

Description

Many kernel algorithms compare *areas* to `tol*tol` rather than `tol`. A planar face with side length 3e-4 mm has area 9e-8 mm². The file declares `tol = 1e-4`; a kernel that filters degenerate faces with `area < tol*tol = 1e-8` keeps it. If the kernel later uses `tol = 1e-3` (for example, after a heal that bumped tolerance), the threshold becomes `tol*tol = 1e-6`, and the face is now sub-threshold and silently dropped. A face that survives one Boolean pass disappears in the next.

Reproducer recipe

A small planar `ADVANCED_FACE` (3e-4 × 3e-4 mm) on a `PLANE`, wrapped in a closed shell so OCCT can transfer; declared uncertainty 1e-4. Wrap in PRODUCT chain so tier-3 can compute area.

Expected kernel behavior

face-area thresholds should be derived from a documented invariant (e.g. minimum-feature-size) rather than `tol*tol`; a face that is non-degenerate at one tolerance must remain non-degenerate at any other tolerance within the operating range. Silent drop of an "infinitesimal" face is unacceptable; reject loudly or preserve the face.
