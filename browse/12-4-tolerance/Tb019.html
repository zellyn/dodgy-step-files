Tb019 — UNCERTAINTY value of `1.0E-30` — below any sane working precision

§12.4 (sub-class: out-of-range tolerance declaration)

Description

`UNCERTAINTY_MEASURE_WITH_UNIT(LENGTH_MEASURE(1.0E-30), ..)`. The value is below any reasonable kernel's working precision. A kernel that respects the declared value tries to compare features at 1e-30 precision and rejects everything as having gaps. A kernel that floors at `Precision::Confusion()` silently uses 1e-7; the file imports cleanly but its declared expectation has been overridden. Producer and receiver silently disagree about precision.

Reproducer recipe

PRODUCT-wrapped simple shape with `UNCERTAINTY_MEASURE_WITH_UNIT(LENGTH_MEASURE(1.0E-30), ..)`.

Expected kernel behavior

tolerance values outside the kernel's documented operating range must be flagged; either coerce-and-warn or reject-with-diagnostic; never silent substitution.

Notes

**See also**: Tb018, Tb020. **OCC behavior**: silently substitutes the floored working-precision value for the absurdly-tight declared uncertainty; kernel mishandling; the catalog above forbids silent substitution. Synonyms: "uncertainty 1e-30 below working precision", "absurdly tight tolerance", "tolerance below kernel resolution", "tolerance value impossibly small".
