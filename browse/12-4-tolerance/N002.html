N002 — Wireframe gap-fix inflates tolerance instead of bridging the gap

§12.4 (sub-class: tolerance ballooning by healing)

P1 — silent data loss

topology

Sources

  • 03-occt-tests R029 (OCC14846)

Description

A wireframe gap-fixing pass increases the maximum tolerance carried by edges and vertices to encompass the gap, rather than adjusting the underlying geometry to actually close it. The shape passes a topology check only because tolerance discs now overlap, hiding the real defect. The user-visible symptom is a "fixed" model whose vertex tolerance balls have ballooned to swallow gaps that were never repaired.

Reproducer recipe

Wire with consecutive edges whose 3D endpoints differ by 0.001 mm on a model with declared 1e-6 uncertainty. Run a wireframe gap-fix pass.

Expected kernel behavior

a gap-fix pass should adjust edge curve endpoints (or insert a bridge edge) so the geometric gap closes; only inflate tolerance when geometry cannot be modified safely; warn when tolerance is inflated.

Notes

**See also**: N040. Synonyms: "healer inflates tolerance instead of closing gap", "tolerance balls grow to swallow gap", "fix passes only because tolerance ballooned", "gap hidden behind fattened tolerance", "wire still has gap but model passes check".
