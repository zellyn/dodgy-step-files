Tb006 — Edge length sub-tolerance squared in 2D pcurve length

§12.4 (sub-class: comparison-threshold mismatch)

topology

View raw fixture (.stp) step-examples/12-4-tolerance/Tb006.stp

Sources

  • synthesized time-bomb.

Description

Sister to Tb005 but in pcurve space. Pcurve domain length is the parameter range; some kernels test pcurve degeneracy by comparing parameter range to `tol*tol_param`. A pcurve with parameter range 1e-4 on a face with declared `tol = 1e-3` is alive at `tol_param = sqrt(tol) ≈ 3.16e-2` but degenerate at `tol_param = tol*tol = 1e-6` (different sign/squareroot policies). Receiver A keeps the edge; receiver B drops it.

Reproducer recipe

An `EDGE_CURVE` on an `ADVANCED_FACE` with a `SURFACE_CURVE.associated_geometry` `PCURVE` whose parameter range is exactly 1e-4 in the U direction; declared uncertainty 1e-3.

Expected kernel behavior

Heal and accept: normalize the pcurve degeneracy criterion to a single documented invariant; preserve consistency across re-imports.

Notes

Synonyms: "pcurve length below tol*tol", "edge length squared comparison in 2D", "pcurve domain length squared vs linear tolerance", "small edge dropped under squared 2D check".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Tier-3 assertions

  • face[0].area < 1e-6
  • face[0].surface_type == "plane"
  • n_edges_total >= 4
