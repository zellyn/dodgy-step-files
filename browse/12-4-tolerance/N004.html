N004 — Edge same-parameter flag asserted but 3D curve and pcurve disagree at sampled parameters (`SameParameter=.T.` lie)

Description

An `EDGE_CURVE` declares the same-parameter invariant (3D curve and pcurve share parameterisation, `SameParameter=.T.`), but a sampling check shows the maximum point-wise deviation exceeds the declared edge tolerance. Typical pattern: a 3D `LINE` from (0,0,0) to (10,0,0) plus a pcurve `LINE` on a `PLANE` running at v=0.005; the pcurve lifts to a curve offset by 0.005 mm from the 3D curve, but the edge tolerance is only 1e-6. The flag was set without re-validation after a geometry edit, so the metadata claims an invariant the data no longer satisfies; the same-parameter flag is true but curves disagree at sampled values.

Reproducer recipe

Build an `EDGE_CURVE` with both 3D BSpline and pcurve. Reproject the pcurve at a different sampling. Set the same-parameter flag without recomputing. Run a topology checker.

Expected kernel behavior

re-parameterise one curve so the flag is true, drop the flag and inflate edge tolerance to absorb the actual deviation, or reject as malformed. Choice is kernel-design-dependent.

Notes

**See also**: N006. Synonyms: "3D curve and pcurve disagree at sampled points", "same parameter flag is true but curves don't match", "edge claims same param but pcurve drifts off 3D", "pcurve offset from 3D curve by 5 microns", "metadata claims invariant data has lost".
