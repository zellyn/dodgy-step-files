N043 — Shape-to-shape distance reports nonzero gap for clearly intersecting parts

§12.4 (sub-class: working precision / extrema)

P1 — silent data loss

topology

Sources

  • 18-other-issues I056 (OCCT #1123, FreeCAD #25158)

Description

For two shapes that demonstrably intersect (their volumes clearly overlap), the minimum-distance query returns a small but nonzero value (e.g. 6e-5 or 0.083) instead of zero. The distance algorithm samples corner points and edge endpoints but does not verify true intersection, so a transverse intersection between two interior surfaces is missed.

Reproducer recipe

4 cylinders intersecting a main part; compute pairwise minimum distance.

Expected kernel behavior

Heal and accept: a minimum-distance query between two intersecting bodies must return zero (or a value smaller than the kernel's working precision); when sampling reports a near-zero distance, the kernel should fall back to a true intersection test rather than reporting the sample value.

Notes

Synonyms: "distance query says gap but parts overlap", "shapes overlap but distance is nonzero", "distance algorithm misses interior intersection", "min distance returns 6e-5 for clearly intersecting solids".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • count_entity_def(b'CYLINDRICAL_SURFACE') == 1
  • count_entity_def(b'UNCERTAINTY_MEASURE_WITH_UNIT') == 3
  • contains(b'6.3E-5') and contains(b'8.3E-2')
