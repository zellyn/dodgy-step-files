Tb015 — Sliver edge length at sqrt(tol) — under squared comparison or linear?

§12.4 (sub-class: sqrt-tolerance ambiguity)

Description

An edge has 3D length 1e-3 mm in a file with declared tolerance 1e-6. A kernel comparing `length < tol` says "alive". A kernel comparing `length < sqrt(tol) ≈ 1e-3` says "right at the boundary — ambiguous". A kernel comparing `length*length < tol` (≡ `length < sqrt(tol)`) says the same boundary. The triple ambiguity (linear, squared, square-root) means three reasonable kernels can disagree on whether the edge survives heal.

Reproducer recipe

`EDGE_CURVE` of 3D length 1e-3 mm in a wrapped shell representation with declared uncertainty 1e-6.

Expected kernel behavior

Heal and accept: normalize the comparison policy to a documented form; documentation specifies whether thresholds are linear, squared, or square-rooted.

Notes

Synonyms: "edge length right at sqrt(tolerance)", "is comparison squared or linear ambiguous", "edge size at sqrt(tol) trips classifier", "boundary case for squared vs linear edge comparison".
