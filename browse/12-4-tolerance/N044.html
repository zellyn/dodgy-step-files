N044 — Persistent IDs lost across editing/translation breaks PMI tolerance attachment

§12.4 (sub-class: tolerance type entity coverage / persistence)

P1 — silent data loss

round-trip

View raw fixture (.stp) step-examples/12-4-tolerance/N044.stp

Sources

  • 17-standards-bodies M015 (CAx-IF Persistent IDs v1.8)
  • 21-patents X007 (Fujitsu EP 2940611), X011 (Dassault EP 3472735)

Description

Stable identifiers assigned to entities (faces, edges) for change tracking and PMI binding are regenerated by intermediate tools, breaking PMI references; a tolerance frame referencing face #47 in a source file no longer resolves after round-trip because the receiver renumbered topology.

Reproducer recipe

Round-trip an AP242 file through a viewer that recreates topology; `STEP_id` of every face changes; semantic PMI bound to those IDs becomes orphaned.

Expected kernel behavior

Heal and accept: preserve persistent IDs (UUIDs in `name_attribute` or `APPLIED_IDENTIFICATION_ASSIGNMENT`) verbatim during read+write; generate new IDs only for newly created entities. Must not silently regenerate IDs.

Notes

**See also**: A011, A028, Pmi001, Pmi057, Pmi065. Synonyms: "face IDs renumbered breaks PMI links", "stable IDs lost on round-trip", "tolerance frame loses face reference", "PMI reference no longer resolves after import", "topology renumbered drops persistent identifiers".

Expected validation

  • contains(b'IDENTIFICATION_ROLE')
  • count_entity_def(b'ADVANCED_FACE') == 2
