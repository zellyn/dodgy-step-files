N032 — Tolerance type entity coverage: AP242 tolerance entities dropped on import

§12.4 (sub-class: tolerance type entity coverage)

Sources

  • 11-translator-vendors W028 (HOOPS Exchange SDHE-21839/SDHE-21836)
  • 18-other-issues I011 (OCCT #384, NIST PMI)

Sender

AP242 PMI emitter (Creo MBD, NX MBD, SolidWorks MBD)

Description

STEP file uses an AP242 tolerance entity (e.g. `RUNOUT_TOLERANCE_WITH_VALUES`, `UNEQUALLY_DISPOSED_GEOMETRIC_TOLERANCE`, `RUNOUT_ZONE_DEFINITION` with `RUNOUT_ZONE_ORIENTATION_REFERENCE_DIRECTION`) that the importer drops because it isn't in its parser. Repeated fixes across HOOPS releases prove this class is large and ongoing.

Reproducer recipe

AP242 file containing `RUNOUT_ZONE_DEFINITION` etc.; importer that only knows AP214.

Expected kernel behavior

accept gracefully — at minimum preserve the raw entity through round-trip; do not crash; warn on unknown subtype.

Notes

Synonyms: "AP242 tolerance entity dropped on import", "GD&T tolerance lost in translation", "RUNOUT_TOLERANCE not parsed", "tolerance frame missing after STEP read".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'RUNOUT_TOLERANCE_WITH_VALUES')
  • contains(b'RUNOUT_ZONE_DEFINITION')
  • contains(b'RUNOUT_ZONE_ORIENTATION_REFERENCE_DIRECTION')
