N033 — Tolerance value polymorphic encoding (`MeasureRepresentationItem` vs plain measure)

§12.4 (sub-class: tolerance type entity coverage)

P1 — silent data loss

  • 18-other-issues I011 (OCCT #384)

Description

`STEP_SHAPE_TOLERANCE_VALUE` lower/upper bounds may be encoded via plain `length_measure_with_unit`, via `StepRepr_ReprItemAndMeasureWithUnit`, or via the AP242 complex form `(LENGTH_MEASURE_WITH_UNIT() MEASURE_REPRESENTATION_ITEM() MEASURE_WITH_UNIT(…) REPRESENTATION_ITEM(''))`. Readers that hard-code a single subtype fail; OCCT had 21 reader classes affected.

Reproducer recipe

NIST PMI examples (nist_ctc_01.nist_stc_10 ap242-e1/e2) with magnitudes wrapped in the complex form.

Expected kernel behavior

Heal and accept all variants — go through `StepRepr_ReprItemAndMeasureWithUnit::GetMeasureWithUnit` polymorphic accessor; never assume one form.

Notes

**See also**: N034. Synonyms: "tolerance measure encoded multiple ways", "reader handles only one tolerance subtype", "polymorphic measure-with-unit confuses parser", "AP242 complex form for tolerance value not read".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'MEASURE_REPRESENTATION_ITEM') or contains(b'LENGTH_MEASURE_WITH_UNIT')
  • count(b'0.005') >= 3
