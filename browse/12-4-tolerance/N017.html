N017 — `UNCERTAINTY_MEASURE_WITH_UNIT` populated with a fixed field-default value (untrustworthy)

§12.4 (sub-class: uncertainty context)

P1 — silent data loss

units

Sources

  • 14-brlcad-rhino K020 (McNeel forum)
  • 17-standards-bodies M020
  • 04-occt-translation Q044

Description

Many STEP exporters emit `UNCERTAINTY_MEASURE_WITH_UNIT` with a constant field-default value (e.g. 0.027352…) rather than a true measure of producer-side precision. Receivers that take this value as document tolerance get bad joins and false gaps when the real geometry is accurate to 1e-6.

Reproducer recipe

STEP with `UNCERTAINTY_MEASURE_WITH_UNIT(LENGTH_MEASURE(0.027352…), …, 'distance_accuracy_value', '')` on geometry actually accurate to 1e-6.

Expected kernel behavior

heal; cap reported tolerance against geometric tightness measured from the actual model; offer override; default to `read.precision.val` parameter when uncertainty is missing or implausible.

Notes

**See also**: N019. Synonyms: "uncertainty value looks like template default", "constant 0.027352 tolerance from exporter", "uncertainty is fixed default not real precision", "writer emits placeholder tolerance value".

Expected validation

  • count_entity_def(b'UNCERTAINTY_MEASURE_WITH_UNIT') == 1
