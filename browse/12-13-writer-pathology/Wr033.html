Wr033 — `FILE_SCHEMA` declares schema version that does not exist

§12.13 writer-pathology (sub-class: schema downgrade)

silent-loss spec-violation writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr033.stp

Sources

  • ISO 10303-21 schema-id format
  • bug-reporter language: "STEP schema unknown to my reader"

Sender

Writers with hard-coded schema-id strings that include a future or fictional version

Description

`FILE_SCHEMA(('AP242_MANAGED_MODEL_BASED_3D_ENGINEERING { 1 0 10303 442 1 99 99 }'))` — the schema name is recognised but the version tuple is unparseable or refers to a non-existent edition. Receivers either reject or ignore the version and load under the last-known compatible schema. Bug-reporter language: "STEP schema version unknown", "future schema version in file".

Reproducer recipe

`FILE_SCHEMA(('AUTOMOTIVE_DESIGN { 1 0 10303 214 99 1 1 }'))` (year tuple 99 is implausible).

Expected kernel behavior

warn on unrecognised schema version and either reject or load under the closest known schema with a diagnostic; never silently treat unknown as known.

Notes

Cousin of Lh004-class. **OCC behavior**: silently accepts the unparseable schema-version tuple (no warning); kernel mishandling — the catalog above forbids treating unknown as known.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a
