Wr019 — Re-export drops face and solid colour assignments

§12.13 writer-pathology (sub-class: round-trip data loss)

P1 — silent data loss

round-trip writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr019.stp

Sources

  • OCCT colour-round-trip tests
  • FreeCAD #5118 "colour lost on re-export"
  • bug-reporter language: "colours gone after STEP round-trip"

Sender

Writers without a colour-metadata propagation layer that drop `STYLED_ITEM` / `PRESENTATION_STYLE_ASSIGNMENT` / `COLOUR_RGB` chains on export

Description

The producer received a file with face- and solid-level colour assignments (`STYLED_ITEM`, `PRESENTATION_LAYER_ASSIGNMENT`) and emits a file that lacks them entirely, even though the geometry is intact. Bug-reporter language: "STEP file lost colours after round-trip", "colours gone", "all faces grey now".

Reproducer recipe

a STEP file showing the *post*-pathology state — a clean `MANIFOLD_SOLID_BREP` with no `STYLED_ITEM` / `COLOUR_RGB` references, where the title comment notes "originally had per-face colours, dropped on re-export".

Expected kernel behavior

preserve `STYLED_ITEM` / `COLOUR_RGB` chains on round-trip; surface a warning if the kernel's internal model cannot represent them.

Notes

Visible in §12.6 / §12.8 colour-bound entries; Wr019 documents the writer-side root cause. Bytes alone are insufficient to demonstrate this defect; needs sibling input fixture. Tagged provenance_tier: requires-sibling-pair.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'STYLED_ITEM') == 0 and count_entity_def(b'COLOUR_RGB') == 0
