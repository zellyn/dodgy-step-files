Wr036 — Re-export inverts solid orientation (inside becomes outside)

§12.13 writer-pathology (sub-class: round-trip data loss)

P2 — spec deviation (no data loss)

round-trip writer

Sources

  • OCCT MANTIS#0028xxx
  • bug-reporter language: "STEP solid is inside-out after re-export", "normals flipped" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers whose internal half-space convention differs from STEP's and that do not apply the conversion on export

Description

The input had a `MANIFOLD_SOLID_BREP` whose face normals point outward (kernel convention: solid material is on the negative side of the face normals, exterior is positive). The re-emitted file has all face normals reversed: the solid is topologically intact but represents an infinite material region with a single hole (the original solid's volume). Bug-reporter language: "STEP solid inside out", "normals flipped on re-export", "solid is inverted".

Reproducer recipe

a unit cube `MANIFOLD_SOLID_BREP` with all `ADVANCED_FACE.same_sense` flags set to `.F.` and corresponding `FACE_OUTER_BOUND.orientation` flipped — geometry is the cube but material is "outside the cube".

Expected kernel behavior

detect orientation by computing signed volume of the closed shell; if negative, flip and warn (or reject under strict policy).

Notes

Common in writers from a half-space-CSG kernel.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'ADVANCED_FACE\([^;]*\.F\.\)')
  • count(b'.F.') >= 1
