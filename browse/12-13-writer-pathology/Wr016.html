Wr016 — Re-output of intermediate construction entities (orphan geometry)

§12.13 writer-pathology (sub-class: construction-residue)

P2 — spec deviation (no data loss)

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr016.stp

Sources

  • OCCT forum "STEP file has unreferenced entities"
  • bug-reporter language: "orphan geometry", "STEP file 3× larger than it should be"

Sender

Writers that emit every kernel-internal entity, even those not referenced by the product structure (intermediate construction history, scratch geometry)

Description

The DATA section contains hundreds of `CARTESIAN_POINT`, `LINE`, `CIRCLE`, and other primitive entities that are not transitively referenced by any `PRODUCT_DEFINITION_SHAPE → SHAPE_DEFINITION_REPRESENTATION → MANIFOLD_SOLID_BREP` chain. The model is correct but the file is bloated 3-5× by construction-history scratch geometry. Bug-reporter language: "STEP file has unreferenced entities", "orphan geometry in DATA section", "construction history not pruned", "STEP file unnecessarily large".

Reproducer recipe

a minimal valid solid plus 30 unreferenced `CARTESIAN_POINT` entities scattered through DATA.

Expected kernel behavior

Heal and accept: parse normally; ignore unreferenced entities; a re-emit pass may normalize / prune; a strict policy emits a warning.

Notes

Common in Pro/E exports of complex parts with sketch history.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'CARTESIAN_POINT') >= 10 or count_entity_def(b'LINE') >= 3 or count_entity_def(b'CIRCLE') >= 3
  • count_entity_def(b'CARTESIAN_POINT') >= 5
