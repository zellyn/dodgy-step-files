Wr024 — NAUO assembly-tree flattened on re-export

§12.13 writer-pathology (sub-class: round-trip data loss)

P1 — silent data loss

round-trip writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr024.stp

Sources

  • OCCT MANTIS#0028xxx assembly round-trip
  • bug-reporter language: "assembly became one part", "STEP lost subassembly structure" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers whose internal assembly model is flat (one-level), forced to flatten multi-level assembly trees on export

Description

The input had a hierarchical assembly: `top → subassembly_A → part_1, part_2; top → subassembly_B → part_3, part_4` represented via `NEXT_ASSEMBLY_USAGE_OCCURRENCE` chains. The re-emitted file flattens to `top → part_1, part_2, part_3, part_4`; semantically wrong, the subassembly grouping is lost. Bug-reporter language: "subassembly structure flattened", "STEP lost assembly hierarchy", "all parts now siblings".

Reproducer recipe

a flat NAUO chain `top → part_1, part_2, part_3, part_4` with comment noting the original had two intermediate subassemblies.

Expected kernel behavior

Heal and accept: preserve NAUO hierarchy depth on round-trip; if the kernel cannot represent multi-level hierarchies internally, document the limitation and warn on input.

Notes

§12.6 covers NAUO defects; Wr024 attributes them to writer.
