Wr023 — Validation properties (volume/area/centroid) dropped on re-export

§12.13 writer-pathology (sub-class: round-trip data loss)

P1 — silent data loss

round-trip writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr023.stp

Sources

  • prostep ivip CAx-IF "validation properties for shape exchange"
  • bug-reporter language: "validation props gone after re-export"

Sender

Writers that compute validation properties on read but do not emit them on write

Description

The input contained `GEOMETRIC_VALIDATION_PROPERTY` entries declaring producer-computed volume, area, and centroid for each solid, intended as a checksum the receiver can use to verify exchange fidelity. The re-emitted file lacks them. The downstream tool can no longer cross-check the round-trip. Bug-reporter language: "validation properties lost", "no volume in re-exported STEP", "checksum gone".

Reproducer recipe

a MANIFOLD_SOLID_BREP fixture with no validation properties, comment indicating input had them.

Expected kernel behavior

recompute and emit validation properties on write, or pass through input properties unchanged with a warning if the kernel cannot verify them.

Notes

prostep ivip CAx-IF Recommended Practice for Validation Properties. Bytes alone are insufficient to demonstrate this defect — needs sibling input fixture. Tagged provenance_tier: requires-sibling-pair.

Expected validation
