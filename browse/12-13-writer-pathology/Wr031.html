Wr031 — Schema downgrade on export (AP242 input emitted as AP203, entities lost)

§12.13 writer-pathology (sub-class: schema downgrade)

P1 — silent data loss

round-trip writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr031.stp

Sources

  • prostep ivip "AP242→AP203 downgrade"
  • bug-reporter language: "STEP file lost PMI on AP203 export"

Sender

Writers configured to emit AP203 because a downstream consumer doesn't speak AP242, with no warning that AP242-specific content (PMI, kinematics, composite materials) is dropped silently

Description

The input declared `FILE_SCHEMA(('AP242_MANAGED_MODEL_BASED_3D_ENGINEERING'))` and contained `GEOMETRIC_TOLERANCE`, `DRAUGHTING_ANNOTATION_OCCURRENCE`, and `KINEMATIC_LINK` entities. The re-emitted file declares `FILE_SCHEMA(('AUTOMOTIVE_DESIGN'))` and contains only the geometry — every AP242-specific entity is gone. Bug-reporter language: "schema downgrade lost data", "AP203 export drops PMI", "STEP went from 242 to 203".

Reproducer recipe

a fixture with `FILE_SCHEMA(('AUTOMOTIVE_DESIGN { 1 0 10303 214 3 1 1 }'))` and only AP203-compatible entities, with a comment noting the input was AP242 with PMI and kinematics.

Expected kernel behavior

Warn and accept: preserve the input schema on round-trip when possible; emit a loud warning on any schema downgrade that drops entities.

Notes

§12.7 covers PMI loss; Wr031 covers the schema-level root cause. Bytes alone are insufficient to demonstrate this defect — needs sibling input fixture. Tagged provenance_tier: requires-sibling-pair.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb"FILE_SCHEMA\(\(\s*'AUTOMOTIVE_DESIGN")
