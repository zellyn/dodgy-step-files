Wr051 — step-g imports cleanly but downstream `g-stl` tessellator silently writes zero triangles

§12.13 writer-pathology (sub-class: importer/tessellator disagreement)

P1 — silent data loss

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr051.stp

Sources

  • BRL-CAD users mailing list 2017 (Filip Binkiewicz reproducer): "ERROR(Brep_2.s): tessellation failure" + "0 triangles written"
  • bug-reporter language: "step-g converts cleanly but g-stl outputs empty file", "BRep imports OK but cannot triangulate", "STEP→.g→.stl pipeline silently produces empty STL".

Sender

STEP files whose features sit at or below the BRL-CAD step-g hard-coded 1e-3 mm tolerance (sliver faces, micro-fillets, sub-tolerance B-spline patches) — the importer treats the geometry as valid but the tessellator's adaptive sampler cannot find sample points satisfying the same hard-coded tolerance.

Description

A STEP file imports cleanly via `step-g` (the resulting .g file contains a `Brep_2.s` solid with face count > 0), but the downstream `g-stl` tessellator prints `ERROR(Brep_2.s): tessellation failure` and writes `0 triangles written` — the resulting `.stl` is empty. The two halves of the BRL-CAD pipeline disagree on whether the model is "good": step-g believes it converted the geometry; g-stl cannot triangulate it. The user-facing symptom is an empty `.stl` with no diagnostic at the file-format interface; the failure happens deep in `PullbackCurve` / `SurfaceTree`. The class of inputs that trigger this is narrow but real: any face whose pcurves and 3D curves agree at vertices but drift to ~1e-3 mm in the interior (because the importer treats 1e-3 as the tolerance, but the tessellator treats anything below 1e-3 as a degeneracy). Distinct from M005 (number-of-facets validation property: facet count, not pipeline disagreement).

Reproducer recipe

STEP `BEZIER_SURFACE` with a 4×4 control net whose v-extent is 3 micrometres (well below step-g's 1e-3 mm tolerance). step-g loads the face; g-stl emits zero triangles.

Expected kernel behavior

reject — the importer and tessellator must agree on a single tolerance value; if a face cannot be tessellated at the importer's tolerance, the importer must reject it at parse time rather than commit a `Brep_2.s` to the .g file. Pipeline diagnostic must surface both the offending face id and the tolerance comparison.

Notes

**See also**: M005, M022, N019, N050. Synonyms: "BRL-CAD step-g imports but g-stl emits empty", "0 triangles written silently", "tessellation failure on sliver face", "importer/tessellator tolerance disagreement", "STEP→.g→.stl produces empty STL no diagnostic".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'BEZIER_SURFACE')
  • contains(b'0.000003') or contains(b'3.E-6') or contains(b'3e-06')
