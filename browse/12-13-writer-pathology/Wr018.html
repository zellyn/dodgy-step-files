Wr018 — Empty `SHAPE_DEFINITION_REPRESENTATION` chain (placeholder structure with no geometry)

§12.13 writer-pathology (sub-class: construction-residue)

P1 — silent data loss

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr018.stp

Sources

  • OCCT MANTIS#0027xxx-class
  • bug-reporter language: "STEP loaded but model is empty" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers that initialise the product structure tree before geometry is computed and forget to suppress empty trees on export when computation fails or is cancelled

Description

The file contains a complete product-structure scaffold (`APPLICATION_CONTEXT`, `PRODUCT`, `PRODUCT_DEFINITION`, `SHAPE_DEFINITION_REPRESENTATION`, `SHAPE_REPRESENTATION`) with all the right cross-references, but the `SHAPE_REPRESENTATION.items` list is empty or contains only placement axes; no `MANIFOLD_SOLID_BREP`, no `SHELL_BASED_SURFACE_MODEL`, no `TESSELLATED_SHELL_REPRESENTATION`. The receiver loads "successfully" but reports zero solids. Bug-reporter language: "STEP file loaded but nothing visible", "empty model", "product tree but no geometry", "ghost STEP file".

Reproducer recipe

full scaffold ending with `SHAPE_REPRESENTATION('main',(#13),#24)` where `#13` is just an `AXIS2_PLACEMENT_3D` and there is no shape.

Expected kernel behavior

Warn and accept: emit a warning that the file describes a product but contains no geometry; do not reject (well-formed empty product is permitted).

Notes

A "successful empty load" is the most confusing failure mode for end users.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb"SHAPE_REPRESENTATION\('[^']*',\(#\d+\),#")

Tier-3 assertions

  • load == "ok"
