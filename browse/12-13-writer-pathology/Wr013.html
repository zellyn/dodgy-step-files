Wr013 — Forward references where sequential numbering was expected

§12.13 writer-pathology (sub-class: instance numbering)

P3 — cosmetic / metadata-only

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr013.stp

Sources

  • OCCT bug "kernel chokes on forward refs"
  • bug-reporter language: "ref to undefined #N", "forward declaration"

Sender

Writers that emit entities in topological-construction order without a topological sort; observed in some open-source exporters

Description

The producer emits `#5 = ORIENTED_EDGE(..,#10,..)` before `#10` has been defined. Spec-conforming readers must do a two-pass parse (or a deferred-resolution mechanism), but a class of single-pass kernels reports "reference to undefined instance #10" and rejects. Bug-reporter language: "forward references in STEP", "ref before def", "kernel doesn't support out-of-order STEP".

Reproducer recipe

`#5 = CARTESIAN_POINT('p',(0.,0.,0.));` followed later by `#1 = AXIS2_PLACEMENT_3D('a',#5,$,$);` — but `#5` appears first; or, more pathologically, `#1 = .. (#5,..);` first, then `#5 = ..;` second (forward).

Expected kernel behavior

implement two-pass parsing or deferred-resolution; the spec permits forward references. Reject only if a reference remains unresolved after the full file is parsed.

Notes
