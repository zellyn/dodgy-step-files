Wr011 — Empty parameter list `()` where the schema requires at least one element

§12.13 writer-pathology (sub-class: optional-parameter abuse)

silent-loss writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr011.stp

Sources

  • OCCT MANTIS#0027xxx-class
  • bug-reporter language: "empty list, expected at least one face" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers that prune the model and forget to suppress now-empty container entities

Description

A `CLOSED_SHELL` entity with an empty face-list `()` appears in the file because the producer pruned all faces but left the shell wrapper. Schema requires the face-list to be non-empty. Some readers reject; some accept and produce a vacuous shell that flows through the rest of the import as an empty solid. Bug-reporter language: "empty shell", "STEP closed_shell with no faces", "writer left a stub entity".

Reproducer recipe

`CLOSED_SHELL('hollow',())` referenced by a `MANIFOLD_SOLID_BREP`.

Expected kernel behavior

reject the empty-shell case as schema-violating; do not silently accept the placeholder.

Notes

Strongly related to Wr020 (empty SHAPE_DEFINITION_REPRESENTATION chains). **OCC behavior**: silently accepts the empty face-list and produces a vacuous shell with no diagnostic; the kernel mishandling is the documented signal here.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'CLOSED_SHELL') and matches(rb"CLOSED_SHELL\('[^']*',\(\)\)")
  • matches(rb'CLOSED_SHELL\([^;]*\(\)\)') or matches(rb',\(\)\s*\)')
