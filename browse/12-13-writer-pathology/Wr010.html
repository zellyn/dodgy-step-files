Wr010 — Re-emitted `*` (overridden) where schema does not allow it

§12.13 writer-pathology (sub-class: optional-parameter abuse)

Sources

  • OCCT forum "writer emitted asterisk in CARTESIAN_POINT coords"
  • bug-reporter language: "asterisk in geometry"

Sender

Buggy writers that mis-handle the inheritance-override mechanism for complex (subtype) entities and apply it to non-inherited attributes

Description

The `*` token denotes an attribute inherited from a supertype and overridden in a subtype context; valid only inside complex (subtype-stack) records. The producer emits `*` in a simple-entity instance where no supertype exists, producing `CARTESIAN_POINT('p',(*,0.0,0.0))` or similar. Receivers diverge: some treat `*` as an error, some treat it as zero, some treat it as `$`. Bug-reporter language: "asterisk where number expected", "STEP file has stars in coordinates", "writer used override-marker incorrectly".

Reproducer recipe

`CARTESIAN_POINT('p',(*,0.0,0.0))` in a non-subtype context.

Expected kernel behavior

reject as malformed; `*` is meaningful only in complex-instance subtype-override position.

Notes

ISO 10303-21 §10 defines `*` semantics narrowly. Provenance tier: writer-side (Q5 full-corpus 2026-07-01).
