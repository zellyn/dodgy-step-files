Wr027 — Unit context emitted twice with different units (HEADER vs DATA mismatch)

Sources

  • OCCT MANTIS#0029xxx-class "unit mismatch in HEADER vs DATA"
  • bug-reporter language: "STEP file has two different units" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers where the HEADER is composed by a templating subsystem and the DATA-section unit context is emitted by a separate geometry serialiser, with no cross-check

Description

`FILE_NAME` or `FILE_DESCRIPTION` lists `'mm'` as the unit (informally, in the description string), while the DATA-section `LENGTH_UNIT` resolves to `INCH` (or vice versa). The geometry is correct in DATA-section units; the HEADER claim is decorative but misleading. Bug-reporter language: "header says mm, geometry is inches", "STEP file has two different units", "unit declaration contradicts geometry".

Reproducer recipe

`FILE_DESCRIPTION(('part in mm'),'2;1')` paired with a `LENGTH_UNIT` resolving to `INCH` (`#20=(LENGTH_UNIT() NAMED_UNIT(*) CONVERSION_BASED_UNIT('INCH',#21))`).

Expected kernel behavior

Warn and accept: normalize by trusting the DATA-section unit context (the schema-meaningful one) and treat HEADER prose as informational. Emit a warning on mismatch.

Notes

§12.5 covers unit defects; Wr027 documents producer-side root cause.
