Wr003 — Final `END-ISO-10303-21;` without trailing newline

Sender

Older Siemens NX export and several in-house writers

Description

The closing `END-ISO-10303-21;` token is emitted without a trailing newline. The spec does not require one (it requires only the closing marker), so the file is well-formed. But concatenation of two such files produces `END-ISO-10303-21;ISO-10303-21;` on a single line, which trips a class of crude scripts that grep for `^ISO-10303-21;`. Bug-reporter language: "can't concat two STEPs", "POSIX text-file rule violated", "no newline at end of file".

Reproducer recipe

Part-21 file ending with the bytes `END-ISO-10303-21;` and no `0x0A` after.

Expected kernel behavior

Heal and accept: parsers normalize / accept this form (the spec permits it); downstream tooling that concatenates files adds its own separator.

Notes

A POSIX-text-file convention (text files end with newline) but not a Part-21 requirement. Provenance tier: writer-side (Q5 full-corpus 2026-07-01).
