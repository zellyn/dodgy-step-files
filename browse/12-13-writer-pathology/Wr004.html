Wr004 — Tab characters used for line continuation indentation inconsistently

§12.13 writer-pathology (sub-class: whitespace/line-ending)

P3 — cosmetic / metadata-only

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr004.stp

Sources

  • KiCad MCAD exporter issue tracker
  • bug-reporter language: "diff is unreadable"

Sender

KiCad PCB-to-STEP exporter and a few homegrown writers

Description

Continuation lines for long records mix TAB (0x09) and SPACE (0x20) for indentation, or use TAB for some continuations and 2-SPACE for others within the same file. Parsers don't care; humans diffing or reviewing exports do. Bug-reporter language: "tabs and spaces mixed", "indentation inconsistent", "looks bad in editor".

Reproducer recipe

a long argument list where some continuation lines start with a TAB and others start with two SPACEs.

Expected kernel behavior

Heal and accept: normalize by ignoring the whitespace.

Notes

Cosmetic only, but reviewer-fatiguing.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'\n\t') and matches(rb'\n ')
  • contains(b'\t')
