Wr008 — Excessive trailing zeros in numeric output

§12.13 writer-pathology (sub-class: numeric formatting)

P3 — cosmetic / metadata-only

writer

View raw fixture (.stp) step-examples/12-13-writer-pathology/Wr008.stp

Sources

  • prostep ivip "exchange file size grew 3× without geometry change"
  • bug-reporter language: "STEP file is huge for what it contains"

Sender

Writers using `printf("%.20f", ..)` or `printf("%.17g", ..)` indiscriminately on every coordinate

Description

Every numeric coordinate is emitted with 17 or more decimal digits, padded with trailing zeros where the underlying value has fewer significant digits (`1.0` is emitted as `1.00000000000000000`). The file inflates 2-3× over what minimal-form output would produce. Spec-conforming, but bandwidth- and storage-hostile. Bug-reporter language: "STEP file unnecessarily huge", "20 digits for every zero", "compresses 95%".

Reproducer recipe

CARTESIAN_POINTs with coordinates such as `(1.00000000000000000,2.50000000000000000,0.00000000000000000)`.

Expected kernel behavior

Heal and accept: parse normally; a re-emit policy may normalize / shorten to minimal round-trip-safe form (`%.17g` shortened to the smallest digit-count that round-trips).

Notes

Cousin of Wr006 from the opposite direction.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'\d\.0{15,}')
  • matches(rb'\.0{14,}')
