Wr030 — `FILE_SCHEMA` listing schemas the file does not actually use

§12.13 writer-pathology (sub-class: header / vendor metadata)

P2 — spec deviation (no data loss)

Sources

  • OCCT MANTIS#0029xxx-class
  • bug-reporter language: "STEP claims AP242 but uses AP203 only" (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Writers that hard-code a schema list rather than computing the minimal set actually referenced

Description

`FILE_SCHEMA(('AUTOMOTIVE_DESIGN','CONFIG_CONTROL_DESIGN','AP242_MANAGED_MODEL_BASED_3D_ENGINEERING'))`; three schemas declared, but the DATA section uses only AP203 entities. The receiver may load the file under whichever schema it understands, and any AP242-specific validation passes vacuously because the AP242 entities aren't there. Bug-reporter language: "STEP claims multiple schemas", "FILE_SCHEMA over-declared", "AP242 listed but not used".

Reproducer recipe

standard AP203 entity body with `FILE_SCHEMA(('AUTOMOTIVE_DESIGN { 1 0 10303 214 3 1 1 }','AP242_MANAGED_MODEL_BASED_3D_ENGINEERING'))`.

Expected kernel behavior

Warn and accept: normalize / validate against any one of the declared schemas under which the DATA-section entities are well-formed; emit a warning on over-declaration.

Notes

Cousin of Wr031 in the opposite direction.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • matches(rb"FILE_SCHEMA\(\(\s*'[^']+'\s*,\s*'[^']+'")
  • count(b"','") >= 2
