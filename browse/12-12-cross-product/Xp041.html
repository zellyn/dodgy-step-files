Xp041 — IfcOpenShell rejects valid IFC4X1 file due to lowercase 'x' in schema name

§12.12 cross-product (header × receiver case-sensitivity)

P1 — silent data loss

Sources

  • github.com/IfcOpenShell/IfcOpenShell issue #1311 "Bug report: fail at parsing IFC4x1 standard files"
  • bug-reporter language: "ifcopenshell rejects my IFC4x1 file", "the file is valid but the parser refuses it because of the lowercase x".

Sender

IFC writers (some that emit lowercase 'x') / equivalently any STEP writer using a non-canonical case in FILE_SCHEMA

Description

FILE_SCHEMA carries 'IFC4x1' (lowercase x). ISO 10303-21 doesn't constrain the case of trailing characters in schema names; ISO 10303-11 schema identifiers are conventionally uppercase but real-world IFC writers have shipped both cases. A strict equality check against an uppercase-only allowlist rejects the file before any parsing of the data section.

Reproducer recipe

FILE_SCHEMA(('IFC4x1')); minimal IFC data section with IFCPROJECT, IFCGEOMETRICREPRESENTATIONCONTEXT, IFCAXIS2PLACEMENT3D, IFCCARTESIANPOINT.

Expected kernel behavior

case-insensitive schema-name matching; or at minimum, accept both 'IFC4x1' and 'IFC4X1' as aliases. Strict-mode kernels should reject with a clear "schema name case mismatch" diagnostic naming the expected canonical form.

Notes

Synonyms: "IFC4x1 lowercase x rejected", "schema name case-sensitive parser bug", "IfcOpenShell strict whitelist reject", "FILE_SCHEMA case mismatch", "valid file rejected by uppercase-only check".
