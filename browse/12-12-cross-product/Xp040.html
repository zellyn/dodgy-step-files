Xp040 — Solid Edge import of Creo Elements STEP: "stuck" sub-assemblies

§12.12 cross-product (assembly × receiver UI)

Sources

  • community.plm.automation.siemens.com Solid Edge 274875 "STEP FILE ASSEMBLY ISSUES"
  • community.sw.siemens.com 0xgTFSAY "Inserted part into assembly is placed way far from origin or other parts"
  • bug-reporter language: "the sub-assemblies are stuck", "I can see the parts but I can't move them".

Sender

Creo Elements (legacy ProE) STEP writer

Description

Two NEXT_ASSEMBLY_USAGE_OCCURRENCEs reference the same shared ITEM_DEFINED_TRANSFORMATION. Solid Edge displays both children but disables UI manipulation because no per-instance frame exists; the user perceives "stuck" sub-assemblies that cannot be selected, moved, or constrained. The defect class is loss of per-instance assembly identity through transformation aliasing.

Reproducer recipe

top-level PRODUCT_DEFINITION; two child PRODUCTs SubA and SubB; both NAUOs reference the SAME ITEM_DEFINED_TRANSFORMATION; both SHAPE_REPRESENTATIONs share the same AXIS2_PLACEMENT_3D.

Expected kernel behavior

Heal and accept: receivers must materialise per-instance frames even when the source uses a shared IDT; warn and accept with a "shared transformation across NAUOs" diagnostic so users know why move/constrain is disabled. Accepting shared-IDT inputs that freeze the UI without explanation is a coverage gap; never crash, never hang.

Notes

**See also**: Xp025. Synonyms: "Solid Edge stuck subassembly", "shared IDT across NAUOs", "Creo Elements assembly placements aliased", "subassembly cannot be moved after import", "per-instance frame missing".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'ITEM_DEFINED_TRANSFORMATION')
