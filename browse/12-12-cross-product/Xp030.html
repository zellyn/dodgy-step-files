Xp030 — Inventor exports Asian (CJK) characters as raw legacy-codepage bytes

§12.12 cross-product (encoding × writer)

P1 — silent data loss

interop

Sources

  • Autodesk KB sfdcarticles "STEP files converted in Inventor, do not display Chinese characters as expected"
  • Inventor forum 6686585 "How can I get Inventor to correctly translate Chinese Character"
  • bug-reporter language: "Chinese names show as gibberish", "Korean characters became a jumbled mess".

Sender

Autodesk Inventor (some localisations) when source uses CJK names

Description

Inventor's STEP writer encodes string literals (PRODUCT.name, PERSON, etc.) using the Windows default codepage (GBK / Shift_JIS / EUC-KR) instead of the ISO 10303-21 \\X2\\ escape mechanism for codepoints outside ASCII. The bytes are syntactically valid (not high-bit characters in apostrophe / control runs), but they decode to mojibake on receivers that interpret the file as ISO-8859-1 (Edition 2 default) or UTF-8 (Edition 3 default).

Reproducer recipe

PRODUCT.name carries raw multi-byte legacy-codepage content (e.g. byte sequence representing GBK 0xD6 0xD0 mis-recoded through Latin-1→UTF-8); intended Chinese characters '中文' should have been encoded as `\\X2\\4E2D6587\\X0\\`.

Expected kernel behavior

writers must emit \\X2\\HHHH\\X0\\ for any codepoint outside ASCII regardless of host OS locale; receivers that find raw high-bit runs should warn and apply edition-default decoding (UTF-8 / ISO-8859-1) without crashing.

Notes

**See also**: Le002, Le021. Synonyms: "Chinese characters mojibake in STEP", "Inventor writes raw GBK bytes", "Korean names garbled after STEP round-trip", "CJK PRODUCT.name corrupt", "non-ASCII writer ignores X2 escape".
