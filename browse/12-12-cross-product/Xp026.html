Xp026 — Fusion 360 AP242 export rejected by NX 12 (no AP242 import)

§12.12 cross-product (schema version × receiver compatibility)

P1 — silent data loss

interop

View raw fixture (.stp) step-examples/12-12-cross-product/Xp026.stp

Sources

  • Autodesk KB sfdcarticles "STEP files exported from Fusion do not import in NX12 software"
  • forum.onshape.com discussion 22915 "Importing STEP files from Fusion 360"
  • bug-reporter language: "NX 12 just refuses the file", "Fusion exports a STEP my colleagues can't open".

Sender

Fusion 360 STEP exporter (default AP242 since ~2022)

Description

Fusion 360 emits a STEP file with FILE_SCHEMA naming AP242 only. Receivers built for AP203/AP214 reject the file by schema name without parsing the data section. There is no fallback schema declaration in FILE_SCHEMA's aggregate. The fix in source applications is to switch the export to AP203 / AP214; the catalog records the reverse-direction defect of writers that emit AP242 by default with no compatibility alternative.

Reproducer recipe

FILE_SCHEMA(('AP242_MANAGED_MODEL_BASED_3D_ENGINEERING_MIM_LF { 1 0 10303 442 1 4 4 }')) with no AP203 or AP214 alternate listed in the schema aggregate; trivial DATA section with one ADVANCED_FACE.

Expected kernel behavior

receivers should ideally schema-fold AP242→AP214 for the geometry subset they recognise, surfacing a "schema downgrade applied" warning. Writers should emit FILE_SCHEMA with both AP242 and AP214 when the data is geometrically expressible in both.

Notes

Synonyms: "Fusion STEP not opening in NX 12", "AP242 file too new for legacy CAD", "schema header rejects file before parsing", "no AP203/AP214 fallback in FILE_SCHEMA", "AP242 only schema causes import failure".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'AP242_MANAGED_MODEL_BASED_3D_ENGINEERING_MIM_LF')
