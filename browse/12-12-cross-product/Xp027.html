Xp027 — Inventor STEP import "stuck at 95%" — long path in FILE_NAME author field

§12.12 cross-product (header parsing × receiver path-buffer)

P1 — silent data loss

interop

View raw fixture (.stp) step-examples/12-12-cross-product/Xp027.stp

Sources

  • Autodesk KB sfdcarticles "A STEP file that gets stuck at 95 percent when attempting to import into Inventor"
  • Inventor forum 10165651 "STEP File import stuck at 95%"
  • bug-reporter language: "import hangs at 95 percent forever", "moving the file to C:\\Temp fixed it".

Sender

any STEP writer that puts the full source path in a FILE_NAME header field

Description

ISO 10303-21 §6.2 lets FILE_NAME's third argument hold the author list with no per-element length bound. Some writers (or pre-processing utilities) populate it (or a sibling header field) with the full source disk path — a UNC \\\\server\\share\\very\\long\\path; receivers that pre-allocate MAX_PATH=260 buffers for header parsing hang on the long string or repeatedly re-walk it during progress-bar updates, leading to the "stuck at 95%" symptom.

Reproducer recipe

FILE_NAME third arg is an author list whose only element is a UNC path 350+ characters long (e.g. \\\\\\\\corp.example.com\\\\engineering\\\\projects\\\\..); rest of header standard; trivial DATA section.

Expected kernel behavior

cap the FILE_NAME first-arg length in the parser (treat as an opaque label, not a path); never hand it to the OS path-resolution APIs; emit warning W_LONG_HEADER_FIELD if length exceeds 1024.

Notes

Synonyms: "STEP import stuck at 95 percent", "Inventor hangs on long file path", "FILE_NAME UNC path makes parser stall", "import progress bar hangs at end", "long path in STEP header".
