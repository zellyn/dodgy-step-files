Xp044 — KiCad PCB STEP export: missing components / wrong MAPPED_ITEM target

Sender

KiCad PcbNew STEP writer (3D model attachment pipeline)

Description

Two distinct defect modes in one fixture: (1) Component A's SHAPE_REPRESENTATION has an empty items list (zero geometry attached) — the footprint is "missing" on receive; (2) Component B's MAPPED_ITEM references the wrong REPRESENTATION_MAP target — TO-220 ends up rendering a TO-252 pin. Both arise from the writer's component-to-3D-model lookup pipeline failing to resolve attachments, with the MAPPED_ITEM still emitted but pointed at whatever happened to be in the lookup cache.

Reproducer recipe

PRODUCT 'R0805' bound to SHAPE_REPRESENTATION with empty items; PRODUCT 'TO-220' bound to MAPPED_ITEM whose REPRESENTATION_MAP target is the SHAPE_REPRESENTATION named 'TO-252_pin_should_be_TO-220'.

Expected kernel behavior

receivers should warn on empty SHAPE_REPRESENTATION items lists ("component has no geometry"); validate MAPPED_ITEM target consistency (the target's name should match the source PRODUCT's name or carry an explicit mapping_origin); never silently render the wrong geometry.

Notes

**See also**: Xp031 (KiCad name-collision). Synonyms: "KiCad PCB STEP missing components", "MAPPED_ITEM wrong target", "footprint imports as different package", "empty SHAPE_REPRESENTATION items", "STEP component swap on export".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • contains(b'MAPPED_ITEM')
  • contains(b'REPRESENTATION_MAP')
