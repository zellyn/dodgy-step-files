Xp001 — Malformed `\X2\` escape in PRODUCT.name AND self-intersecting wire

Description

A `PRODUCT.name` literal contains a `\X2\` escape with three hex digits and no closing `\X0\` — the encoding sub-grammar is violated. In the same file, an `ADVANCED_FACE`'s outer wire crosses itself in 3D — the topological-simplicity invariant is violated. Both pathologies must be resolved before the file is usable: a kernel that repairs encoding but assumes geometry validity (or vice versa) will produce a partial result.

Reproducer recipe

`PRODUCT('part-\X2\30A2 30A4','desc',..)` (no `\X0\`, three trailing hex digits in second group). The DATA section carries one planar `ADVANCED_FACE` whose `EDGE_LOOP` contains four `ORIENTED_EDGE`s tracing a figure-eight in the XY plane (two diagonals cross at the origin).

Expected kernel behavior

Two independent invariants must hold — the string literal must be either decoded successfully or rejected with a diagnostic; the wire must be either resolved into a simple boundary or rejected. The order of resolution is the kernel's choice; the corpus expects each to be addressed independently.
