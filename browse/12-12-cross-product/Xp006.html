Xp006 — Schema-mismatch × forward-reference × unresolved entity

§12.12 cross-product (header × syntax × references)

Description

`FILE_SCHEMA` declares `CONFIG_CONTROL_DESIGN { 1 0 10303 203 1 1 1 1 }` (AP203). The DATA section contains AP242-only entities (`TESSELLATED_FACE`, `COMPLEX_TRIANGULATED_ SURFACE_SET`). One `ADVANCED_FACE` references `#999` for its `face_geometry` — but `#999` is never defined in the file (forward reference that never resolves). All three are independent failures of the reference-/schema-consistency invariant.

Reproducer recipe

AP203 schema in header; DATA contains a `TRIANGULATED_FACE`, an `ADVANCED_FACE` whose `face_geometry` slot is `#999`, and no `#999` definition. Other entities resolve normally.

Expected kernel behavior

schema/entity-set mismatch detected and resolved (load anyway, reject, warn); unresolved `#999` flagged or the containing face dropped.

Notes

Cross-oracle: pure-Python Part-21 validator rejects (reject(E_UNRESOLVED_REFS)); OCCT silently accepts (load is `empty`). OCC auto-heals a spec-level violation.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

  • contains(b'EDGE_CURVE')
  • contains(b'ADVANCED_FACE')
