Description

The file has two `DATA` sections. Both define `#10` (with different bodies). One section references `@otherSection#10` (cross- section reference syntax). The behavior under the spec is ambiguous — multi-DATA is permitted in Edition 3 with explicit naming, but anonymous DATA blocks are not, and duplicated IDs across blocks must be resolved.

Reproducer recipe

two `DATA;`/`ENDSEC;` blocks, both defining `#10`, with one entity citing `@s2#10`.

Expected kernel behavior

Heal and accept, or reject with E_DUPLICATE_ID / E_BAD_CROSS_REF diagnostic: multi-DATA policy normalizes the section choice, duplicate-ID resolution coerces / repairs IDs, cross-section-ref handling resolves references. Each independent.
