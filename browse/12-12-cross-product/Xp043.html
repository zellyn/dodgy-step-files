Xp043 — CATIA AP242 → Inventor: top-level PRODUCT_DEFINITION without SDR

§12.12 cross-product (assembly graph × receiver strictness)

P1 — silent data loss

spec-violation interop

View raw fixture (.stp) step-examples/12-12-cross-product/Xp043.stp

Sources

  • forums.autodesk.com inventor 10994597 "STEP import fails for AP242 from PTC Creo"
  • bug-reporter language: "Inventor refuses the file as structurally invalid", "the children import fine alone but the assembly fails".

Sender

CATIA / Creo AP242 writer for empty top-level assemblies

Description

The top-level PRODUCT_DEFINITION exists but no SHAPE_DEFINITION_REPRESENTATION binds it to a SHAPE_REPRESENTATION. Child PRODUCT_DEFINITIONs each have their own SDR. Some receivers (FreeCAD, Onshape) infer the missing top-level binding from the child graph; Inventor's reader treats it as structurally invalid and aborts the entire import even though the children are fine.

Reproducer recipe

top-level PRODUCT_DEFINITION with no SHAPE_DEFINITION_REPRESENTATION pointing to it; one child PRODUCT_DEFINITION with a proper SDR / SHAPE_REPRESENTATION / AXIS2_PLACEMENT_3D / GEOMETRIC_REPRESENTATION_CONTEXT.

Expected kernel behavior

when the top-level PRODUCT has no SDR but children do, infer a default top-level SHAPE_REPRESENTATION wrapping the children and emit a warning; do not abort the import. Strict-mode kernels should reject with "top-level PRODUCT_DEFINITION has no SHAPE_DEFINITION_REPRESENTATION".

Notes

**See also**: A065. Synonyms: "missing root SDR", "PRODUCT_DEFINITION not bound to SHAPE_REPRESENTATION", "Inventor rejects empty top-level assembly", "AP242 from CATIA structurally invalid", "import aborts on missing SDR".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'PRODUCT_DEFINITION')
  • contains(b'SHAPE_DEFINITION_REPRESENTATION')
