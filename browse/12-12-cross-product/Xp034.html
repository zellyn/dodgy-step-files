Xp034 — CadQuery RGB shifted by sRGB→linear conversion on STEP export

§12.12 cross-product (appearance × writer colour space)

round-trip interop

Sources

  • github.com/CadQuery/cadquery issue #794 "Assembly Color Component Values in Exported STEP File Are Shifted"
  • bug-reporter language: "I asked for (0.5, 0.5, 0.5) but the STEP file has (0.7353, 0.7353, 0.7353)", "colours look brighter after STEP export".

Sender

CadQuery STEP writer (uses OCC's STEPCAFControl_Writer)

Description

ISO 10303-46 nominally treats COLOUR_RGB values as linear-space [0.1] floats. The writer applies an sRGB-companding step before emission, producing values that look correct in sRGB-aware viewers but appear over-bright in linear-space-aware kernels. A user input of (0.5, 0.5, 0.5) becomes 0.7353569830523 (= sRGB(0.5)). Round-trip with mismatched receivers progressively brightens.

Reproducer recipe

COLOUR_RGB('grey_should_be_0p5', 0.7353569830523, 0.7353569830523, 0.7353569830523); bind to a face via PRESENTATION_STYLE_ASSIGNMENT and STYLED_ITEM.

Expected kernel behavior

Warn and accept: kernels should document their colour-space convention and emit a warning when COLOUR_RGB values cluster around sRGB-companded gray values that don't round-trip cleanly. Writers should heal by emitting in linear space. Treating companded values as linear without diagnostic is a coverage gap.

Notes

Synonyms: "STEP colors brighter after CadQuery export", "RGB sRGB linear conversion bug", "colour values shifted on round-trip", "0.5 grey becomes 0.735", "gamma applied twice on STEP export".
