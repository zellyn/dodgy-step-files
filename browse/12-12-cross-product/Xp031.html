Xp031 — KiCad STEP imports cleanly in FreeCAD but corrupts in SolidWorks (PRODUCT.name de-dup)

§12.12 cross-product (assembly identity × receiver heuristic)

Sources

  • forum.kicad.info t/47681 "Wrong parts assignment when opening STEP files in Solidworks 2021"
  • t/46359 "STEP file corrupting on import to Solidworks (but not freecad)"
  • bug-reporter language: "in Solidworks several components were rotated and replaced by other components", "FreeCAD opens it fine but Solidworks scrambles the parts".

Sender

KiCad PcbNew STEP exporter

Description

Two distinct PRODUCT_DEFINITIONs share the same PRODUCT.name (e.g. both labelled 'R0805', a common PCB resistor footprint). FreeCAD treats them as separate instances using the IDT (instance frame) for de-duplication; SolidWorks de-dups by PRODUCT.name and re-uses the first occurrence's geometry for all instances, effectively swapping parts between slots. Round-trip leaves the assembly visually scrambled.

Reproducer recipe

two PRODUCT entities both named 'R0805' but with distinct PRODUCT_DEFINITION_FORMATIONs and PRODUCT_DEFINITIONs; same PRODUCT_CONTEXT for both; ADVANCED_FACE shared (worsening the swap).

Expected kernel behavior

Heal and accept: receivers must de-dup by PRODUCT_DEFINITION identity (entity reference), not by PRODUCT.name string equality. Writers should heal by emitting unique PRODUCT.names where possible, but receivers cannot rely on that. Name-keyed conflations that swap parts between assembly slots are a coverage gap.

Notes

Synonyms: "duplicate PRODUCT name swaps parts", "Solidworks scrambles KiCad STEP imports", "same-name components conflate", "PRODUCT identity by name not entity", "PCB STEP imports wrong components".
