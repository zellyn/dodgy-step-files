Pf001 — Multi-GB Creo AP242 assemblies trigger unbounded receiver memory

§12.10 (sub-class: file-size / OOM)

Sender

PTC Creo (large 1+ GB AP242 assemblies)

Description

STEP files exceeding 1 GB cause downstream consumers (Inventor, AutoCAD, Navisworks) to allocate memory unboundedly until OOM even on hosts with 96 GB RAM. The producing kernel re-imports the same file successfully, so the file is not corrupt — the receiver simply cannot scale.

Reproducer recipe

AP242 STEP with thousands of `MANIFOLD_SOLID_BREP`s in nested `NEXT_ASSEMBLY_USAGE_OCCURRENCE` chains, total size > 1 GB.

Expected kernel behavior

streaming/lazy reader with bounded peak memory; partial-load via configurable `max_instances`; abort with `E_INSTANCE_LIMIT` rather than thrash.

Notes

PTC community thread documents the symptom; Mantis 32127 / **See also**: Pf013, Pf017.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'CARTESIAN_POINT') >= 1
  • contains(b'NEXT_ASSEMBLY_USAGE_OCCURRENCE')
  • contains(b'MANIFOLD_SOLID_BREP')
