Sources

  • occt-coverage `exchange/problems.json` `stp-ideas-shell-closing` (`STEPControl_ActorRead::computeIDEASClosings`, `STEPControl_ActorRead.cxx:2064-2086`
  • `STEPControl_ActorRead::closeIDEASShell`, `:1997-2055`). Root cause of the class's long-standing "merge never fires" finding identified live and read from OCCT source at `bd2a789f15235755ce4d1a3b07379a2e062fdc2e`: `StepToTopoDS_NMTool::IsPureNMShell` (`StepToTopoDS_NMTool.cxx:183-194`) requires every edge of a candidate closing shell to have been passed to `RegisterNMEdge`, and `RegisterNMEdge` has exactly ONE call site — `StepToTopoDS_TranslateEdge.cxx:244`, inside the branch at `:237-249` that fires only when an `EDGE_CURVE`'s own NAME is non-empty and a DIFFERENT, already-translated `EDGE_CURVE` was bound under that same name (`:336-337`). Reusing the same `EDGE_CURVE` entity in both shells short-circuits at `:208` / `:223` and registers nothing. Additionally `STEPControl_ActorRead.cxx:1015-1024`: a representation that yields exactly one shape binds that per-item shape directly and discards the compound the closing and solid-reconstruction passes wrote into.

Description

An I-DEAS-authored file represents one closed solid boundary as several separate OPEN shells: a "main" open shell plus extra shells made entirely of shared edges that exist only to close the gap. This fixture supplies that pattern in the encoding the receiver can actually act on. A unit cube's bottom and four sides form `main_open_shell` (5 faces, genuinely open — no lid); the lid forms `closing_shell` (1 face) whose four boundary edges are four NEW `EDGE_CURVE` records whose names `e_lid_1`..`e_lid_4` are byte-equal to the four top edges already used by the side faces. Separate edge records matched by name is the real I-DEAS authoring shape — and the only one that marks the closing shell's edges as shared, which is the precondition for it to be treated as a closing candidate. Lh031 supplies only the header trigger (no shell topology at all); Lh053 supplies real open+closing topology but reuses the same `EDGE_CURVE` entities, which is exactly why no merge was ever observed for it. A second, unrelated representation item is also required: with a single item the merge runs but its result is discarded before binding.

Reproducer recipe

`FILE_NAME('Lh054.stp',...,'I-DEAS Master Series 11','','');`. Unit cube, consistently outward-oriented. `OPEN_SHELL('main_open_shell',(#bottom,#front,#right,#back,#left))`; four new `EDGE_CURVE('e_lid_1',...)`..`('e_lid_4',...)` duplicating the names (not the entity ids) of the side faces' top edges; `ADVANCED_FACE('top_closing',...)` on those four; `OPEN_SHELL('closing_shell',(#top_closing))`; `SHELL_BASED_SURFACE_MODEL('ideas_shells',(#main_open_shell,#closing_shell))`. Second item: one open square face → `OPEN_SHELL('second_item_shell',...)` → `SHELL_BASED_SURFACE_MODEL('second_item_model',...)`. Both models listed as the two items of one `MANIFOLD_SURFACE_SHAPE_REPRESENTATION`.

Expected kernel behavior

with non-manifold reading and I-DEAS post-processing enabled, recognise the lid shell as a closing candidate for the open shell, merge its face in, confirm the merged shell is closed, prune any closing face not needed for closure, and promote the now-closed shell to a solid — leaving unrelated open shells untouched.

Notes

**See also**: Lh031 (header-only trigger), Lh053 (real topology in the same-entity encoding that cannot fire — this entry is its working counterpart, not a duplicate), Tsh258 (documents the same single-item binding shortcut for shell-to-solid promotion). Live-verified (2026-07-31, this worktree, OCP/OCCT 7.8.1). Under this corpus's default oracle settings the file reads verbatim — 7 faces, 3 shells, 0 solids, 20 unique edges, brepcheck valid — because the whole pipeline is gated behind two opt-in reader parameters. Driving `read.step.nonmanifold=1` AND `read.step.ideas=1` (BOTH required; either alone leaves the result unchanged) the merge is directly observed: 1 SOLID appears, the unique-edge count drops 20 → 16 as the lid's four name-matched edges resolve to the main shell's own edges, and the shell count drops 3 → 2 (the merged, now-closed cube shell inside the solid, plus the second item's untouched open shell); brepcheck stays valid. Perturbation control (byte-level A/B): repointing the lid face's four `ORIENTED_EDGE`s at the main shell's own `EDGE_CURVE` entities — four reference numbers changed, Lh053's encoding, nothing else touched — gives 0 solids and 3 shells under those same parameters. **Reader-configuration finding, recorded because it invalidates earlier negative results for this class**: setting these two parameters through `Interface_Static` alone does NOT reach the transfer in this OCP build; they must be carried in a `StepData_ConfParameters` handed to `ReadFile(path, params)`. Verified independently by a control on an unrelated fixture whose behaviour changes only under the parameters-object route. Synonyms: "I-DEAS closing shell merged", "open shell closed by adjacent non-manifold shell", "closing face pruned after closure", "same edge name different edge record", "I-DEAS non-manifold post processing". Provenance tier: bytes-sufficient.
