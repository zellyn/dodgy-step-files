Lh044 — Cross-section reference resolves through chain (`@s1#10` defined as `@s2#20`)

§12.1b header/numbering (sub-class: multi-section)

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh044.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §7 (named DATA sections, cross-section reference syntax)

Description

Edition-3 named DATA sections allow a cross-section reference `@section#NNN`. A producer that organises its model into a foundation section plus a derived section can emit `@derived#10` whose definition is itself `@foundation#20`. A receiver that does not eagerly resolve transitive cross-section references either presents the user with the indirection-handle (a placeholder pointing at another reference) or short-circuits and skips the indirection. The two outcomes diverge geometrically. Bug-reporter language: "cross-section ref through another ref", "STEP file has chained cross-section pointers".

Reproducer recipe

DATA section `'foundation'` defines `#20=CARTESIAN_POINT('origin',(0.0,0.0,0.0))`; DATA section `'derived'` defines `#10=@foundation#20`; an `AXIS2_PLACEMENT_3D` in a third section `'topology'` references `@derived#10`.

Expected kernel behavior

Heal and accept: resolve transitive cross-section references to their concrete instance before geometry uses them; or, if a placeholder model is preferred, document the deferred-resolution policy and warn-and-accept when the chain is followed.

Notes

**See also**: Lh033, Lh039. Synonyms: "chained cross-section reference", "@s1#10 resolves to @s2#20", "transitive @section reference", "STEP cross-section chain", "multi-hop named-section reference".

Expected validation

  • contains(b"DATA('foundation'") and contains(b"DATA('derived'") and contains(b'@derived#') and contains(b'@foundation#')
  • count(b'@') >= 2
