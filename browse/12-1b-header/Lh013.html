Lh013 — Non-deterministic / build-time timestamp pollution

§12.1b header/numbering

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh013.stp

Sources

  • 18-other-issues I069

Sender

build123d export_step (also CadQuery #1396)

Description

Producer pulls the FILE_NAME timestamp from the system clock rather than honoring a user-supplied datetime. Breaks reproducible builds (e.g. AUR packagers, CI artefact comparisons, downstream LibrePCB content hashes).

Reproducer recipe

`export_step(b, "box.step", timestamp=t)` and confirm FILE_NAME's timestamp matches `t`.

Expected kernel behavior

Heal and accept: writer must honor an explicit timestamp parameter when given; default to current time only when absent.

Notes

Producer-side defect, but the resulting headers are a recognizable wild-corpus class. **See also**: Lh011. Provenance tier: runtime-only; bytes alone cannot demonstrate non-determinism; the defect is that the timestamp was generated from the system clock rather than a user-supplied parameter. Demonstrating this requires comparing two writer invocations (or a writer-with-explicit-timestamp behavioral test), not a static file. Synonyms: "non-deterministic STEP build timestamp", "system-clock timestamp pollutes FILE_NAME", "reproducible build broken by STEP timestamp", "different timestamps each export", "CI artefact differs only by STEP date".
