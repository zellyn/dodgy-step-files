Lh029 — Schema name in FILE_SCHEMA has whitespace, comments, or vendor extensions inside the list

§12.1b header/numbering

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh029.stp

Sources

  • 11-translator-vendors W047

Sender

CAD Exchanger CHANGES v3.24.8 ("improved parsing of FILE_SCHEMA headers")

Description

Multi-schema FILE_SCHEMA with embedded comments inside the schema-name list (`FILE_SCHEMA(('CONFIG_CONTROL_DESIGN' /* legacy */, 'AUTOMOTIVE_DESIGN'))`) or with vendor-specific extensions confuses naive header parsers.

Reproducer recipe

`FILE_SCHEMA(('CONFIG_CONTROL_DESIGN' /* legacy */, 'AUTOMOTIVE_DESIGN'));`

Expected kernel behavior

Heal and accept: parse FILE_SCHEMA via the same robust string-literal tokenizer as DATA; choose the most-capable supported schema; never fall back to byte-level regex on the raw header.

Notes

Synonyms: "comment inside FILE_SCHEMA list", "vendor extension in schema name list", "whitespace in FILE_SCHEMA element", "FILE_SCHEMA with embedded comment", "schema-name list malformed".

Expected validation

occt=reject/reject gmsh=reject ifc=reject

Byte assertions

  • matches(rb"FILE_SCHEMA\([^;]*/\*[^;]*\*/")
  • contains(b'/* legacy */') or contains(b'/* ')

Tier-3 assertions

  • shape_null == True
