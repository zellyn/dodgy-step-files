Lh019 — FILE_SCHEMA names a schema that disagrees with entity types in DATA

§12.1b header/numbering

P1 — silent data loss

syntax

Description

HEADER claims one schema (e.g. `IFC4`, `AUTOMOTIVE_DESIGN`/AP214, `AP242_…` Ed.2) but DATA uses entity names that exist only in another schema or another edition (e.g. `IFC2X3_PROJECT` in an IFC4 file; `ROUND_HOLE` in an AP214 file; post-Ed.3 hole-feature entities under an Ed.2 header).

Reproducer recipe

`FILE_SCHEMA(('IFC4'));` with body `#1=IFC2X3_PROJECT(..);` — or hand-edit FILE_SCHEMA of an Ed.3 file to claim Ed.2.

Expected kernel behavior

reject with a diagnostic naming the offending entity-name vs. claimed schema; offer a schema-name override flag. Parse based on entity-name availability, not header schema name; warn on mismatch.

Notes

**See also**: Le027, Lh031. Synonyms: "FILE_SCHEMA disagrees with DATA entities", "AP214 entity in IFC4 file", "schema name mismatches entity types", "entity not in declared schema", "STEP DATA uses entities from another schema". Provenance tier: bytes-only (Q5 full-corpus 2026-07-01).
