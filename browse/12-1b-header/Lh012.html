Lh012 — Unquoted timestamp in FILE_NAME (timestamp not a STRING)

§12.1b header/numbering

syntax

Sources

  • 07-stepcode-ifcopenshell T011

Sender

older stepcode versions (#267)

Description

Per spec the timestamp attribute is a STRING. Some generators write it without surrounding apostrophes: `FILE_NAME('out.stp',2013-10-24T12:12:06,..);`. The bare token tokenizes as identifiers/numbers and fails grammar.

Reproducer recipe

`FILE_NAME('out.stp',2013-10-24T12:12:06,(''),(''),'writer','','');`

Expected kernel behavior

reject with "expected STRING at attribute 2" pointing at the unquoted token; offer strict/lenient toggle that re-quotes ISO-8601-shaped tokens with a warning.

Notes

**See also**: Lh011. Synonyms: "unquoted timestamp in FILE_NAME", "STEP date without apostrophes", "bare timestamp parses as identifier", "FILE_NAME date not a STRING", "timestamp tokenizes as numbers".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb"FILE_NAME\(\s*'[^']*'\s*,\s*[0-9]{4}-[0-9]{2}-[0-9]{2}T")
  • matches(rb"FILE_NAME\([^;]*,\s*\d{4}-\d{2}-\d{2}T")
