Lh022 — Duplicate instance ID (`#N=..` defined twice within one DATA section)

§12.1b header/numbering

silent-loss spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh022.stp

Sources

  • 07-stepcode-ifcopenshell T015, 12-adversarial A006, 16-iso-spec N034

Description

Within one DATA section each `#N` may appear on the LHS at most once. Concatenating two STEP files with overlapping IDs, or merging sub-files without renumbering, produces duplicates. Silent overwrite causes semantic divergence; in C++ implementations, freeing the first instance while references still point at it transitions to use-after-free.

Reproducer recipe

`DATA; #10=PRODUCT('a','a','',(#11)); #10=PRODUCT('b','b','',(#12)); ENDSEC;` or `#19=IFCPROJECT(..); #19=IFCSITE(..);`

Expected kernel behavior

reject with `E_DUPLICATE_INSTANCE_ID` before constructing the second instance; never silently overwrite or free-then-reuse.

Notes

**See also**: Ad038, Lh024. **OCC behavior**: silently accepts duplicate instance IDs (typically last-write-wins) without diagnostic; kernel mishandling; the catalog above forbids silent overwrite. Synonyms: "duplicate instance ID in DATA", "#42 defined twice in STEP", "concatenated STEP files have ID collision", "two definitions of same #N", "instance ID overwrites previous".
