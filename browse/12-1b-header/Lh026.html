Lh026 — Edition-3 ANCHOR / REFERENCE / SIGNATURE sections present in Edition-2 readers

§12.1b header/numbering

Description

Edition 3 introduces three optional sections: ANCHOR (named external entry points), REFERENCE (named external links via URI), SIGNATURE (digital signature). `implementation_level` becomes `'4;1'`. Older Edition-2 readers either fail to parse the sections, or strip and re-parse, or warn-and-skip; behavior is implementation-defined.

Reproducer recipe

`HEADER;..ENDSEC;ANCHOR;<a>=#1;ENDSEC;DATA;..` or add a SIGNATURE section after DATA.

Expected kernel behavior

under Ed.3, accept and pass through; warn on SIGNATURE that cannot be validated; under strict Ed.2, reject with a clear edition-mismatch diagnostic.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires. Synonyms: "ANCHOR section in Edition 2 reader", "REFERENCE section unknown", "SIGNATURE section ignored", "Edition 3 sections fail in old reader", "STEP Ed.3 sections rejected".

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

Byte assertions

  • contains(b'ANCHOR;') or contains(b'REFERENCE;') or contains(b'SIGNATURE;')
  • count(b'ENDSEC') >= 3
