Lh005 — FILE_DESCRIPTION/FILE_NAME/FILE_SCHEMA arity mismatch (extra or missing attributes)

§12.1b header/numbering

P1 — silent data loss

spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh005.stp

Sources

  • 07-stepcode-ifcopenshell T012, 16-iso-spec N054

Description

FILE_NAME requires 7 attributes; FILE_DESCRIPTION 2; FILE_SCHEMA 1 (a list). Real-world failures: extra attribute appended to FILE_NAME, empty parameter lists where attributes are required, FILE_SCHEMA written with a single string in place of a list of strings.

Reproducer recipe

`FILE_NAME('a','b',('c'),('d'),'e','f','g','h');` (8 args; expected 7); or `FILE_DESCRIPTION();` (0 args).

Expected kernel behavior

reject with a precise "attribute count mismatch" diagnostic naming the field.

Notes

**See also**: Lh004. Synonyms: "FILE_NAME wrong number of attributes", "FILE_SCHEMA arity mismatch", "FILE_DESCRIPTION extra attribute", "header record with too few parameters", "FILE_SCHEMA single string instead of list".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

Tier-3 assertions

  • load == "ok"
