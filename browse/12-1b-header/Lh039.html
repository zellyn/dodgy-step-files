Lh039 — Multi-DATA-section file with `#NNN` reuse and ambiguous local reference

§12.1b header/numbering (sub-class: multi-section)

spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh039.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §7 (intra-section vs cross-section reference)

Description

Edition-3 multi-DATA-section files may reuse `#NNN` in different sections; intra-section references default to the local section. A producer may emit a bare `#NNN` inside one section that should resolve against another (intent unclear), or copy/paste a reference forgetting the `@name` prefix. The receiver resolves to the wrong instance silently.

Reproducer recipe

DATA section `'geom'` defines `#1` and `#2`; DATA section `'pmi'` defines its own `#1` and `#2` and creates an `AXIS2_PLACEMENT_3D(..,#1,#2,@geom#2)` whose first two arguments resolve locally.

Expected kernel behavior

resolve bare `#NNN` strictly against the local section; never silently fall back to another section. Document or reject duplicate intra-section instance numbers across sections only when cross-references are explicit.

Notes

**See also**: Lh024, Lh033. Synonyms: "#NNN reuse with ambiguous local reference", "intra-section reference resolves wrong", "missing @name prefix on reference", "STEP multi-DATA local-reference ambiguity", "bare #NNN in multi-section STEP".

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

Byte assertions

  • contains(b"DATA('geom'") or contains(b"DATA('pmi'") or contains(b'@geom#')
  • contains(b'@geom') or contains(b'@geometry')
