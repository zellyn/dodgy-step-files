Lh045 — Cross-section reference to undefined section name

§12.1b header/numbering (sub-class: multi-section)

spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh045.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §7 (cross-section reference resolution)

Description

Edition-3 cross-section references `@name#NNN` resolve against the section whose `DATA('name')` declaration matches `name`. A producer that misspells the section name in a cross-reference (`@geomtry#5` for `@geometry#5`), or refers to a section that was renamed during refactoring, or copies records from another file without updating the section name, leaves a dangling reference. Receivers diverge: strict ones reject, lenient ones substitute null and load the rest, some search alternative sections in declaration order and silently bind to a wrong instance.

Reproducer recipe

DATA section `'geometry'` defines `#10=CARTESIAN_POINT('p',(0.0,0.0,0.0))`; DATA section `'pmi'` defines an `AXIS2_PLACEMENT_3D` whose location is `@geomtry#10` (typo) — section `'geomtry'` does not exist.

Expected kernel behavior

reject the unresolved cross-reference with a precise diagnostic naming the missing section and the referencing instance; never silently bind to a same-named instance in a different section.

Notes

**See also**: Lh033, Lh039. Synonyms: "misspelled section name in cross-reference", "@geomtry instead of @geometry", "STEP @section name typo", "renamed section reference broken", "cross-reference to non-existent section".

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

  • contains(b"DATA('geometry'") and contains(b"DATA('pmi'") and contains(b'@geomtry#')
  • contains(b'@geomtry')
