Lh033 — Multi-DATA-section file with cross-section reference via `@section_name#NNN`

§12.1b header/numbering (sub-class: multi-section)

spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh033.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §7 (multi-section data, cross-section reference syntax)

Description

Edition-3 introduces named DATA sections (`DATA('section_name')`) and cross-section references of the form `@section_name#NNN` to refer to instance NNN inside a different section. Edition-2 readers (the majority) recognise only `DATA;` (no name) and a single anonymous data section. Such readers either ignore the section name (collapsing all instances into one global pool, where `#NNN` may collide between sections) or choke on the `@` syntax.

Reproducer recipe

two named DATA sections `'geometry'` and `'pmi'`; an instance in `'pmi'` references `@geometry#2`.

Expected kernel behavior

parse named DATA sections and resolve `@name#NNN` cross-references against the named section; reject duplicate section names. Edition-2-only kernels should reject the file rather than silently collapse handles.

Notes

**See also**: Lh024. Synonyms: "cross-section reference @section#NNN", "Ed.3 named DATA section reference", "Ed.2 reader rejects @section#NNN", "named DATA section unsupported", "multi-DATA section cross reference".

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

  • contains(b'@geometry#') or contains(b'@geom#') or contains(b'@pmi#')
