Lh042 — SIGNATURE section appearing before DATA (signature-over-empty-content)

§12.1b header/numbering (sub-class: SIGNATURE)

spec-violation syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh042.stp

Sources

  • 16-iso-spec ISO 10303-21 Ed.3 §9 (SIGNATURE position)

Description

Edition-3 places SIGNATURE near end-of-file by convention so the signed content is fully known at signature time. A producer placing SIGNATURE before DATA either signed an empty file or computed the signature over content not yet emitted. Receivers must reject as inconsistent or warn that the signature does not cover the full payload.

Reproducer recipe

HEADER → SIGNATURE → DATA → END (SIGNATURE before DATA).

Expected kernel behavior

reject section ordering where SIGNATURE precedes DATA, or, in tolerant mode, document that the signature covers only the prefix.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires. Synonyms: "SIGNATURE before DATA section", "STEP signed empty content", "SIGNATURE at top of file", "signature over zero-content STEP", "STEP signature placement wrong".
