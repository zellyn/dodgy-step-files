Lh031 — Header recognition relies on FILE_NAME originating-system substring (I-DEAS auto-detect)

§12.1b header/numbering

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh031.stp

Sources

  • 04-occt-translation Q038, 04-occt-translation Q086

Sender

I-DEAS variants (and any tool whose preprocessor string changes)

Description

OCCT auto-detects I-DEAS-style non-manifold encoding by substring-matching the FILE_NAME `preprocessor_version` field. Misses other I-DEAS variants whose preprocessor string differs; flags false positives on tools whose preprocessor mentions "I-DEAS".

Reproducer recipe

file with `FILE_NAME(..,..,(''),(''),'I-DEAS Master Series 11','','');` versus a renamed variant.

Expected kernel behavior

Heal and accept by detecting non-manifold encoding from the entity graph (e.g. presence of `NON_MANIFOLD_SURFACE_SHAPE_REPRESENTATION`), not from a substring of header metadata.

Notes

**See also**: Lh019. Synonyms: "I-DEAS auto-detect by FILE_NAME substring", "preprocessor_version string match brittle", "false-positive non-manifold detection", "STEP receiver inferring vendor from header", "originating-system substring detection".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'I-DEAS')
  • matches(rb"FILE_NAME\([^;]*'I-DEAS")

Tier-3 assertions

  • shape_null == True
