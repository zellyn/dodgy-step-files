Lh008 — Duplicate `FILE_SCHEMA` records with conflicting schema names

§12.1b header/numbering

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1b-header/Lh008.stp

Sources

  • 12-adversarial A023

Description

Two separate `FILE_SCHEMA` lines in HEADER. Last-write-wins vs. first-write-wins behavior diverges across implementations, leading to silent schema mis-binding.

Reproducer recipe

`HEADER; FILE_DESCRIPTION((''),'2;1'); FILE_NAME(..); FILE_SCHEMA(('AP203_CONFIG_CONTROL_DESIGN')); FILE_SCHEMA(('AUTOMOTIVE_DESIGN')); ENDSEC;`

Expected kernel behavior

reject — exactly one FILE_SCHEMA permitted.

Notes

**See also**: Lh006. Synonyms: "duplicate FILE_SCHEMA records", "two FILE_SCHEMA lines in HEADER", "conflicting schema names in header", "second FILE_SCHEMA overrides first", "schema declared twice with different names".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count(b'FILE_SCHEMA') >= 2
