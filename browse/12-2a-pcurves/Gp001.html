Gp001 — Missing pcurve on edge — only the 3D curve representation is present

Sender

STEP exporters in 3D-only mode; IGES BRep round-trips; Multiboard parts library

Description

An `EDGE_CURVE` bounding a face has only its 3D curve populated; no parametric (pcurve) representation accompanies the edge on its host surface. Many writers strip pcurves entirely or fail to compute them per-face. Receivers that assume every edge-on-face has a pcurve dereference null and crash; receivers that tolerate the absence must reconstruct the pcurve by projecting the 3D curve onto the surface.

Reproducer recipe

`EDGE_CURVE` references a 3D `LINE`/`B_SPLINE_CURVE_WITH_KNOTS` and bounds an `ADVANCED_FACE`; the corresponding `SURFACE_CURVE.associated_geometry` lacks any `PCURVE` entry. With STEP writer flag "Write out curves in parametric space of surface" enabled but no cached pcurve.

Expected kernel behavior

synthesise the missing pcurve by projecting the 3D curve onto the host surface, or reject the input as malformed. Never dereference a null pcurve handle.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT crashes (`signal(11)`). The crash is on the kernel side; the file is spec-conformant Part-21.

Expected validation

occt=signal(11)/signal(11) gmsh=signal(11) ifc=schema_n/a

Byte assertions

  • contains(b'SURFACE_CURVE')
  • contains(b'EDGE_CURVE')
  • contains(b'PCURVE')
