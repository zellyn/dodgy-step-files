Gp011 — Seam curve with same pcurve referenced twice

§12.2a pcurve

silent-loss geometry

View raw fixture (.stp) step-examples/12-2a-pcurves/Gp011.stp

Sources

  • 04-occt-translation.md Q032

Description

A `SEAM_CURVE` is required to carry two distinct pcurves (one for each side of the seam), but the sender wrote the same pcurve handle twice. The two banks of the seam cannot be disambiguated, and the wire fails to close around the periodic surface.

Reproducer recipe

`SEAM_CURVE('',#3d,(#pc, #pc),.PCURVE_S1.)` where both `associated_geometry` entries are the same `PCURVE`.

Expected kernel behavior

duplicate one pcurve and shift it by the surface period to recover the missing bank, or reject as malformed. Choice is kernel-design-dependent.

Notes

**See also**: Twi022. **OCC behavior**: accepts with ERR diagnostic (empty result); outside catalog's allowed set ({heal, reject}). Kernel-bug witnessed: catalog allows either heal or reject; OCC silently accepts the bad input without doing either. Synonyms: "seam edge has same pcurve in both slots", "seam_curve associated_geometry references one pcurve twice", "two banks of seam point at same 2D curve", "seam pcurve duplicated instead of period-shifted", "seam wire fails to close around cylinder".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(3) ifc=schema_n/a

  • contains(b'EDGE_CURVE')
  • count_entity_def(b'PCURVE') >= 1

Tier-3 assertions

  • shape_null == False
  • n_faces_total == 1
  • n_edges_total == 1
  • n_vertices_total == 2
