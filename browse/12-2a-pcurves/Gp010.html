Gp010 — Surface_curve.associated_geometry contains a 3D curve in lieu of pcurve

§12.2a pcurve

P1 — silent data loss

Sender

Parasolid-origin files

Description

A `SURFACE_CURVE`'s `associated_geometry` slot uses a 3D curve (e.g. `LINE`) lying in a `PLANE` rather than a `PCURVE` with 2D parameters. Mathematically valid for flat surfaces, but importers that hardcode the 2D form fail; openNURBS-style consumers cannot evaluate `PointAtStart`/`PointAtEnd` because the path through pcurve→surface is unimplemented.

Reproducer recipe

`SURFACE_CURVE('',#3dcurve,(#assoc_geom),.PCURVE_S1.)` where `#assoc_geom` is a 3D `LINE` lying in the host `PLANE`, instead of a `PCURVE`.

Expected kernel behavior

Heal and accept; derive 2D parameter curve from 3D curve when the surface is flat; for true pcurves, evaluate in (u,v) and lift via basis surface.

Notes

**See also**: Gn030, Gp001. Synonyms: "3D curve used where pcurve expected", "associated_geometry has 3D line not 2D pcurve", "Parasolid file with 3D curve in surface_curve slot", "importer expects 2D pcurve gets 3D curve", "flat surface has 3D edge curve instead of parametric".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(3) ifc=schema_n/a

Byte assertions

  • contains(b'SURFACE_CURVE')
  • contains(b'EDGE_CURVE')
  • contains(b'PCURVE')

Tier-3 assertions

  • shape_null == False
  • n_faces_total == 1
  • n_edges_total == 1
  • n_vertices_total == 2
