Description

A `PLANE`-hosted face's sole boundary is a single self-closed edge whose 3D geometry is a `COMPOSITE_CURVE` with `closed_curve=.T.` (DECLARED closed) built from three `LINE` segments forming an approximate triangular rim: `(0,0,0)`→`(6,0,0)`→`(6,4,0)`→`(0.004,0,0)`. The third segment's actual endpoint `(0.004,0,0)` misses the first segment's true start `(0,0,0)` by 4mm — a genuine post-reorder connectivity gap specifically at the WRAP-AROUND CLOSURE, distinct from Gp034 (a 2-segment, open, `LINE`+`LINE` composite curve used as one edge of a 4-edge rectangle, with a 5mm INTERIOR gap between its two segments, not at a declared closure).

Reproducer recipe

`COMPOSITE_CURVE('...', (seg1, seg2, seg3), .T.)` with three `COMPOSITE_CURVE_SEGMENT`s wrapping `LINE`s `(0,0,0)→(6,0,0)`, `(6,0,0)→(6,4,0)`, `(6,4,0)→(0.004,0,0)`; single self-loop `EDGE_CURVE` (same start/end `VERTEX_POINT` at the true origin) using the composite curve as its 3D geometry, forming the sole `FACE_OUTER_BOUND`.

Expected kernel behavior

the composite-curve translation stage::Init` detects the closure-seam gap via `FixConnected`, and either closes it within tolerance, reports the failure with a clear diagnostic, or refuses to declare the wire closed.

Notes

**See also**: Gp034 (this class's original witness — 2-segment interior gap on an open composite curve inside a larger 4-edge face, distinct geometry and distinct gap location from this fixture). Both fixtures verified to reach the composite-curve translation stage (not orphaned in a `GEOMETRIC_CURVE_SET` per M096's rejected pattern). Tier-3 introspection shows `n_edges_total=0`/`n_vertices_total=0` despite `n_faces_total=1` — the same signature Gp034 already ships with (the composite-curve edge/vertex explorer undercounts relative to the face's own reachability), a pre-existing pattern in this corpus, not a new concern introduced here.
