Gp023 — Point-projection onto trimmed periodic `CYLINDRICAL_SURFACE` returns UV outside trimmed band (pcurve start parameter shifted by period)

§12.2a pcurve

P1 — silent data loss

Description

A face on a periodic surface (full `CYLINDRICAL_SURFACE`, `TOROIDAL_SURFACE`, etc.) is trimmed to a sub-band of U (e.g. U in [π, 2π]). Pcurve parameterisations for edges following a `CIRCLE` start at the wrong angle relative to the trimmed band; e.g. a pcurve `LINE` starts at u=π instead of u=0, off by π from the circle start angle. Equivalently, projecting a 3D point onto the trimmed periodic surface returns a UV pair outside the face's actual `[UMin,UMax]/[VMin,VMax]` band, even though a valid in-range pre-image exists in another period. Mesh-node reprojection during sheet-metal unfolding lands in the wrong period.

Reproducer recipe

Face on full cylinder trimmed to U in `[π,2π]`; pick a 3D point above the face; project; observe returned U near 0.

Expected kernel behavior

Heal and accept: a point-projection onto a trimmed periodic surface must return a UV that lies inside the face's actual parameter band when an in-range pre-image exists (re-shifting by full periods as required). Must not silently return out-of-band UV.

Notes

**See also**: Gs019. Synonyms: "point projection onto trimmed cylinder returns out-of-band UV", "projected UV outside trimmed face parameter range", "pcurve start parameter shifted by full period", "projection onto periodic surface returns wrong period", "sheet metal mesh node lands in wrong period band".
