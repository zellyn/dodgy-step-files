Description

A bare curve set — the shape representation's own item, and therefore a real translation root — holds two `B_SPLINE_CURVE_WITH_KNOTS` elements that are structurally identical and differ only in their knot vector. `good_bspline_element` has monotonically increasing knots `(0.0, 1.0)`. `throwing_bspline_element` has DECREASING knots `(1.0, 0.5)`: schema-legal Part-21 bytes, but numerically invalid geometry — a B-spline constructor requires a non-decreasing knot sequence and raises a construction error on violation rather than returning an error code. The receiver must contain that exception at the individual element, log the loss, and carry on with the set's other elements.

Reproducer recipe

`#3=B_SPLINE_CURVE_WITH_KNOTS('good_bspline_element',1,(#1,#2),.UNSPECIFIED.,.F.,.F.,(2,2),(0.0,1.0),.UNSPECIFIED.);` and `#6=B_SPLINE_CURVE_WITH_KNOTS('throwing_bspline_element',1,(#4,#5),.UNSPECIFIED.,.F.,.F.,(2,2),(1.0,0.5),.UNSPECIFIED.);` — identical apart from the knots — listed together in `#7=GEOMETRIC_CURVE_SET('ad138_element_catch_set',(#3,#6));` inside a `MANIFOLD_SURFACE_SHAPE_REPRESENTATION`.

Expected kernel behavior

catch the construction exception at the individual set element, log that element as not mapped, and still emit the surviving element's edge into the output compound — rather than aborting the set, the representation, or the whole read.

Notes

**See also**: Ad043, Xp008, Ad137 (the three coarser/sibling catch boundaries of this same class), M051, Xp017 (bare-curve-set siblings with non-geometric and empty item lists). Live-verified (2026-07-31, this worktree, OCP/OCCT 7.8.1): the transfer check list carries exactly ONE message, the warning " Entity not mapped to TopoDS", and the transferred shape is a compound holding exactly ONE edge — the good element's. Independently confirmed that the decreasing knot vector does raise (constructing the same degree-1 B-spline directly from the same poles/knots/multiplicities fails with "BSpline curve: Knots interval values too close"). Perturbation control: flipping the bad element's knots to `(0.0,1.0)` — a one-token byte change, nothing else — makes the warning disappear and the edge count go 1 → 2, so the observable is caused by the knot bytes and not by the surrounding scaffold. Synonyms: "geometric set element throws", "per-element try catch geometric curve set", "bad knot vector element skipped", "one bad curve doesn't sink the curve set", "element not mapped to TopoDS". Provenance tier: bytes-sufficient.
