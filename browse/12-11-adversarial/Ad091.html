Ad091 — Crash on STEP file from non-C locale (decimal separator)

§12.11 adversarial

adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad091.stp

Sources

  • OCCT MANTIS#0024759 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

A STEP file written under a non-C locale (e.g., Czech, German) uses comma as the decimal separator (`1,5` instead of `1.5`). When read on a system with C locale, the parser interprets `1,5` as two integers separated by a comma; the second integer being silently shifted into the next parameter. Misalignment leads to crash deeper in the geometry builder.

Reproducer recipe

STEP file containing `CARTESIAN_POINT('',(1,5,2,5,3,5))` intended as `(1.5, 2.5, 3.5)`.

Expected kernel behavior

ISO 10303-21 mandates `.` as decimal separator; reader must interpret literally regardless of locale; emit warning when ambiguous comma-separated decimal is detected.

Notes

**See also**: Le023. **OCC behavior**: accepts and loads shape(1); outside catalog's allowed set ({warn-and-proceed}). Kernel-bug witnessed: catalog wants a warning to surface; OCC accepts without any diagnostic.

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a

Byte assertions

  • matches(rb"CARTESIAN_POINT\([^;]*,\(\s*\d+\s*,\s*\d+\s*,\s*\d+\s*,\s*\d+")
  • count(b',') >= 5 and matches(rb'\(\d+,\d+,\d+,\d+,\d+,\d+\)')

Tier-3 assertions

  • load == "ok"
