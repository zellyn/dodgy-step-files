Ad057 — Memory leak / unbounded RSS after STEP assembly read (typed-value / BOOLEAN-enum table allocations not freed)

§12.11 (sub-class: resource-exhaustion)

silent-loss adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad057.stp

Sources

  • 18-other-issues.md I017 (`ShapeFix_Shape` huge memory), I018 (Linux/Docker RSS), I019 (LSAN reports `STEPControl_Controller::Init` enum allocations)

Description

After read of a moderate STEP file, RSS does not return to baseline (~900 MB held after a 142 MB file on glibc); ShapeFix on huge shells consumes huge memory. The leak is partly in the typed-value / enum tables: every distinct `BOOLEAN` slot (`.T.` / `.F.`) parsed grows a per-process table that isn't freed. Common stress shape: many `EDGE_CURVE` entries with alternating `.T.` / `.F.` BOOLEAN orientation slots stresses the enum-table allocator.

Reproducer recipe

ReadFile→Transfer→destruct on 142 MB STEP; observe RSS.

Expected kernel behavior

bypass/chunk shell-fix at large counts; release working set on destruction; free typed-value tables on shutdown.

Notes

**See also**: Ad027. **OCC behavior**: silently accepts (no diagnostic, empty result); outside catalog's allowed set ({heal}). Kernel-bug witnessed: catalog asks for healing; OCC neither heals nor rejects; the input is dropped on the floor without diagnostic.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • count_entity_def(b'EDGE_CURVE') >= 5
  • count(b'.T.') + count(b'.F.') >= 5

Tier-3 assertions

  • load == "ok"
