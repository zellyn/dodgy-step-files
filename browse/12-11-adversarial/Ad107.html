Ad107 — STEP-XML wrapper carries a billion-laughs entity-expansion bomb

Sender

deduced — adversarial input that exercises the XML-1.0 entity-expansion path with recursively-defined internal entities

Description

ISO 10303-28 specifies an XML transfer of STEP data. A STEP-XML file may include an internal DTD; XML 1.0 permits an internal DTD to declare named entities that reference other named entities. The classic billion-laughs construction declares `&lol;` as ten `&lol1;` references, `&lol1;` as ten `&lol2;` references, and so on; expansion produces 10^N copies of the leaf string from N+1 entity declarations. A receiver whose XML parser does not cap entity-expansion depth or expanded-text size allocates gigabytes from a one-kilobyte input. Bug-reporter language: "STEP-XML billion laughs", "entity expansion DoS", "recursive XML entities in STEP".

Reproducer recipe

a `.stpx` (STEP-XML) file with an internal DTD declaring `<!ENTITY lol "lol">` then `<!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">` repeated through `&lol9;`, with the document body referencing `&lol9;` inside an attribute value.

Expected kernel behavior

cap entity-expansion depth and expanded-text size in the XML parser used to load STEP-XML; reject documents that exceed the cap with a precise diagnostic; treat as adversarial.
