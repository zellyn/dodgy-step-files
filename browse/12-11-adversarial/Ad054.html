Ad054 — Mutual-cycle `NEXT_ASSEMBLY_USAGE_OCCURRENCE` chain hangs reader's `Transfer` phase forever

§12.11 (sub-class: DoS / resource-exhaustion)

P2 — spec deviation (no data loss)

adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad054.stp

Sources

  • 18-other-issues.md I002 (OCCT #712)

Description

A STEP file accepted by Catia and NX hangs the consumer indefinitely during the `Transfer` phase (`ReadFile` completes). Common attack shape: two `NEXT_ASSEMBLY_USAGE_OCCURRENCE` entries form a mutual parent/child cycle (e.g. #30 has parent=#12, child=#22; #31 has parent=#22, child=#12), so the assembly-tree walk loops forever.

Reproducer recipe

real assembly `250709r8000_asm-all` (size unspecified).

Expected kernel behavior

Reject with `E_TRANSFER_BUDGET` diagnostic: bound transfer time; detect loop and bail. Must not hang.

Notes

**See also**: Ad032.

occt=empty/empty gmsh=empty ifc=schema_n/a
