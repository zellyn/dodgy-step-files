Ad047 — `ADVANCED_FACE` `same_sense=.F.` inverts surface normal: negative or invalid face area after orientation fix

§12.11 (sub-class: schema-validation)

adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad047.stp

Sources

  • 03-occt-tests.md R075 (`bug28523`)

Description

An `ADVANCED_FACE` whose `same_sense` flag is `.F.` while the supporting surface (e.g. a `PLANE` with +Z normal) is itself oriented normally; the face flag inverts the surface normal so the orientation is inverse of the host surface. Healing reverses face orientation, producing negative computed area downstream.

Reproducer recipe

input with one mis-oriented face that triggers ShapeFix orientation flip.

Expected kernel behavior

post-fix invariant check; correct orientation idempotently.

Notes

**See also**: Ad043. **OCC behavior**: OCC loads the file and produces no shape (empty). Re-audit (2026-07-18, empty-claim re-audit): the valid square `ADVANCED_FACE` is left orphan (no shape-representation root references it). Given a rooted `SHELL_BASED_SURFACE_MODEL` it builds shape(1 face) identically with `same_sense=.F.` and `.T.`, so the declared orientation defect does not drive the empty; base/clean=empty. Orphaned defect carrier, not a defect-driven silent data-loss; not a proven kernel bug.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'ADVANCED_FACE\([^;]*,\.F\.\)')
  • count(b'.F.') >= 1

Tier-3 assertions

  • load == "ok"
