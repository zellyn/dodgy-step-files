Ad106 — `EXTERNAL_FILE` URI resolves through a symlink (TOCTOU race)

Sender

deduced — adversarial filesystem context, or a multi-process pipeline where one process writes a file and another renames the path between check and open

Description

An EXTERNAL_FILE entry references a sibling Part-21 file via a path. A receiver that follows the path performs at minimum two filesystem operations: a stat / access check (to verify the file exists, is the right type, fits a size budget) and an open (to read the bytes). On systems where the path resolves through a symlink, the symlink target may change between the check and the open — the classic TOCTOU race. A receiver that validates the stat result then opens the path can read a different file than it validated. Bug-reporter language: "STEP file follows symlink", "external-file resolves to wrong path", "TOCTOU race in STEP load".

Reproducer recipe

a STEP file whose REFERENCE / EXTERNAL_FILE clause names a path `/tmp/parts/widget.stp`; the receiver-side filesystem is set up so `/tmp/parts/widget.stp` is a symlink that the attacker can swap between the check and the open. The STEP body alone establishes only the path-naming side; the demonstration requires the receiver-side filesystem manipulation.

Expected kernel behavior

open the path once and stat the resulting file descriptor; never re-resolve the path between check and open. Refuse to follow symlinks unless explicitly enabled. Reject EXTERNAL_FILE paths that resolve outside a configured root directory.
