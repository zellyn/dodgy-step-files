Ad114 — STEP fixture path is a symlink to `/etc/passwd` or other privileged file

§12.11 adversarial (sub-class: TOCTOU / symlink-following)

silent-loss adversarial

Sources

  • bug-reporter language: "STEP loader followed symlink to /etc/passwd", "fixture path resolves outside research root"
  • CWE-59 (symlink following)
  • CWE-22 (path traversal)

Sender

deduced — adversarial filesystem context where a `.stp` fixture path is a symlink to a file the receiver should not read

Description

A receiver that opens a fixture by name without checking whether the path traverses a symlink will follow symlinks transparently. If an attacker can place a symlink at the fixture path (or anywhere along its resolution chain) pointing at a privileged file (`/etc/passwd`, `~/.ssh/id_rsa`, `/proc/self/environ`), the receiver reads the privileged file's bytes and feeds them to the Part-21 tokeniser. Most privileged files do not parse as Part-21 and the load fails benignly, but the bytes have already been read into the receiver's address space and may appear in error messages, crash dumps, or telemetry. Bug-reporter language: "STEP fixture leaks /etc/passwd", "symlink in research tree", "kernel reads non-STEP file as STEP".

Reproducer recipe

a `.stp` path in the research tree is a symlink to `/etc/passwd`. The receiver opens the path and reads ~3 KB of `root:x:0:0:..` bytes into its tokeniser. The fixture in this catalog documents the scenario in a header comment but does NOT actually create a symlink in the repo.

Expected kernel behavior

refuse to open paths whose resolved location is outside a configured root; refuse to follow symlinks within the research tree unless explicitly enabled; check `O_NOFOLLOW`-style flags on open; refuse to dump bytes from a non-Part-21 file in error messages or telemetry.
