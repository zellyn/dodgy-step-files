Ad031 — Malformed `FILE_DESCRIPTION` (missing `implementation_level` argument) triggers use-after-free in deferred header diagnostic

§12.11 (sub-class: UAF)

Description

Parser opens header parsing context, frees on `ENDSEC;`, but a deferred diagnostic emitter still holds a pointer to a string copied from the header. Common trigger: a `FILE_DESCRIPTION` header missing its `implementation_level` second argument (only one positional argument supplied), so a deferred diagnostic referencing the freed string fires after `ENDSEC;`.

Reproducer recipe

header with malformed `FILE_DESCRIPTION` followed by valid `DATA;` triggering deferred diagnostic referencing freed memory.

Expected kernel behavior

Reject malformed FILE_DESCRIPTION with diagnostic; own all diagnostic-bound strings via the diagnostic arena, not the parser's transient allocator. Must not crash via use-after-free.

Notes

H. **See also**: Ad084. Validation observed: silent-empty rather than the cited crash. The structural attack pattern (e.g., billion-laughs / cyclic-reference / very-large-string) is demonstrated; production-scale exploitation requires inflating the size factor as described. Kernel-mishandling-by-silent-acceptance is itself a defect signal at fixture scale.
