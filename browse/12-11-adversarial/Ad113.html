Ad113 — Symlink swap between read of `.input.stp` and read of `.stp` (sibling-pair TOCTOU)

§12.11 adversarial (sub-class: TOCTOU / sibling-pair race)

silent-loss adversarial

Sources

  • bug-reporter language: "STEP loader reads wrong file in sibling pair", "symlink swap between input and main STEP"
  • CWE-367 (TOCTOU)
  • cad/research sibling-pair convention (`.input.stp` + `.stp`)

Sender

deduced — adversarial filesystem context, or a multi-process pipeline where one process renames a sibling file between the receiver's two reads

Description

The cad/research validator pairs each `.stp` fixture with an optional `.input.stp` sibling that captures the producer-side input. A receiver that reads `.input.stp` first (to populate its "expected input" oracle) and then reads `.stp` (the actual fixture) performs at least two independent path resolutions. If either path is a symlink that an attacker swaps between the two reads, the receiver sees a `.input.stp` that does not match the `.stp` it ultimately processes; the textbook TOCTOU race applied to the sibling-pair convention. A receiver that reports outcomes against the wrong input grades the wrong fixture. Bug-reporter language: "sibling-pair files don't match", "symlink swap on STEP test fixture", "validator races on .input.stp".

Reproducer recipe

a `.input.stp` and `.stp` pair where one path is a symlink under attacker control; between the validator's read of `.input.stp` and its open of `.stp`, the symlink target is swapped. The bytes alone cannot demonstrate this; the demonstration requires a concurrent attacker process. **Important**: this fixture documents the scenario in a header comment but does NOT actually create a symlink in the repo (cross-platform unfriendly).

Expected kernel behavior

open both paths atomically in a single resolve, or open the directory once and use `openat()` for both files; never re-resolve absolute paths between the two reads; refuse to follow symlinks in the fixture tree unless explicitly enabled.
