Ad095 — STEP file from Pro/Engineer crashes (vendor-attribution)

§12.11 adversarial

silent-loss adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad095.stp

Sources

  • OCCT MANTIS#0026461
  • OCCT MANTIS#0025699 (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Pro/Engineer (legacy versions)

Description

STEP files from older Pro/Engineer versions emit valid syntax but combine entities in patterns the reader did not anticipate (e.g., `MAPPED_ITEM` referencing itself transitively, attribute order swapped on `STYLED_ITEM`). Reader crashes on these idiosyncratic patterns.

Reproducer recipe

AP203 file with vendor field "Pro/E v2001" containing a `STYLED_ITEM` whose `definition` parameter is in non-spec order (positional arguments swapped).

Expected kernel behavior

vendor-conditional handling; tolerate known legacy patterns when vendor field matches; reject cleanly otherwise.

Notes

**See also**: Ad081. **OCC behavior**: silently accepts (no diagnostic, empty result); outside catalog's allowed set ({reject}). Kernel-bug witnessed: receivers must reject this fixture per the catalog's stated invariant.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'Pro/E') or contains(b'Pro/Engineer')
  • contains(b'STYLED_ITEM') and contains(b'Pro')
