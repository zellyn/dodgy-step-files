Ad117 — STEP reader crashes on minimal file with malformed `STYLED_ITEM`

§12.11 adversarial / parser-robustness (sub-class: SEGV on style record)

Sources

  • OCCT MANTIS#0029979
  • bug-reporter language: "crash by reading STEP file", "STEP reader crashes on import", "segmentation fault on small STEP file". (OCCT MANTIS tracker 502 as of 2026-05-02)

Sender

Hand-edited fixtures or files emitted by a buggy producer where a `STYLED_ITEM` references a non-existent presentation-style record.

Description

A STEP file contains a `STYLED_ITEM` whose `styles` list points to an entity ID that does not exist in the data section, or contains an empty `styles` list. The reader's style-resolution pass dereferences a null pointer and the process aborts with `SIGSEGV`. The bug surfaces on otherwise minimal files — single solid plus dangling style — so the crash is reproducible on a 1 KB fixture.

Reproducer recipe

`#100=STYLED_ITEM('',(#999),#50);` where `#999` is undefined and `#50` is a valid `MANIFOLD_SOLID_BREP`. The reader segfaults dereferencing the unresolved style.

Expected kernel behavior

reject — emit `E_DANGLING_STYLE_REFERENCE` and skip the styled item; never dereference an unresolved entity reference. A crash on malformed input is a reliability defect.

Notes

**See also**: A106. Synonyms: "STEP reader crash on STYLED_ITEM", "segfault reading STEP file", "null pointer in style resolution", "STEP import crash on dangling reference".
