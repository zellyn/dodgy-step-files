Ad100 — Memory leak reading STEP file into TDocStd_Document

§12.11 adversarial

P2 — spec deviation (no data loss)

adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad100.stp

Sources

  • OCCT MANTIS#0031075
  • OCCT MANTIS#0022807
  • OCCT MANTIS#0022941 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

A STEP read into an XCAF document leaks ~MB of memory per file. Cause: the entity-graph table holds strong references to entities that are no longer referenced by any final shape, but document destruction doesn't walk the graph.

Reproducer recipe

Read 100 STEP files in succession into a single process; observe memory growth proportional to the number of files even when each document is destroyed.

Expected kernel behavior

Heal and accept: document destruction releases all internal caches; no shared globals retain entity references between reads. Must not leak memory.

Notes

**See also**: A076. Provenance tier: cross-file-state; bytes alone cannot demonstrate this defect; the symptom is monotonic process-RSS growth across many successive reads of any STEP file. Demonstrating this requires the kernel to retain state across documents and an external memory measurement, not a single fixture.

Expected validation

occt=shape(1)/shape(1) gmsh=shape(1) ifc=schema_n/a
