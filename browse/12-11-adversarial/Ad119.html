Ad119 — "Unknown ENTITY type" warning is not a hard failure (presentation subgraph silently dropped, BRL-CAD step-g)

Sources

  • SourceForge BRL-CAD bug #291 (CATIA V5R19 AP203 — `step-g` printed `Unknown ENTITY type` for nine presentation entities then aborted with `glibc detected *** step-g: malloc(): memory corruption`)
  • SourceForge BRL-CAD bug #332 (`mdgpr.step` — eleven unknown entities, geometry imports cleanly, all presentation data lost)
  • bug-reporter language: "Unknown ENTITY type STYLED_ITEM", "Unknown ENTITY type MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION", "step-g imports geometry but loses all colour and layer info", "presentation entities silently skipped".

Sender

CATIA V5/V6, NX, and Inventor exports of AP203/AP214 files where the geometric subgraph and the presentation subgraph (STYLED_ITEM, PRESENTATION_STYLE_ASSIGNMENT, SURFACE_STYLE_USAGE, SURFACE_SIDE_STYLE, SURFACE_STYLE_FILL_AREA, FILL_AREA_STYLE, FILL_AREA_STYLE_COLOUR, COLOUR_RGB, PRESENTATION_LAYER_ASSIGNMENT, MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION) coexist.

Description

When `step-g` encounters an entity its STEPcode-generated dispatcher does not recognise, it prints `Unknown ENTITY type <name>` once per instance to stderr, marks the instance as load-failed in `entity_status`, and then completes the import — the geometric subgraph is unaffected, but every colour/layer/style assignment is silently discarded. The user only notices the lost appearance after the converted .g file is rendered. In versions ≤ 7.18.4 the same dispatch path additionally tripped a glibc malloc-corruption abort (bug #291) during cleanup of the partially-loaded styled items; the warn-without-fail pattern coexisted with a latent double-free. Distinct from Ad117 (specific crash on dangling STYLED_ITEM ref) by being the umbrella "unknown entity is silently skipped" defect that drops the entire presentation subgraph at once.

Reproducer recipe

AP203 file containing `MANIFOLD_SOLID_BREP` plus `COLOUR_RGB` → `FILL_AREA_STYLE_COLOUR` → `FILL_AREA_STYLE` → `SURFACE_STYLE_FILL_AREA` → `SURFACE_SIDE_STYLE` → `SURFACE_STYLE_USAGE` → `PRESENTATION_STYLE_ASSIGNMENT` → `STYLED_ITEM` → `PRESENTATION_LAYER_ASSIGNMENT` → `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION`. step-g prints nine `Unknown ENTITY type` warnings and produces a colourless .g file.

Expected kernel behavior

reject — when an unknown entity type is referenced by a known consumer (e.g. `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION` references `STYLED_ITEM` references unresolved style), the importer must either (a) implement the presentation subgraph or (b) raise `E_UNKNOWN_PRESENTATION_ENTITY` so the caller knows colour/layer information has been lost.
