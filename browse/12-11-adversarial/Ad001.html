Ad001 — Heap buffer overflow on overlong `'…'` string literal

§12.11 (sub-class: heap-overflow / fuzz-class)

spec-violation adversarial

View raw fixture (.stp) step-examples/12-11-adversarial/Ad001.stp

Sources

  • 12-adversarial.md A001, A035
  • 16-iso-spec.md N013

Sender

attacker-crafted; pattern in CVE-2024-1848 (SOLIDWORKS), CVE-2024-23120 (Autodesk ASMIMPORT*)

Description

Reader copies a Part-21 single-quoted string into a fixed-size buffer without bounds-checking against length present. ISO 10303-21 caps strings at 32 769 octets (Ed.3 §6.4.3.5) but readers commonly use much smaller fixed slots.

Reproducer recipe

`#10=PERSON('AAAA…(several MiB of A's)…');` inside `DATA;`.

Expected kernel behavior

stream into growable buffer; impose a configurable hard cap; reject with `E_LITERAL_TOO_LONG`.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires.

Expected validation

occt=reject/reject gmsh=reject ifc=schema_n/a

Byte assertions

  • max_string_literal_length >= 32768
  • length > 32768
  • matches(rb"PERSON\([^;]*'A{1000,}")

Tier-3 assertions

  • load != "ok"
