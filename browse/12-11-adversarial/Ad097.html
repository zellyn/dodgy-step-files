Ad097 — Comment string inside STEP file breaks parser

Description

A STEP file comment `/* .. */` contains characters that resemble entity-record terminators or section markers. Lexer that uses regex-based comment stripping can be tricked into ending the comment early, leaving the comment's tail interpreted as records.

Reproducer recipe

Comment containing `*/ENDSEC;` — naive regex strips up to first `*/`, leaving `ENDSEC;` interpreted as section terminator.

Expected kernel behavior

Heal and accept: comment-stripping is character-by-character with explicit `/*` and `*/` matching; never use greedy regex. Must not crash on embedded comment-like strings.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT rejects (`reject`). OCC enforces stricter framing than the spec text requires.
