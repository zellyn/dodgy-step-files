Ad081 — Empty `SHAPE_REPRESENTATION.items` plus dangling `PRODUCT_DEFINITION_SHAPE` triggers out-of-range abort in root-transfer (Rhino-6 emit)

§12.11 (sub-class: OOB-read / DoS)

crash adversarial

Sources

  • 18-other-issues.md I044 (pythonocc-core #702)

Description

The file parses successfully but the subsequent root-transfer pass dereferences an out-of-range index and aborts. Common trigger shape: a `SHAPE_REPRESENTATION` whose `items` list is empty (`()`) combined with a dangling product chain; a `PRODUCT_DEFINITION_SHAPE` with no `SHAPE_DEFINITION_REPRESENTATION` linking it back to any representation. Producer signature: STEP/IGES emitted by a particular Rhino-6 build, which exposes the receiver's missing bound-check.

Reproducer recipe

any Rhino-6-emitted STEP loaded through the STEP reader's root-transfer entrypoint.

Expected kernel behavior

bound-check the index, fail recoverably with a diagnostic, never abort the process across the API.

Notes

**See also**: Ad043. Validation observed: silent-empty rather than the cited crash. The structural attack pattern (e.g., billion-laughs / cyclic-reference / very-large-string) is demonstrated; production-scale exploitation requires inflating the size factor as described. Kernel-mishandling-by-silent-acceptance is itself a defect signal at fixture scale.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a
