Ad045 — Healing pipeline raises exception on real input with `EDGE_CURVE` vertices off the `LINE` by sub-confusion offset ("must not throw")

§12.11 (sub-class: null-deref / fuzz-class)

Description

A healing pass over a real-world input shape throws an exception across the kernel ABI rather than producing a result, a warning, or an empty shape. Common trigger: an `EDGE_CURVE` whose `VERTEX_POINT`s do not lie on the edge's 3D `LINE` — a sub-confusion vertex/curve mismatch (e.g. ±1e-7 Y-offset from an X-axis `LINE`) — exposes a healing-path edge case. Reported failure modes include out-of-range index access on a wire-ordering pass, exceptions while evaluating an offset surface, healing reporting a negative face area, and fatal errors emerging from a wire-fix pass after a kernel upgrade.

Reproducer recipe

any of pinned test inputs; or wire whose `EDGE_CURVE` start/end disagree by approximately the kernel's confusion tolerance when traced against the host surface.

Expected kernel behavior

a healing pipeline run on any real-world input must terminate without throwing across the ABI. Kernels may report failure as a status flag, return an empty/partial shape, or downgrade to a warning; throwing an unhandled exception is not acceptable.

Notes

**See also**: Ad043. Validation observed: silent-empty rather than the cited crash. The structural attack pattern (e.g., billion-laughs / cyclic-reference / very-large-string) is demonstrated; production-scale exploitation requires inflating the size factor as described. Kernel-mishandling-by-silent-acceptance is itself a defect signal at fixture scale. **OCC behavior**: silently accepts (no diagnostic, empty result); outside catalog's allowed set ({warn-and-proceed}). Kernel-bug witnessed: catalog wants a warning to surface; OCC accepts without any diagnostic.

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'EDGE_CURVE')
  • contains(b'1e-7') or contains(b'1.0E-7') or contains(b'1.0e-7')
  • contains(b'EDGE_CURVE') and contains(b'LINE')
