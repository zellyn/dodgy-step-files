U009 — KiCad assembly: board mm + component model in inch, naive merge breaks scale

Sources

  • 22-niche-forums.md Y011 (gitlab.com/kicad/code/kicad/-/issues/22139)

Sender

vendor-supplied component STEP (US-origin, inch-based)

Description

Component vendor STEP has `LENGTH_UNIT() NAMED_UNIT(*) SI_UNIT(.INCH.)` (or `CONVERSION_BASED_UNIT` to inch); board file has `SI_UNIT(.MILLI.,.METRE.)`. Naive merger that doesn't apply per-context conversion places components 25.4× too large or too small relative to the board.

Reproducer recipe

synthesize component STEP with explicit `CONVERSION_BASED_UNIT('INCH', .., 25.4·MILLIMETRE)`; merge into mm board without unit-aware transformer.

Expected kernel behavior

heal; apply unit conversion at `MAPPED_ITEM` / sub-assembly boundary using each component's own `GEOMETRIC_REPRESENTATION_CONTEXT` global units.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT crashes (`signal(11)`). The crash is on the kernel side; the file is spec-conformant Part-21. Synonyms: "KiCad board mm with inch components", "naive STEP merger ignores per-context unit", "KiCad component placed at wrong scale", "vendor STEP inch model into mm board", "MAPPED_ITEM unit boundary unhandled".

Expected validation

occt=signal(11)/signal(11) gmsh=signal(11) ifc=schema_n/a

Byte assertions

  • contains(b"CONVERSION_BASED_UNIT('INCH'") and contains(b".MILLI.")
  • contains(b'MAPPED_ITEM')
