U039 — Plane-angle unit declared as DEGREE but values stored as radians (or vice-versa)

§12.5 (sub-class: angular-unit/value mismatch)

P1 — silent data loss

  • deduced from `CONVERSION_BASED_UNIT('DEG',..)` defects in U031 plus value-side disagreement

Sender

deduced — multi-source writer pipelines where one subsystem stores angle attributes in degrees and another in radians, with a single PLANE_ANGLE_UNIT context binding both

Description

A `PLANE_ANGLE_UNIT` context is declared as degrees via a `CONVERSION_BASED_UNIT('DEG',#x)` complex entity. Numeric angle attributes elsewhere in the same file are stored as radians (e.g. a rotation of 1.5708 radians intended as 90°). A receiver that takes the unit declaration at face value reads 1.5708° (a tiny rotation, off by a factor of pi/180 ≈ 57.3); a receiver that hard-assumes radians for any PLANE_ANGLE_MEASURE silently produces the right number for the wrong reason. Symmetrical defect: unit declared `RADIAN` but values stored as degrees (90.0 read as 90 radians ≈ 5157°). The angular twin of U001's mm-vs-inch length defect. Bug-reporter language: "STEP rotation off by 57x", "angles too small", "PMI angle reads 1.57° not 90°", "1 radian or 1 degree?".

Reproducer recipe

a `PLANE_ANGLE_UNIT` context declared as `CONVERSION_BASED_UNIT('DEGREE',#refRadianMeasure)` (factor pi/180); a `MEASURE_REPRESENTATION_ITEM` carrying `PLANE_ANGLE_MEASURE(1.5708)` whose author intended 90° but emitted the radian value. Counter-fixture: `RADIAN` unit declared, value `90.0` stored.

Expected kernel behavior

surface the disagreement when the value's magnitude is implausible for the declared unit (e.g. an angle of 90 rad is unphysical); reject as malformed when out-of-range, or warn and convert per the declared unit. The unit declaration is authoritative; receivers that hard-assume one over the other hide the producer-side defect.

Notes

Angular twin of U001 (mm vs inches). **See also**: U031, Pmi067. Synonyms: "STEP angle wrong by 57x", "deg/rad confusion", "rotation off by pi/180".
