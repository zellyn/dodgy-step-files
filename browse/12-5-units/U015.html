U015 — FreeCAD/OCCT 7.8.1: model in mm but file labelled as inches (re-import 25.4× too large)

§12.5 (sub-class: wrong-declaration / writer mislabel)

P1 — silent data loss

units

Sources

  • 20-general-forums.md J005 (forum.freecad.org viewtopic 94435
  • FreeCAD GH#18078
  • OCCT #354)

Sender

FreeCAD 1.0.x on OCCT 7.8.1

Description

User picks "inch" as export unit; OCCT 7.8.1 still writes coordinates in mm but writes `LENGTH_UNIT` as inch. Re-import scales 25.4× too large.

Reproducer recipe

file declares `(CONVERSION_BASED_UNIT('INCH',..) NAMED_UNIT(..) LENGTH_UNIT())` but `CARTESIAN_POINT` coordinates are mm-valued.

Expected kernel behavior

Warn and accept: the validator normalizes coordinate magnitudes against declared `UNCERTAINTY_MEASURE_WITH_UNIT` and assembly bounding boxes; emit a warning diagnostic on suspicious 25.4× / 1000× mismatch.

Notes

**See also**: U001. Synonyms: "FreeCAD STEP labelled inch but values mm", "model in mm but file says inches", "re-import 25.4x too large from FreeCAD STEP", "mm coords with INCH declaration", "OCCT 7.8.1 mislabels STEP as inches".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b"CONVERSION_BASED_UNIT('INCH'")
  • matches(rb"'INCH'")

Tier-3 assertions

  • shape_null == True
