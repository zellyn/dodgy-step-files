U036 — `BinXCAF` does not preserve length unit

§12.5 units

P1 — silent data loss

units

View raw fixture (.stp) step-examples/12-5-units/U036.stp

Sources

  • OCCT MANTIS#0031382 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

A document carrying a non-default length unit (e.g., inches) is saved to OCCT's binary XBF format. The persistence layer records geometry but not the document's length unit. Re-loading defaults to millimetres, scaling all values incorrectly.

Reproducer recipe

Document with `LENGTH_UNIT = INCH`, one cube side `1.0`. Save XBF. Reload — cube is 1.0 mm, not 25.4 mm.

Expected kernel behavior

Heal and accept: the persistence layer round-trips / preserves the document's length unit alongside geometry.

Notes

**See also**: U025. Synonyms: "BinXCAF loses length unit", "XBF binary loses INCH unit on save", "non-default unit not preserved in XBF", "OCCT binary persistence drops unit", "STEP unit lost through XBF round-trip".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b"CONVERSION_BASED_UNIT('INCH'")
  • contains(b'25.4') or contains(b'INCH')

Tier-3 assertions

  • shape_null == True
