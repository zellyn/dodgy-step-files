U003 — Onshape inch workspace exports metric STEP (inch-shaped coordinates in mm `LENGTH_UNIT` context)

§12.5 (sub-class: wrong-declaration / producer-side display-unit drop)

P1 — silent data loss

units

View raw fixture (.stp) step-examples/12-5-units/U003.stp

Sources

  • 10-vendor-kbs.md V003 (forum.onshape.com discussion 6658)

Sender

Onshape (workspace inches)

Description

A part modelled in Onshape with inch units exports to STEP whose `LENGTH_UNIT` is metric (millimetres); but coordinates are exact inch-to-mm conversions like 25.4 (1 in) and 63.5 (2.5 in). Geometry is preserved but the display-unit choice is lost: the file looks like an inch part rewritten as mm without scaling. Receivers display in mm with mm display tolerances.

Reproducer recipe

Onshape workspace=inch; export STEP; result file declares metric SI unit although authoring was in inches.

Expected kernel behavior

round-trip authored display unit through `CONVERSION_BASED_UNIT` for inch; do not coerce to base SI on export.

Notes

**See also**: U001. Synonyms: "Onshape inch workspace exports mm STEP", "STEP coordinates 25.4 instead of 1", "inch workspace lost in metric STEP", "display unit lost on Onshape export", "inch model with mm declaration".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'SI_UNIT(.MILLI.,.METRE.)') or contains(b'SI_UNIT(.MILLI., .METRE.)')
  • matches(rb'25\.4|63\.5')

Tier-3 assertions

  • shape_null == True
