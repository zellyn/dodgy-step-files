U038 — STEP read produces unexpectedly enormous scaling on parts (MAPPED_ITEM target uses MM while source REPRESENTATION_MAP context uses METRE: cross-context unit composition error)

Sources

  • OCCT MANTIS#0033101
  • OCCT MANTIS#0032239 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

A STEP file declares millimetres, but an internal `MAPPED_ITEM` chain composes scale factors (e.g., feature tree where a parent reused a child via a scaled placement). The reader composes the scales correctly for translation but applies them as additional unit conversions, producing parts kilometres in size.

Reproducer recipe

STEP file with `LENGTH_UNIT = MM`, root part containing a `MAPPED_ITEM` whose source has unit metres. Reader composes scale = 1000 × 1000 = 1e6.

Expected kernel behavior

Heal and accept: normalize / apply the unit-conversion factor exactly once at the leaf level; mapped-item placements compose as transforms only, not as additional unit factors.

Notes

**See also**: U028. Synonyms: "MAPPED_ITEM cross-context unit composition", "STEP scales composed as additional units", "model kilometres in size from MAPPED_ITEM", "1000x1000 unit composition error", "cross-context REPRESENTATION_MAP unit bug".
