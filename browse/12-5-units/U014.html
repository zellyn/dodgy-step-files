U014 — `LENGTH_UNIT` is bare `SI_UNIT(METRE)` but coordinates are mm-sized (`STEP Export` ignores `write.units` since OCCT 7.8 regression)

Sources

  • 18-other-issues.md I015 (OCCT issue #354)
  • 04-occt-translation.md Q083 (`write.step.unit` parameter incorrect)

Sender

OCCT `STEPControl_Writer`

Description

After OCCT 7.8 the `write.units` / `DESTEP_Parameters` write-unit setting is no longer applied: output coordinates are not scaled to the requested unit. Common signature: `LENGTH_UNIT` declared as bare `SI_UNIT(METRE)` (no `.MILLI.` prefix) but coordinate values are sized as if mm (e.g. 100, 50, 25.4), so a literal interpretation produces a 100 m × 50 m oversized part.

Reproducer recipe

`xstep.cascade.unit MM` and `write.step.unit M`, write a 1-unit vertex; file is still in mm.

Expected kernel behavior

Heal and accept: normalize / honour the configured target unit on write; coerce / apply scale during transfer.

Notes

**See also**: Pf022. Synonyms: "OCCT 7.8 ignores write.units setting", "STEP exports as METRE despite mm setting", "write.step.unit silently ignored", "OCCT regression on STEP write unit", "100m oversized part from STEP write".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • matches(rb'SI_UNIT\(\s*\$\s*,\s*\.METRE\.\)') or contains(b'SI_UNIT($,.METRE.)')
  • contains(b'.METRE.')
