U045 — `CARTESIAN_TRANSFORMATION_OPERATOR` `scale` attribute parsed but never applied (BRL-CAD step-g)

§12.5 units & coordinate systems (sub-class: transformation operator scale ignored)

P1 — silent data loss

units

Sources

  • BRL-CAD `src/conv/step/step-g/CartesianTransformationOperator.cpp` `Load` reads optional `scale` REAL attribute then `LoadONBrep` is a stub that prints `"::LoadONBrep(..) not implemented for <entity>"`
  • bug-reporter language: "STEP scale operator does nothing", "CartesianTransformationOperator3D scale ignored on import", "imported subassembly arrives at wrong size despite scale=25.4".

Sender

STEP producers that emit `CARTESIAN_TRANSFORMATION_OPERATOR_3D` with a non-unit `scale` attribute to convert sub-component units (e.g. inch-prototype scaled to mm by `scale = 25.4`), or that scale a per-instance copy of a shared prototype.

Description

The `Load` pass parses the optional `scale` REAL into a class member, but `LoadONBrep` is an unconditional stub: the scale never reaches the resulting `ON_Xform`/`gp_Trsf`. A producer's intent — "place this prototype at this location and scale it by k" — is silently lost; the located sub-shape arrives at unit scale, so a 1 inch prototype with `scale = 25.4` to make a 25.4 mm part stays 1 unit big. The reverse defect on the producer side is U015 / Wr050 (writer composes scale twice); this is the symmetric reader-side defect: scale dropped on the floor.

Reproducer recipe

`#100=CARTESIAN_TRANSFORMATION_OPERATOR_3D('inch_to_mm', #11, #12, #10, 25.4, #13);` referenced as a transformation between two `REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION` representations. step-g loads but does not apply `scale`.

Expected kernel behavior

heal-and-accept; `LoadONBrep` must build a uniform-scale `ON_Xform` from the parsed `scale` value; emit `W_OPERATOR_SCALE_APPLIED` diagnostic recording the factor.

Notes

**See also**: U015, Wr050, M061. Synonyms: "CartesianTransformationOperator scale parsed but ignored", "STEP scale operator does nothing on import", "step-g LoadONBrep stub for transformation operator", "uniform scale 25.4 dropped by reader", "BRL-CAD subassembly arrives unit scale despite operator scale".
