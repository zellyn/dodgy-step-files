Bo003 — Two void shells of one solid are nested inside each other

§12.3a (sub-class: solid imbrication)

topology

Sources

  • OCCT BRepCheck_Solid.cxx (InvalidImbricationOfShells code path) (uncovered class evidence)

Sender

deduced — OCCT uncovered-class sweep

Description

A `BREP_WITH_VOIDS` carries two inner void shells where one void is fully enclosed by the other rather than disjoint. The kernel cannot construct a clean inside/outside classification because the void hierarchy is malformed: a region the inner void declares "solid material" the outer void declares "empty space". Bug-reporter language: "nested cavities", "voids inside voids", "shell inside another shell".

Reproducer recipe

`BREP_WITH_VOIDS` with `voids` referencing two `ORIENTED_CLOSED_SHELL` entries; the inner void's bounding box is geometrically contained in the outer void's bounding box.

Expected kernel behavior

Detect the imbricated-shells case before classifying point-in-solid queries; reject as malformed, or heal by coalescing nested voids into one and emit a warning.

Notes

Synonyms: "voids overlap", "void hierarchy invalid", "nested holes".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(79) ifc=schema_n/a

Tier-3 assertions

  • face[0].surface_type == "plane"
  • face[5].surface_type == "plane"
