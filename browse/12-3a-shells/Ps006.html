Ps006 — Self-overlapping shell: one face double-covers a region of another

§12.3a shells / orientation (sub-class: pathological-success / coverage-multiplicity)

Sources

  • deduced from CLOSED_SHELL face-set semantics
  • bug-report patterns "shell has T-vertices", "two faces on same plane overlap", "mesh has double-covered triangles"

Description

A "closed" shell where a single planar region is represented twice: once by a large face spanning the whole region, and once by a smaller face on the same supporting PLANE covering a sub-region. The smaller face's edges are not shared with the larger face's loop — they form a separate boundary. Edge-degree-per-shell checks pass within each face's own loop. Kernel accepts the file silently; tier-3 introspection (point-in-face count over a sample grid) reveals certain points are "inside" two faces simultaneously.

Reproducer recipe

A unit cube whose bottom z=0 face is represented TWICE — once as the full unit square, once as the (0.0.5, 0.0.5) quadrant of the same PLANE. Both faces appear in the same OPEN_SHELL.

Expected kernel behavior

Detect overlapping face supports in a shell — either by checking that no two faces share a positive-area region of the same supporting surface, or by enforcing the edge-degree-2 invariant globally (overlapping faces fail it). Should reject, repair, or surface the overlap as a quality metric.

Notes

Tier-3 metric: cumulative covered-area-per-supporting-surface vs. union-area. For a clean shell these match; here they differ by the area of the overlay quadrant. T-vertices appear at (0.5, 0, 0), (0.5, 0.5, 0), (0, 0.5, 0). Synonyms: "shell has T-vertices", "two faces on same plane overlap", "mesh has double-covered triangles", "face partially covers another face", "overlapping coplanar faces in shell".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(34) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 28
  • face[0].surface_type == "plane"
  • face[5].surface_type == "plane"
