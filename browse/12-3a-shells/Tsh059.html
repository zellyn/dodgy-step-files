Tsh059 — Coplanar-face merge history map omits intermediate shapes (multiple ADVANCED_FACEs aliasing the same FACE_OUTER_BOUND and same PLANE)

§12.3a shells/orientation

P1 — silent data loss

Description

After merging adjacent same-surface ADVANCED_FACEs, a shape-history query asks "what resulted from edge X?" expecting either "merged into edge Y" or "deleted". History map is incomplete — some intermediate edges that were created and then re-merged carry no history record. Downstream "transfer attribute" pipelines (PMI, colour, mesh) lose data on those edges. Typical fixture precondition: multiple ADVANCED_FACEs (e.g., 4 faces) all referencing the same FACE_OUTER_BOUND and the same underlying PLANE — coplanar faces aliasing the same wire and surface entities.

Reproducer recipe

Three or more coplanar ADVANCED_FACEs sharing the same PLANE (and possibly aliasing one FACE_OUTER_BOUND); unify them. Two interior edges are created in pass 1 then removed in pass 2. History query for source-edges returns only the originals, missing the intermediate-edge → output mapping.

Expected kernel behavior

Heal and accept: normalize history to record every input → output edge mapping including intermediate states; downstream attribute transfer follows the chain.

Notes

**See also**: A007. Synonyms: "history map missing intermediate edges after merge", "PMI lost during multi-pass face merge", "color attribute disappears on edges from merged faces", "shape history incomplete after unification", "edge mapping doesn't follow merge chain".
