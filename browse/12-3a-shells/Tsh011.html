Tsh011 — `FACE_OUTER_BOUND` orientation flag inconsistent with required winding

§12.3a shell-orientation

P1 — silent data loss

topology

  • 05-occt-shapefix.md F022 (FixOrientation)

Description

An `EDGE_LOOP`'s `ORIENTED_EDGE.orientation` flags are inconsistent with the geometric winding required by the face's outward normal; the outer wire winds the wrong way, or a hole is oriented as if it were the outer bound.

Reproducer recipe

`FACE_OUTER_BOUND` with three edges, one `ORIENTED_EDGE` having `.F.` when geometrically `.T.` is required for outward winding.

Expected kernel behavior

propagate orientation from the face normal and flip wire-direction flags / inner-vs-outer classification accordingly; reject only if the loop is geometrically inconsistent (not just flag-wrong).

Notes

**See also**: Twi024. Synonyms: "outer wire winds the wrong direction", "hole loop oriented as outer boundary", "loop direction inconsistent with face normal", "face boundary winds backwards", "wire orientation opposite of expected".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(17) ifc=schema_n/a

Byte assertions

  • contains(b'FACE_OUTER_BOUND')
  • contains(b'FACE_BOUND')
  • count_entity_def(b'ADVANCED_FACE') == 1

Tier-3 assertions

  • n_faces_total == 1
