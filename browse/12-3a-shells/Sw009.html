Sw009 — `same_parameter` flag-skip trap during fast sewing

§12.3a (sub-class: fast-sewing edge-flag trap)

Description

An incoming EDGE_CURVE has its `same_parameter` flag falsely set true; fast-sewing skips the parameter-reconciliation pass that would catch it. The result is a sewn shell with edges whose 3D curve and pcurve disagree. Typical fixture: an EDGE_CURVE references a 3D LINE for its curve geometry; a separate LINE_2D/VECTOR_2D/DIRECTION_2D pcurve is also defined but parameterized differently and not connected via PCURVE/SURFACE_CURVE to the edge — the parametric pcurve dangles separately. Bug-reporter language: "same_parameter flag stuck", "fast sew skips parameter reconciliation", "orphan pcurve / dangling LINE_2D".

Reproducer recipe

An EDGE_CURVE with `same_parameter = .T.` referencing a 3D LINE; alongside it, a free LINE_2D/VECTOR_2D pcurve with a different parameter range that is not bound via PCURVE/SURFACE_CURVE. Pass through fast sewing.

Expected kernel behavior

Heal and accept: always normalize / reconcile parameters when sewing produces a new edge; trust no input flag.

Notes

Bug-reporter synonyms: "edge sew bypass".
