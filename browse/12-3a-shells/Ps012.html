Ps012 — Sweep silently truncated to a CONICAL_SURFACE

§12.3a shells / orientation (sub-class: pathological-success / surface-simplification)

P1 — silent data loss

topology

Sources

  • deduced from CONICAL_SURFACE vs SURFACE_OF_REVOLUTION semantics
  • bug-report patterns "swept profile lost", "vase imported as cone", "B-spline simplified during export"

Description

A producer modelled a "vase" — a closed solid of revolution whose generatrix is a B-spline curve that bulges outward at mid-height. The export pipeline simplified the generatrix to a single straight line, yielding a CONICAL_SURFACE. The resulting solid is a perfectly valid frustum-like cone; the producer thought it was a curved vase. The file is clean and topologically sound.

Reproducer recipe

A frustum of revolution: cone apex on Z-axis, half-angle small enough that radius goes from 5 at z=0 to 2 at z=10. Top and bottom planar disk faces, side cone face. CLOSED_SHELL, MANIFOLD_SOLID_BREP.

Expected kernel behavior

Warn and accept: a kernel cannot detect this from the file alone, but it normalizes and exposes the surface type (CONICAL_SURFACE, SURFACE_OF_REVOLUTION, B_SPLINE_SURFACE, ..) and the actual generatrix curve so downstream tools or DRC checks can compare against the producer's intent if it's known. A "surface-type histogram" output is a common kernel feature for this purpose.

Notes

Tier-3 metric: count of CONICAL_SURFACE / CYLINDRICAL_SURFACE / B_SPLINE_SURFACE per representation; cross-check against expected counts from metadata. Real-vs-intended-curvature deviation can be computed from sample points if the original generatrix is available. Synonyms: "swept profile lost", "vase imported as cone", "B-spline simplified during export", "curved generatrix replaced by straight line", "complex revolution simplified to frustum".

Tier-3 assertions

  • face[0].surface_type == "cone"
