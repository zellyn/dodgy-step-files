Description

`FILE_NAME`'s preprocessor-version field is `'I-DEAS 9.1'`, triggering OCCT's I-DEAS legacy heuristic. Two DISTINCT `EDGE_CURVE` entities — `#12` (on `face_a`, real geometry `(5,0,0)→(5,1,0)`) and `#49` (on `face_b`, a spatially unrelated stand-in geometry `(20,0,0)→(21,0,0)`) — carry the IDENTICAL Name string `'ideas_shared_edge'` but are otherwise unconnected entities (different STEP ids, different `VERTEX_POINT`/`LINE` sub-entities). `face_a` and `face_b` are each their own `OPEN_SHELL`/`SHELL_BASED_SURFACE_MODEL`, both listed as items of one ordinary `SHAPE_REPRESENTATION` (not the explicit non-manifold subtype — the I-DEAS heuristic is meant to infer non-manifold intent from legacy preprocessor strings alone, on an otherwise-ordinary representation).

Reproducer recipe

`FILE_NAME('Tsh255.stp','...',(''),(''),'I-DEAS 9.1','','')`. `#12=EDGE_CURVE('ideas_shared_edge',#6,#7,#11,.T.)` on `face_a` (real hinge edge). `#49=EDGE_CURVE('ideas_shared_edge',#42,#43,#48,.T.)` on `face_b` — same Name, deliberately WRONG own geometry (a different `LINE`/`VERTEX_POINT` pair 15 units away). Both faces' `SHELL_BASED_SURFACE_MODEL`s listed together in one plain `SHAPE_REPRESENTATION('',(#37,#74),#9060)`.

Expected kernel behavior

with `read.step.nonmanifold` AND `read.step.ideas` both enabled and the preprocessor-version I-DEAS heuristic matched, a second `EDGE_CURVE` sharing an already-bound, non-empty Name with a previously-translated edge is resolved by name lookup to the EXISTING shape (reversed if needed) — its own (possibly divergent) 3D curve and vertices are never evaluated at all.

Notes

**Empirical finding (live-verified, decisive)**: with `read.step.nonmanifold=1` and `read.step.ideas=1` both set (`Interface_Static`), `#49`'s own declared geometry `(20,0,0)→(21,0,0)` is never used — `TopExp.MapShapesAndAncestors_s` on the translated shape shows an edge at `#12`'s actual coordinates `(5,0,0)→(5,1,0)` shared by BOTH faces (`used by 2 faces`), while `face_b`'s remaining boundary (near `x=20-21`) is left spatially disconnected from it (the corpus's standard `XSAlgo` shape-fixing pass subsequently patches the resulting gap by relocating one `face_b` vertex to `(20.5,0,0)`, a visible artifact of the substitution, not part of the core claim). This directly confirms `#49`'s own curve/vertex geometry was discarded in favor of the name-matched `#12` shape. With EITHER flag off, or with the default OCCT settings this corpus's standard tier-3 harness uses (both flags default 0), no substitution occurs: `#49` translates its own (self-consistent, if spatially odd) geometry independently, giving 2 faces / 8 edges / 16(raw)/8(distinct) vertices and a normal `brepcheck.valid=True` shape — the Tier-3 fields below describe this DEFAULT read; the name-matched reuse is a supplementary, explicitly-enabled-mode finding (same convention as Tsh254 and Tsh248-250).
