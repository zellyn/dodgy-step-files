Description

A topologically CLOSED tetrahedron — 4 vertices, 6 EDGE_CURVE entities each genuinely SHARED by exactly 2 of the 4 faces (unlike Tsh003, whose 4 faces each carry their own independently-duplicated edge entities with no cross-face entity sharing at all) — emitted as `OPEN_SHELL`/`SHELL_BASED_SURFACE_MODEL` (the wrong container for a solid, same "wrong-container" premise as Tsh003), alongside a second, unrelated open planar-face item (`second_item_face`, an ordinary un-closed 4-edge square), both listed as two items of one `NON_MANIFOLD_SURFACE_SHAPE_REPRESENTATION`.

Reproducer recipe

Tetrahedron with vertices `vtx_a/b/c/d`; six shared `EDGE_CURVE`s `e_ab,e_ac,e_ad,e_bc,e_bd,e_cd`, each referenced by exactly 2 of `face_abc/face_abd/face_acd/face_bcd` via correctly-paired forward/reversed `ORIENTED_EDGE`s; `OPEN_SHELL('tsh258_shell',(...4 faces...))` in `SHELL_BASED_SURFACE_MODEL('tsh258_sbsm',(...))`. Second item: `OPEN_SHELL('second_item_shell',(#109))` (one ordinary open square face) in its own `SHELL_BASED_SURFACE_MODEL`. Both listed together: `NON_MANIFOLD_SURFACE_SHAPE_REPRESENTATION('',(#74,#111),#9060)`.

Expected kernel behavior

when non-manifold reading is active, after the per-item shapes are aggregated and healed, any resulting shell that is genuinely closed (every edge shared by exactly 2 faces) is automatically re-wrapped in a solid; a shell that is NOT closed (like the second item's lone open face) is left as a bare shell, unchanged.

Notes

**Empirical finding (live-verified, decisive, this worktree's OCP/OCCT 7.8.1) — supersedes the prior "unconfirmed" framing**: three variants were tested directly against the reader before arriving at this construction. (1) Tsh003's own literal geometry (independently-duplicated per-face edges, no entity sharing) — the shape's own closure query genuinely returns false regardless of settings (12 free edges, each used by only 1 face), so it can NEVER be promoted by ANY mechanism; Tsh003's `occt=shape(1)` was never actually a promoted solid, confirming the prior audit's suspicion. (2) A genuinely-shared-edge tetrahedron (this fixture's geometry) as the SOLE item of its `NON_MANIFOLD_SURFACE_SHAPE_REPRESENTATION` — the reader's single-item shortcut for a representation containing just one shape binds the PRE-reconstruction result directly, silently discarding the reconstructed/promoted compound entirely — the promotion runs internally but is invisible in the final transferred shape. (3) THIS fixture, with 2 items: the reconstructed compound (containing the promoted solid) is what's actually bound. Live-confirmed via a direct reader load with non-manifold reading enabled: the result is a compound containing exactly 1 solid (verified via an explicit shape-kind traversal) whose own face count is exactly 4 (a shape-traversal map on the solid), plus the second item's un-promoted open shell/face — decisive, per-item confirmation that specifically the closed tetrahedron (not the whole file) was promoted. With non-manifold reading at its default (off, this corpus's standard tier-3 harness setting), no non-manifold-specific processing occurs at all and the result is an ordinary compound of 2 shells / 5 faces, 0 solids — the Tier-3 fields below describe this DEFAULT read; the promotion is a supplementary, explicitly-enabled-mode finding (same convention as Tsh254/255/256/257 in this packet). Synonyms: "closed shell promoted to solid", "OPEN_SHELL closed tetrahedron becomes a genuine solid", "shell-to-solid reconstruction non-manifold mode", "wrong container type silently upgraded", "multi-item representation required to observe promotion".
