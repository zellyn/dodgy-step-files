Bo031 — Void shell of a solid that translates to nothing at all: the solid is still built from the outer shell and the surviving void

Companion reachability analysis read from OCCT source at `bd2a789f15235755ce4d1a3b07379a2e062fdc2e`: `StepToTopoDS_TranslateShell.cxx:104-107` (shell translation reports done unconditionally for any non-null connected-face-set, even one whose every face failed at `:95-97` or one with no faces at all) and `:61-62` (the only not-done path is a null connected-face-set, whose early return does not reset the done flag).

Description

A solid-with-voids has a valid 10×10×10 outer boundary shell, one valid 2×2×2 void, and a second void, `failing_void_shell`, that is a `CLOSED_SHELL` holding exactly one `ADVANCED_FACE`, `failing_void_face`, whose `face_geometry` is unset (`$`). That face has no surface and cannot be translated, so the second void contributes no geometry whatsoever. The receiver must still assemble the solid from the outer shell and the good void — the asymmetric counterpart to a failed OUTER shell, which is fatal to the whole solid (Bo001, Bo002). Every existing void fixture in the corpus (Tsh015, Tsh067, Bo003) has voids that translate cleanly; unset `face_geometry` is the same null-surface pattern Xp008 uses one container level down.

Reproducer recipe

`CLOSED_SHELL` boxes for the outer boundary (`outer_*`, 10 units) and the good void (`good_void_*`, 2 units); then `ADVANCED_FACE('failing_void_face',(#bound),$,.T.)` in `CLOSED_SHELL('failing_void_shell',(#failing_void_face))`; `ORIENTED_CLOSED_SHELL('',*,#good_void,.F.)` and `ORIENTED_CLOSED_SHELL('',*,#failing_void_shell,.F.)` (note the `*` placeholder — `cfs_faces` is a redeclared derived attribute here); `BREP_WITH_VOIDS('bo031_body',#outer,(#ocs_good,#ocs_bad))` in an `ADVANCED_BREP_SHAPE_REPRESENTATION`.

Expected kernel behavior

a void member that yields no geometry is logged and dropped while the solid is still assembled from the outer shell and the remaining voids; only the mandatory outer shell's failure is fatal.

Notes

**See also**: Bo001, Bo002 (the fatal-outer-shell half of this contrast), Bo003, Tsh015, Tsh067 (solids whose voids all translate), Xp008, Tsh023, Tsh256, Tsh257, M051, Xp017 (the other container subvariants of this class). Live-verified (2026-07-31, this worktree, OCP/OCCT 7.8.1): the transfer check list carries " Surface has not been created" (the unset `face_geometry`) and " a Face from Shell not mapped to TopoDS" — and NOT " A Void from BrepWithVoids not mapped to TopoDS". The transferred shape is still 1 SOLID carrying 3 shells (outer, good void, and the now-empty failing void) with 12 faces: the outer shell's 6 plus the good void's 6, the failing void contributing none. A third, incidental warning "Shell has incorrect flag isClosed" is present in the control too and is not part of the claim. **Honest scope note — what this entry does NOT show.** The literal per-void "not mapped" warning is structurally UNREACHABLE from a Part-21 file in this OCCT version, for two independent reasons (both cited under Sources): shell translation reports done for any void whose reference resolves, however empty the result; and the only not-done path needs an unresolvable void reference, whose early return does not clear the stale done flag anyway. That second construction was built and run and is process-fatal — the reader exits with signal 11 during the read — so it was discarded as CI-unsafe and is not shipped. What IS demonstrated live is the class's actual claim for this container: a void that contributes nothing does not abort the parent solid. Perturbation control (byte-level A/B): giving `failing_void_face` a real `PLANE` instead of `$` — one reference changed, nothing else — makes both target messages disappear and raises the face count 12 → 13; the solid count stays 1 either way. Synonyms: "void shell not mapped", "solid built without its failing void", "brep with voids partial continuation", "one bad void doesn't sink the solid", "outer shell fatal but void is not". Provenance tier: bytes-sufficient.
