Tsh015 — Brep_with_voids: void shell oriented `.T.` instead of `.F.` (ProSTEP TR9)

§12.3a shell-orientation

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-3a-shells/Tsh015.stp

Sources

  • 04-occt-translation.md Q027 (ProSTEP TR9, RWStepShape_RWBrepWithVoids)

Sender

ProSTEP TR9 reference files

Description

Per AP214, voids in a `BREP_WITH_VOIDS` must be reversed orientation relative to the outer shell; some files emit them with `.T.` so the void is mis-classified as a positive volume.

Reproducer recipe

`#N=BREP_WITH_VOIDS('',#outer,(#void));` where `#void` is a `CLOSED_SHELL` whose orientation in `oriented_closed_shell` is `.T.` instead of `.F.`.

Expected kernel behavior

heal — detect mis-oriented voids by signed-volume sign; auto-reverse with warning.

Notes

**See also**: Tsh009. Synonyms: "interior void mis-classified as positive volume", "hollow part loses its inner cavity", "void shell oriented backwards", "internal hole counts as solid material", "BREP_WITH_VOIDS void direction wrong".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'ORIENTED_CLOSED_SHELL')
  • count_entity_def(b'CLOSED_SHELL') == 2
