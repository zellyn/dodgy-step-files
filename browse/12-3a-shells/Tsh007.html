Tsh007 — `IsClosed` flag inconsistent with actual shell topology

§12.3a shell-orientation

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-3a-shells/Tsh007.stp

Sources

  • 08-occt-gitlog.md G078, G105 (Mantis 23182, 24385)

Description

A STEP-imported shell carries `IsClosed=true` while geometrically having free boundaries (or vice versa); the declared `CLOSED_SHELL` was translated without checking actual face-graph closure, leaving the wrong flag downstream.

Reproducer recipe

`CLOSED_SHELL` whose face graph has dangling edges; or `OPEN_SHELL` whose face graph actually closes.

Expected kernel behavior

recompute the closed-shell flag from edge sharing during the shell-validity pass and emit a warning when the flag was incorrect; or reject as malformed.

Notes

Synonyms: "solid declared closed but isn't watertight", "manifold solid contains free naked edges", "claimed-closed shell has gaps", "shell flag lies about closure", "watertight flag set on leaky body".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(25) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 20
  • face[0].surface_type == "plane"
  • face[4].surface_type == "plane"
