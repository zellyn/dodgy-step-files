Tsh243 — Within-tolerance gap but candidate edge shorter than the min-length floor: rejected as a spurious sliver

§12.3a shells (sub-class: edge-merging-tolerance — `sew-free-edge-gap-merge`)

Sources

  • occt-coverage PARTIAL audit, `exchange/problems.json` `sew-free-edge-gap-merge` (`BRepBuilderAPI_Sewing::FindCandidates`, `BRepBuilderAPI_Sewing.cxx:1502`). First of the class's two missing subvariants — the six existing fixtures (Tfa020, Tsh203, Tsh187, Twi037, Tfa019, Tsh181) all present ordinary-length within-tolerance gap-merge candidates.

Description

An `OPEN_SHELL` with TWO `ADVANCED_FACE`s. Face A hosts a 10mm-long reference free edge E=(0,0,0)-(10,0,0). Face B hosts a genuinely tiny (5e-5mm-long) candidate edge at x:[4.0,4.00005], y=1e-4 (perpendicular gap comfortably within a 1.0mm sewing tolerance, so the gap check alone would pass) — Face B's other two (apex) edges are ordinary-sized (2mm), so the whole face's free-boundary wire is NOT itself negligible-extent (avoiding the unrelated `sew-degenerate-free-wire-collapse` mechanism firing on the whole face instead). `FindCandidates`: `if (aMaxDist >= 0.0 && aMaxDist <= myTolerance && arrLen(i) > myMinTolerance)` — a candidate is accepted only if BOTH the sampled max distance is within tolerance AND the matching span exceeds `myMinTolerance` (internally `myTolerance*1e-4`). At operating tolerance 1.0, `myMinTolerance==1e-4`; Face B's candidate span (5e-5) is HALF that floor.

Reproducer recipe

A long (e.g. 10mm) face-hosted reference free edge, and a second face-hosted candidate edge within-tolerance-gap of it but whose own length is below `myTolerance*1e-4` — with the candidate face's OTHER boundary edges kept ordinary-sized so the whole candidate face isn't itself negligible-extent.

Expected kernel behavior

reject the candidate as a spurious sliver (do not merge), leaving the reference edge free/unmatched at that location, distinct from an ordinary-length candidate which DOES merge under the same harness (verified separately via Tsh242's Face A/B pair).

Notes

Live-verified (this worktree's OCP/OCCT 7.8.1, runtime the sewing stage(tolerance=1.0)` scaffold — reader-default the reader does not itself invoke Sewing): `NbContigousEdges()==0` for this fixture (no merge). A control build with the candidate's length raised to 5e-3mm (100x larger, above the `myMinTolerance` floor at the same tolerance) shows `NbContigousEdges()==1` and a genuine unique-edge-count increase (7→8), confirming length — not distance — is the deciding factor isolated by this pair. Synonyms: "spurious sliver candidate rejection", "myMinTolerance span floor", "short candidate edge gap-merge reject", "FindCandidates arrLen length gate", "sub-floor sliver edge not merged".
