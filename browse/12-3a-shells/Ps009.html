Ps009 — Flatness tolerance attached to geometrically adjacent wrong face

§12.3a shells / orientation (filed here per Ps prefix; conceptually §12.7 PMI)

Sources

  • deduced from GEOMETRIC_ITEM_SPECIFIC_USAGE semantics
  • bug-report patterns "PMI on wrong face", "tolerance attached to back face instead of front", "GD&T frame references neighboring face"

Description

A thin block (1mm thick in Y) where the producer intended a flatness tolerance on FACE_A (front, y=0). Due to a face-indexing bug in the PMI exporter, the GISU references FACE_B (back, y=1) — a face geometrically very close but functionally unrelated. The tolerance frame, datum system, and value are all well-formed. Kernel accepts the file silently; tier-3 introspection (cross-check intended-target metadata names against actual GISU references, or annotation-leader-line endpoint vs. face geometry) reveals the misattachment.

Reproducer recipe

A 10x1x5 block with the front face named 'FACE_A_FRONT' and back face named 'FACE_B_BACK'. A FLATNESS_TOLERANCE attached to a SHAPE_ASPECT whose GISU references the back face. Wrap in AP242_MANAGED_MODEL_BASED_3D_ENGINEERING_MIM_LF schema.

Expected kernel behavior

Surface every PMI-to-feature link as a pair (PMI-frame, target-face) so downstream tools can verify alignment between the leader-line geometry, the face name, and the tolerance semantics. Should not silently propagate a tolerance to a face the producer never intended.

Notes

Tier-3 metric: leader-line endpoint distance to GISU-target face vs. distance to nearest other face — if the nearest face is different, the tolerance is likely misattached. Synonyms: "PMI on wrong face", "tolerance attached to back face instead of front", "GD&T frame references neighboring face", "annotation points to wrong face", "flatness tolerance bound to neighbor face".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(27) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 24
  • face[0].surface_type == "plane"
  • face[5].surface_type == "plane"
