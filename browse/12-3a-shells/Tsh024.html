Tsh024 — `CONNECTED_FACE_SET` containing non-face entities

§12.3a shell-orientation

P1 — silent data loss

crash topology

View raw fixture (.stp) step-examples/12-3a-shells/Tsh024.stp

Sources

  • 08-occt-gitlog.md G034 (Mantis 29784)

Description

When sub-shapes are enabled, a `CONNECTED_FACE_SET` may contain `VERTEX_POINT` entries; OCCT's `ExpandShell` assumed all children were faces.

Reproducer recipe

`CONNECTED_FACE_SET` aggregating `ADVANCED_FACE` entities and one `VERTEX_POINT`.

Expected kernel behavior

Warn and accept: normalize / filter children to faces; emit a warning diagnostic on the rest.

Notes

Synonyms: "shell contains non-face entities", "vertex appears in face set", "wrong entity type in connected face set", "face aggregation has stray vertices", "ExpandShell crashes on non-face child".

Expected validation

occt=empty/empty gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'OPEN_SHELL')
  • contains(b'SHELL_BASED_SURFACE_MODEL')
  • count_entity_def(b'ADVANCED_FACE') == 2
