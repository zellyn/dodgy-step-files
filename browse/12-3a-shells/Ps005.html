Ps005 — Two MANIFOLD_SOLID_BREPs at identical coordinates in one SHAPE_REPRESENTATION

Sources

  • deduced from SHAPE_REPRESENTATION list semantics
  • bug-report patterns "duplicate body", "two solids occupying same space", "mass-properties returns 2x the mass", "boolean union deduplicates"

Description

A single SHAPE_REPRESENTATION lists two MANIFOLD_SOLID_BREPs that occupy the same coordinate space. They share no entities; vertices, edges, faces, and shells are all distinct instances but with bit-identical coordinates. Each individual solid validates. The kernel reports two bodies; the producer's intent was one. Tier-3 introspection (pairwise spatial-overlap check among solids in a representation, or AABB-equality + face-set hash) reveals the duplicate.

Reproducer recipe

Build a unit cube as MANIFOLD_SOLID_BREP #510. Build a second unit cube with freshly-renumbered entities at the same coordinates as #1110. Reference both from ADVANCED_BREP_SHAPE_REPRESENTATION.items.

Expected kernel behavior

Detect spatially-coincident solids in a single representation and either deduplicate, report the redundancy, or expose count/AABB metrics that downstream code can use. Should not silently propagate doubled mass / volume / face counts to downstream consumers.

Notes

Tier-3 metric: count of solids in representation whose AABBs match within working precision AND whose face counts match. Synonyms: "duplicate body at same location", "two solids occupying same space", "mass-properties returns 2x the mass", "boolean union deduplicates", "two copies of same part overlapping".

Expected validation

occt=shape(2)/shape(2) gmsh=shape(54) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 48
  • face[0].surface_type == "plane"
  • face[5].surface_type == "plane"
