Tsh252 — Partial-overlap (80%-coverage) gap candidate: achieved merge tolerance tracks the inset distance, not the true perpendicular gap

  • no live construction previously isolated a case where that estimate visibly diverges from the true geometric gap.

Description

Two real `ADVANCED_FACE`s in one `OPEN_SHELL`, both 5.0mm-scale free edges with a genuine TRUE perpendicular gap of only 0.0001mm — well within sewing tolerance — but the candidate edge is symmetrically inset 0.5mm from each end relative to the reference edge's full span (an 80%-coverage interior candidate, a substantially larger inset than the roughly 1% insets used elsewhere in this corpus). A parameter sweep holding the true gap fixed and varying only the inset shows a sharp, reproducible split: insets from 1% to 14% of the span all produce an achieved tolerance that scales with the INSET distance rather than the true gap (off by up to five orders of magnitude), while a full-span candidate (zero inset) recovers the tight, gap-proportional value.

Reproducer recipe

`OPEN_SHELL` with two `ADVANCED_FACE`s, the reference edge x:[0,5],y=0 and the candidate edge x:[0.5,4.5],y=0.0001 (an 80%-coverage interior span, true perpendicular gap 0.0001mm).

Expected kernel behavior

whichever tolerance-estimation path a partial-overlap candidate takes, the reported achieved tolerance should still reflect the true geometric deviation between the two curves, not an unrelated quantity such as the longitudinal inset distance between the candidate's endpoints and the reference's own endpoints.

Notes

Live-verified (this worktree's OCP/OCCT 7.8.1, runtime sewing scaffold): the pair merges (`NbContigousEdges()==1`) and the shared edge's achieved tolerance comes back `0.525` — essentially the 0.5mm inset distance scaled by roughly 1.05, having nothing to do with the 0.0001mm true gap (off by roughly 5000x). A controlled sweep over the inset distance (0.05mm through 0.7mm, true gap fixed at 0.0001mm) reproduces the SAME pattern every time — achieved tolerance is consistently ≈1.05×inset — while a full-span candidate (zero inset, endpoints coincide with the reference's own endpoints) recovers the tight, correct `0.000105`. This qualitative split (tight-and-correct at zero inset vs. inset-scaled-and-wrong across a broad range of partial-overlap configurations) is consistent with a distinct, cruder estimation path engaging specifically when a candidate only partially overlaps its reference's own span, matching the class's last-resort-estimate citation; it was independently confirmed not to depend on curve type (an equivalent all-line construction and a construction using an explicit B-spline basis both reproduce the identical `0.525` value at the same inset). Synonyms: "sewing tolerance tracks inset not gap", "partial overlap tolerance estimate wrong", "discretized sampling fallback tolerance", "last resort tolerance estimate sewing", "candidate coverage affects achieved tolerance".
