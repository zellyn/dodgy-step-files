Ls046 — STEP parser syntax error messages inaccessible to caller (e.g., entities with unclosed parentheses and missing string quotes)

Description

A STEP reader parses a malformed file, accumulates syntax errors internally, then reports a generic "parsing failed" status to the caller. Detailed line / column / entity information is logged to stderr but not returned via API. Tools that wrap the reader (via Python / command-line) cannot present diagnostics to users. Typical fixture: two entities with distinct lexical syntax errors — e.g., one with an unclosed parenthesis and another with a missing string-literal quote.

Reproducer recipe

STEP file with two distinct syntax errors (e.g., unclosed parentheses, missing quotes) at lines 100 and 200; caller obtains status only.

Expected kernel behavior

Reject with structured diagnostics: reader returns a structured diagnostic list with file location, entity ID, and error text per error. Must not silently swallow syntax errors.

Notes

**See also**: Ad088. Synonyms: "STEP parser error message inaccessible", "syntax error not surfaced to caller", "unclosed paren error swallowed", "parser warnings don't reach API", "STEP error log not exposed".
