Ls030 — Apostrophe inside `/* .. */` comment misread as string delimiter

§12.1c comments

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1c-syntax/Ls030.stp

Sources

  • T002

Description

A `/* .. */` comment containing an apostrophe is rejected because the comment-skip routine and a separate string-literal recognizer share a regex/scanner that mis-pairs the in-comment apostrophe with the next apostrophe in the file.

Reproducer recipe

`/* plane angle is 'degree' as non-SI unit */` placed between header and DATA.

Expected kernel behavior

Heal and accept: comments scanned to next `*/` independent of any string state; apostrophe inside comment is opaque.

Notes

Synonyms: "apostrophe inside STEP comment misread", "comment containing single quote breaks parser", "comment apostrophe paired with later quote", "STEP comment quote desyncs scanner", "in-comment apostrophe confuses lexer".
