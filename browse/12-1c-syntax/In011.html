In011 — Reader exception swallowed (entity bound to null) when B_SPLINE control points use extreme-magnitude or subnormal coordinates (1.0E+308 / 5.0E-324)

Description

A C++ exception is thrown during the transfer of a single entity; the transfer record is "bound" but the bound result is null. Downstream consumers see "Done" status with no shape attached. Typical fixture: a B_SPLINE_CURVE_WITH_KNOTS whose CARTESIAN_POINT control points use extreme-magnitude IEEE-754 values (e.g., 1.0E+308 near the ceiling, or a subnormal like 5.0E-324) that overflow during arithmetic. Bug-reporter language: "kernel says done but produced nothing", "transfer succeeded with empty result", "extreme-magnitude coordinates overflow".

Reproducer recipe

An entity that triggers a transfer-time exception (e.g., a `B_SPLINE_CURVE_WITH_KNOTS` with NaN-valued, near-IEEE-ceiling (1.0E+308), or subnormal (5.0E-324) control point coordinates).

Expected kernel behavior

Reject and emit the underlying exception text: mark the transfer as Error, not Done; must not silently swallow exceptions.

Notes

Synonyms: "silent transfer failure". Provenance tier: runtime-only; bytes alone cannot demonstrate this defect; the symptom is a transfer-time C++ exception silently swallowed and replaced with a null binding plus a "Done" status. The static fixture only carries the trigger geometry; demonstrating the swallowed exception requires a kernel runtime trace. Synonyms: "STEP entity bound to null after exception", "B-spline with extreme coords gives null", "1.0E+308 control point swallows exception", "STEP transfer Done but shape null", "exception swallowed during STEP transfer".
