In002 — Load-time warning vs data-content warning: severity confusion

Sender

Description

Two different sources of warnings (parser warnings about file syntax vs. semantic warnings about data content) are mapped onto the same severity bucket. A consumer who suppresses load warnings ends up suppressing data warnings too. Typical fixture: a stray comment between HEADER's ENDSEC and the DATA section (parser-level warning) plus a B_SPLINE_CURVE_WITH_KNOTS at the upper-boundary degree (e.g., degree 25 — a data-level warning). Bug-reporter language: "warnings hidden", "parser warnings vs data warnings confused".

Reproducer recipe

A file with both a parser-level warning (a stray comment between ENDSEC and DATA, or in another unusual place) and a data-level warning (e.g., a B_SPLINE_CURVE_WITH_KNOTS at the spec-boundary degree).

Expected kernel behavior

Distinguish severity classes; separate warning channels.

Notes

Bug-reporter synonyms: "diagnostic channel confusion". Provenance tier: runtime-only — bytes alone cannot demonstrate this defect; the symptom is the conflation of two diagnostic severity channels emitted by the kernel during parse + transfer. A behavioral test that captures the kernel's diagnostic stream is the appropriate venue. Synonyms: "STEP load warning vs data warning conflated", "diagnostic severity confused", "syntax warning suppresses semantic warning", "warning channel mixed for STEP load", "STEP warning bucket conflated".
