In003 — A "Mend" demotes a Fail to a Warning, hiding the original failure (e.g., B_SPLINE_CURVE_WITH_KNOTS with wrong knot count auto-fixed)

Description

A reader's `Mend()` step takes a Fail-class diagnostic and downgrades it to a Warning if the kernel "fixed" the underlying problem. A consumer relying on the original Fail to gate further processing now misses it. Typical fixture: a B_SPLINE_CURVE_WITH_KNOTS whose knot multiplicities don't match the required count (e.g., degree 2 with 3 control points needs 6 knots, but the multiplicities sum to 7); a Fail-class condition that gets auto-mended and silently demoted. Bug-reporter language: "kernel hid an error", "fail downgraded to warning silently", "wrong knot count not reported".

Reproducer recipe

An entity that triggers a Fail-class check (e.g., a `B_SPLINE_CURVE_WITH_KNOTS` whose knot count is off-by-one — degree 2 with 3 control points but knot_multiplicities sum to 7 instead of the expected 6) but is then auto-fixed by the reader.

Expected kernel behavior

Warn and accept: always preserve the original severity; record the Mend as a separate "auto-corrected" event. Must not silently downgrade Fail to Warning.

Notes

Synonyms: "silent error fix", "fail demoted". Provenance tier: runtime-only; bytes alone cannot demonstrate this defect; the symptom is a runtime mutation of the diagnostic-severity record (Fail demoted to Warning) inside the kernel's check object. The static fixture only encodes the input precondition; observing the demotion requires a kernel runtime trace.
