Ls044 — String concatenation across consecutive literals (not allowed)

§12.1c string-quoting (impacts grammar shape)

P1 — silent data loss

syntax

View raw fixture (.stp) step-examples/12-1c-syntax/Ls044.stp

Sources

  • N055

Description

Unlike C, Part 21 does not concatenate adjacent string literals. `'foo' 'bar'` is two strings, not one. Generators that line-wrap long strings by writing two consecutive literals corrupt the data when the position expects exactly one STRING.

Reproducer recipe

`FILE_DESCRIPTION(('first part' ' second part'),'2;1');`

Expected kernel behavior

When grammar expects a single STRING, reject. When position is `LIST OF STRING`, accept as two list elements (warn — likely unintended).

Notes

Synonyms: "adjacent STEP string literals", "two strings line-wrap into one slot", "C-style string concatenation in STEP", "STEP string concatenation not allowed", "consecutive literals corrupt data".
