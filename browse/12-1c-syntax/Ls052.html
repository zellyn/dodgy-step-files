Ls052 — Instance ID just past `UINT64_MAX` wraps to a low-numbered ID

§12.1c instance-namespace

silent-loss syntax

View raw fixture (.stp) step-examples/12-1c-syntax/Ls052.stp

Sources

  • T016, T017, A022

Description

`UINT64_MAX` is 18446744073709551615. The ID 18446744073709551617 is two greater and wraps modulo 2^64 to 1, which collides with the low-numbered `#1` namespace and may enable type confusion if the reader does not validate before storing.

Reproducer recipe

`#18446744073709551617=AXIS2_PLACEMENT_3D('wrap',#1,$,$);`

Expected kernel behavior

Detect overflow during digit accumulation and reject with `E_INSTANCE_ID_RANGE`; never silently wrap.

Notes

**See also**: Ls038, Ls051. **OCC behavior**: silently accepts (no diagnostic, empty result); catalog disallows silent-accept. Kernel-bug witnessed: receivers enforcing the spec must reject (or surface a diagnostic); silent acceptance defeats the catalog's stated invariant. Synonyms: "instance ID wraps to low number", "ID past UINT64_MAX collides with #1", "modular wrap on STEP instance ID", "STEP ID overflow type confusion", "huge ID wraps to small ID".
