Ls001 — REAL literal missing mandatory decimal point

§12.1c numeric-literal grammar

syntax

View raw fixture (.stp) step-examples/12-1c-syntax/Ls001.stp

Sources

  • T021, N015, Q051

Description

ISO 10303-21 grammar requires every REAL to carry a decimal point (`1.`, `1.0`, `0.5`). Generators that print integer values into REAL slots emit `1` where `1.` is required (e.g. `IFCDIRECTION((1,0,0))`). stepcode warns and salvages via `istringstream >> double`; strict readers reject. Implementors Issue 003 records the original disagreement: integers must not be followed by a dot, REALs must be.

Reproducer recipe

`#1=DIRECTION('',(1,0,0));` instead of `(1.,0.,0.)`.

Expected kernel behavior

Strict reject by default; lenient mode auto-promote INTEGER → REAL with a warning. Never silently coerce.

Notes

A primary cause of integer-vs-real type-coercion bugs. **See also**: Ad049, Ls002, Ls003, Ls004, Ls005, Ls006, Ls009. **OCC behavior**: silently coerces the integer to a REAL with no diagnostic; kernel mishandling; the catalog above forbids silent coercion. Synonyms: "REAL with no decimal point", "integer where REAL required", "1 written instead of 1.", "DIRECTION coords missing dots", "STEP REAL missing trailing period".
