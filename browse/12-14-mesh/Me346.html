Me346 — init_info_preservation_flag: near-coincident vertex pair forces clone_info to copy degenerate triangle info pointer

§12.14 mesh defects (sub-class: Basic_TMesh.init / info-preservation-flag)

topology

Sources

  • MeshFix `Basic_TMesh.init` Branch 7 (*INFO_PRESERVATION_FLAG*: `if (clone_info) { nt->info = t->info
  • }`)
  • `MESH_HEAL_COVERAGE.md`.

Description

A 2-triangle mesh: t0=(v0,v1,v3) is valid; t1=(v0,v1,v2) is near-degenerate — v1=(1,0,0) and v2=(1+1e-8,0,0) are sub-tolerance coincident, making t1 effectively zero-area. When a healer calls init with clone_info=true, each triangle's void* info pointer is copied to the clone — including the degenerate triangle's info, which may hold a repair tag or be NULL.

Reproducer recipe

v0=(0,0,0), v1=(1,0,0), v2=(1+1e-8,0,0), v3=(0.5,1,0); t0=(v0,v1,v3), t1=(v0,v1,v2); assert_vertex_pair_distance_lt(1,2,1e-6); assert_triangle_area_lt(1,1e-9).

Expected kernel behavior

Branch 7 fires when clone_info=true; degenerate t1's info pointer is copied to clone triangle; healer must not rely on info being clean post-init.
