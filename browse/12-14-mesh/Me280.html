Me280 — checkGeometry_memory_alloc_fail_vertices: near-coincident vertex pair, alloc guard (Branch 1)

§12.14 mesh defects (sub-class: checkGeometry / coincident-vertex-alloc-guard)

Sources

  • MeshFix `checkAndRepair::checkGeometry` Branch 1 (*MEMORY_ALLOCATION_FAILURE*: vertex array alloc fails, skip coincident-vertex scan)
  • `MESH_HEAL_COVERAGE.md`.

Description

A 3-triangle mesh where vertex v0=(0,0,0) and vertex v6=(5e-8,0,0) are spatially near-coincident (distance < 1e-7) but belong to different triangles with no shared edge. Branch 1 fires when the sort buffer for vertex coordinates cannot be allocated — the function skips the coincident-vertex scan entirely. The same geometry would be caught by Branch 2 (COINCIDENT_VERTICES_EDGE_ABSENT) if allocation succeeds.

Reproducer recipe

t0=(v0,v1,v2) upper triangle; t1=(v3,v4,v5) clean lower triangle; t2=(v6,v7,v8) with v6 at (5e-8,0,0) near v0; assert v0-v6 distance < 1e-7 and no shared triangle.

Expected kernel behavior

Branch 1 fires on alloc failure; coincident vertex pair (v0,v6) would be flagged as COINCIDENT_VERTICES_EDGE_ABSENT by Branch 2 if alloc succeeds.
