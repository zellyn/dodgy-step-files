Me283 — checkGeometry_memory_alloc_fail_edges: coincident edge pair, edge alloc guard (Branch 4)

§12.14 mesh defects (sub-class: checkGeometry / coincident-edges-alloc-guard)

topology

Sources

  • MeshFix `checkAndRepair::checkGeometry` Branch 4 (*MEMORY_ALLOCATION_FAILURE_EDGES*: edge array alloc fails, skip coincident-edge scan)
  • `MESH_HEAL_COVERAGE.md`.

Description

Two triangles where edge (v0,v1) and edge (v3,v4) are spatially coincident (v0==v3 and v1==v4 by coordinate) but topologically distinct (different vertex indices). Branch 4 fires when ExtTriMesh::newEdges fails to allocate the sort buffer for edge coordinates — coincident-edge detection is skipped. The same geometry triggers Branch 5 (COINCIDENT_EDGES) when allocation succeeds.

Reproducer recipe

t0=(v0,v1,v2) with v0=(0,0,0), v1=(1,0,0); t1=(v3,v4,v5) with v3=(0,0,0), v4=(1,0,0); assert vertex pair distances < 1e-12 and edge_pair_coincident.

Expected kernel behavior

Branch 4 fires on alloc failure; coincident edge pair would be flagged as COINCIDENT_EDGES by Branch 5 if alloc succeeds.
