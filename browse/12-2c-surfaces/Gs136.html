Description

Torus whose rotation axis is NOT aligned with global Z-axis causes Singularity() to produce incorrect results. Code assumes axis=(0,0,1) and singular circles lie at (R+r, z=0) and (R-r, z=0); rotated torus has singularities in rotated frame.

This type mismatch -- not axis-alignment of the torus's singularity detection -- is the file's actual defect. Actual kernel behavior: reject at parse time -- a kernel must validate that each entity's references resolve to an instance of the required type before using it, and refuse to build (or dereference as a VECTOR) a reference that actually points to a CARTESIAN_POINT, rather than read past the type mismatch into whatever memory layout results.
