Gs058 — `SURFACE_PATCH` `transition_code` / `u_sense` / `v_sense` parsed but ignored (BRL-CAD step-g)

§12.2c surface / curve degeneracies (sub-class: patch continuity metadata lost)

P1 — silent data loss

geometry

View raw fixture (.stp) step-examples/12-2c-surfaces/Gs058.stp

Sources

  • BRL-CAD `src/conv/step/step-g/SurfacePatch.cpp` `Load` reads `u_transition`, `v_transition` (Transition_code enum: `DISCONTINUOUS` / `CONTINUOUS` / `CONT_SAME_GRADIENT` / `CONT_SAME_GRADIENT_SAME_CURVATURE`) and `u_sense` / `v_sense` BOOLEANs into class members
  • `LoadONBrep` is a stub printing `"not implemented"` and returning false
  • bug-reporter language: "SURFACE_PATCH transition_code dropped on import", "C2 continuity hint lost by step-g", "u_sense / v_sense booleans not applied".

Sender

Producers that compose a quilt of patches with explicit continuity guarantees — CATIA Class A surface tools, ICEM Surf, and legacy aero/automotive translators all emit `CONT_SAME_GRADIENT_SAME_CURVATURE` to declare C2 continuity at patch boundaries.

Description

Even when the consumer **does** intend to promote a `RECTANGULAR_COMPOSITE_SURFACE` (Gs057) to a single B-spline, the patch-by-patch continuity metadata (`u_transition` / `v_transition` and the per-patch `u_sense` / `v_sense` direction flags) carries information the receiver needs to perform that promotion correctly: a `CONT_SAME_GRADIENT_SAME_CURVATURE` boundary must be promoted with multiplicity = degree-2 knot at the patch boundary; a `DISCONTINUOUS` boundary must be promoted with multiplicity = degree+1. step-g parses both attributes into the in-memory model and then never reads them back; the receiver re-evaluates continuity numerically, which both costs CPU and may produce a kink the producer's continuity hint would have prevented.

Reproducer recipe

`#101=SURFACE_PATCH(#100, .CONT_SAME_GRADIENT_SAME_CURVATURE., .CONT_SAME_GRADIENT_SAME_CURVATURE., .T., .F.);`. step-g loads the value but applies it nowhere.

Expected kernel behavior

heal-and-accept — every importer that consumes a `SURFACE_PATCH` (whether via `RECTANGULAR_COMPOSITE_SURFACE` or directly) must convert the parsed `transition_code` into the appropriate knot multiplicity at the patch boundary; emit `W_PATCH_TRANSITION_HONORED` recording which transition was applied.

Notes

**See also**: Gs057, Gn017. Synonyms: "SURFACE_PATCH transition_code dropped", "step-g ignores patch continuity metadata", "CONT_SAME_GRADIENT_SAME_CURVATURE not applied", "u_sense / v_sense booleans lost", "patch-boundary C2 hint discarded by importer".
