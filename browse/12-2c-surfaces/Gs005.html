Gs005 — Surface periodicity not declared but actually closed

§12.2c surface-degeneracy

P1 — silent data loss

geometry

View raw fixture (.stp) step-examples/12-2c-surfaces/Gs005.stp

Sources

  • F069, Q018, G108

Sender

ProSTEP UG ug_exhaust-A.stp #18360 (U-closed BSpline)

Description

A `B_SPLINE_SURFACE_WITH_KNOTS` whose first and last control rows coincide is geometrically closed but the schema flag `u_closed`/`v_closed` is set to `.F.`. The receiver does not recognise the closure unless it explicitly tests for it; seam insertion and PCurve continuity logic both fall back to non-periodic-surface cases and produce wrong results at the wraparound.

Reproducer recipe

`B_SPLINE_SURFACE_WITH_KNOTS` with control net rows[i,0] equal to rows[i,N] within 1e-7; `u_closed:=.F.`.

Expected kernel behavior

detect the geometric closure on near-closed BSpline surfaces (regardless of the flag) and treat the surface as periodic for natural-bound and seam-insertion logic; or reject the input as inconsistent.

Notes

**See also**: Gp013. Synonyms: "BSpline surface declared non-periodic but actually closed", "u_closed flag false but first/last rows coincide", "near-period BSpline surface periodicity not detected", "geometric closure on B-spline surface not flagged", "first and last control rows identical but flag says non-periodic".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Byte assertions

  • contains(b'B_SPLINE_SURFACE_WITH_KNOTS(')
  • count(b'(10.0,0.0,0.0)') >= 2

Tier-3 assertions

  • load == "ok"
  • face[0].surface_type == "bspline"
  • face[0].bspline.is_u_periodic == True
