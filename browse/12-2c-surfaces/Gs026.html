Gs026 — Helix on `CYLINDRICAL_SURFACE` mis-projected: pcurve missing or BSpline-approximated (analytic line lost)

§12.2c surface-degeneracy

P0 — receiver crash / hang / OOM

crash geometry

View raw fixture (.stp) step-examples/12-2c-surfaces/Gs026.stp

Sources

  • R027, G073

Description

When a 3D helix on a `CYLINDRICAL_SURFACE` is projected to the surface's parametric domain, the projection ought to yield an analytic 2D `LINE` segment — the helix unwraps cleanly onto a straight UV path. The actual translator either emits an empty `SURFACE_CURVE.associated_geometry` list (no pcurve at all on a non-trivial helical 3D `B_SPLINE_CURVE_WITH_KNOTS` `EDGE_CURVE`), or emits a BSpline approximation with poor accuracy — losing the analytic-line representation and inflating tolerance budgets downstream.

Reproducer recipe

Edge whose 3D curve is helix on cylinder, no pcurve attached; reference from face on `CYLINDRICAL_SURFACE`.

Expected kernel behavior

detect that the projected pcurve is collinear in UV and emit it as a 2D `LINE` pcurve, or reject as a translation-quality issue. A normal-distance closeness check is sufficient for the elementary-surface family.

Notes

Cross-oracle: pure-Python Part-21 validator accepts (`accept`); OCCT crashes (`signal(11)`). The crash is on the kernel side — the file is spec-conformant Part-21.
