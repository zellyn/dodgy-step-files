Description

A single `ADVANCED_FACE` on a `PLANE` has one boundary edge whose 3D curve is a clamped, non-periodic degree-3 `B_SPLINE_CURVE_WITH_KNOTS` (4 poles) shaped as a near-loop: its start pole `(0,0,0)` and end pole `(5e-8,0,0)` are only `5e-8` apart — BELOW the fixture's own declared `UNCERTAINTY_MEASURE_WITH_UNIT` of `1e-7` (so the curve is "closed" for all practical modeling purposes) but ABOVE `Geom_BSplineCurve::IsClosed()`'s own much tighter internal `~1e-8` test (so OCCT's own geometric-closure flag reports `False` — this is genuinely the "not formally flagged Closed" case). The edge's `edge_start` vertex sits at the curve's exact MIDPOINT (parameter 0.5, an unambiguous on-curve point, live-computed via `Geom_BSplineCurve::Value(0.5)`); `edge_end` sits at the curve's exact START pole `(0,0,0)` (projects exactly to parameter 0). Naive projection therefore yields `w1=0.5 > w2=0.0` on a curve that is neither periodic nor formally closed — the scenario the packet spec's "closed only within 3D tolerance" subvariant names.

Reproducer recipe

`B_SPLINE_CURVE_WITH_KNOTS('name',3,(p0,p1,p2,p3),.UNSPECIFIED.,.F.,.F.,(4,4),(0.0,1.0),.UNSPECIFIED.)` with `p3` positioned `5e-8` from `p0` (a near-loop); `VERTEX_POINT`s at the curve's exact midpoint (edge_start) and exactly at `p0` (edge_end).

Expected kernel behavior

Because the curve is near-closed within the model's own declared tolerance but not periodic and not formally `.Closed.`, a receiver must NOT treat `w2=0.0` (which naively equals the curve's own first parameter) at face value; it must recognize that a point this close to the curve's near-coincident start/end poles could legitimately be intended as the curve's LAST parameter instead, and re-target `w2` to `cl` (here `1.0`) — producing a well-formed, non-degenerate `[0.5, 1.0]` parameter range — rather than either leaving `w1>w2` unresolved or collapsing both parameters to the same value.

Notes

Live-verified directly against the fixture's own bytes (default read — this parameter-range repair runs unconditionally as part of ordinary edge translation): the resulting edge's 3D curve reports parameter range `(0.49999999999999994, 1.0)` — NOT the naive/raw `(0.5, 0.0)`, confirming `w2` was correctly re-targeted from the curve's first parameter to its TRUE last parameter; evaluating the curve at `w2=1.0` gives `(5e-08, 0.0, 0.0)` — the curve's real end pole, only `5e-8` from the file's stated `edge_end` vertex coordinates `(0,0,0)`, well within the declared `1e-7` tolerance; the resulting face closes as a valid triangle (curved + 2 straight sides), area `13.8`, `shape_null=False`. Fills `stp-edge-curve-param-range`'s previously-missing "B-spline curve closed only within 3D tolerance" subvariant (the last of 3 missing; see also Gs201, Gs202 — the class is now fully covered, 6 of 6 subvariants demonstrated across Gs029/Gp171/Twi017/Twi086/Gs201/Gs202/Gs203).
