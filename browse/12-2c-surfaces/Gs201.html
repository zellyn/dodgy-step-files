This is the SAME function Gs029 (periodic wrap-wrong-way, `:243-246`) and Twi086 (`w1==w2`, `:339-344`) exercise — this fixture targets its FIRST, distinct branch (out-of-bounds clamp on an ordinary bounded curve, unrelated to periodicity or closure).

Description

A single `ADVANCED_FACE` on a `PLANE` is a 4×4 rectangle; one boundary edge's 3D curve is a `TRIMMED_CURVE` over a `LINE`, with DECLARED bounds `PARAMETER_VALUE(1.5)`..`PARAMETER_VALUE(4.5)` — but the `EDGE_CURVE`'s own `VERTEX_POINT`s sit at `(1.0,0.0,0.0)` and `(5.0,0.0,0.0)`, which project onto the underlying (unbounded) `LINE` at parameters 1.0 and 5.0 — BOTH outside the curve's declared `[1.5, 4.5]` bounded range. STEP's `EDGE_CURVE` never stores explicit trim parameters; OCCT always derives them by projecting the edge's vertex coordinates onto the 3D curve, so a bounded curve whose OWN definition range is narrower than where the vertices actually sit is a well-formed but self-inconsistent file — a real pattern from writers that trim a curve entity conservatively but position vertices from unrelated (looser) tessellation or snapping logic.

Reproducer recipe

`LINE` at the origin, direction `(1,0,0)`; `TRIMMED_CURVE('name',#line,(PARAMETER_VALUE(1.5)),(PARAMETER_VALUE(4.5)),.T.,.PARAMETER.)` as `EDGE_CURVE.edge_geometry`; `VERTEX_POINT`s at `(1.0,0.0,0.0)` and `(5.0,0.0,0.0)` (line-parameters 1.0 and 5.0, both outside `[1.5,4.5]`); the edge is one side of an otherwise-ordinary rectangular `ADVANCED_FACE` boundary loop.

Expected kernel behavior

the edge-parameter-range repair stage must detect that the vertex-projected parameters fall outside the curve's own `[FirstParameter, LastParameter]` and clamp each independently to the nearest bound (`w1<cf → w1=cf`; `w2>cl → w2=cl`), producing an edge whose 3D-curve parameter range is `[1.5, 4.5]` — the curve's own declared domain — rather than the geometrically-implied-but-out-of-range `[1.0, 5.0]`, and rather than crashing or leaving an invalid/unresolvable trim.

Notes

Live-verified directly against the fixture's own bytes (default read — this parameter-range repair runs unconditionally as part of ordinary edge translation, unlike Gn177-Gn179's opt-in healers): the resulting edge's 3D curve reports parameter range `(1.5, 4.5)` — EXACTLY the curve's own declared bounds, confirming both out-of-range parameters were independently clamped (not merely one, and not left at the raw `(1.0, 5.0)` vertex-projected values); the resulting face still closes correctly (area `16.0`, the full 4×4 rectangle, live-verified) — OCCT reconciles the small gap between the clamped curve endpoint `(1.5,0,0)`/`(4.5,0,0)` and the actual vertex coordinates `(1,0,0)`/`(5,0,0)` via edge tolerance rather than leaving an open/invalid boundary. Fills `stp-edge-curve-param-range`'s previously-missing "parameter outside the curve's own bounded definition range → clamped" subvariant (1 of 3 missing; see also Gs202, Gs203). Synonyms: "EDGE_CURVE vertex parameter outside curve bounds clamp", "edge-parameter-range repair clamps a bounded-curve out-of-range projection", "TRIMMED_CURVE declared range narrower than vertex projection", "out-of-range trim parameter clamped to curve FirstParameter LastParameter", "writer trims curve conservatively vertices positioned looser".
