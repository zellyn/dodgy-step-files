Description

Rectangular face with three inner hole wires (not just a claimed 2-wire-vs-3-wire edge case) crashes the reader (SIGSEGV) as soon as the extra bound wire is present; loads cleanly with only the outer wire — ShapeFix_Face::FixWiresTwoCoincEdges is never reached

Reproducer recipe

Expected kernel behavior

heal or reject (mechanism-specific; see Description)

Notes

Corrected 2026-07-17 (truth-in-labeling audit): retitled/redescribed — original claimed ShapeFix_Face::FixWiresTwoCoincEdges handles the 2-wire coincidence case but misses the 3rd wire; that method is never reached because the file crashes (SIGSEGV) during shape translation before any wire-level healing pass runs. Isolation testing (stripping the extra bound wire) confirms the outer-bound-alone face loads cleanly; the crash is reproduced by restoring the additional wire. Part of the ~127-entry `ShapeFix_Face`/`ShapeAnalysis_CheckSmallFace` misnomer family — see `BACKLOG.md` Q14. Synonyms: "multi-bound face crashes reader, outer-alone loads clean", "any single inner hole (not just a 3rd) crashes the reader".
