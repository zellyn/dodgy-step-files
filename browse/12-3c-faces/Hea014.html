Hea014 — Compound rebuild misses location chain when child SHAPE_REPRESENTATION via REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION at non-identity placement

§12.3c faces/sewing

topology

Sources

  • OCCT MANTIS#0033806
  • OCCT MANTIS#0033791 (OCCT MANTIS tracker 502 as of 2026-05-02)

Description

A document is processed through a generic shape-rebuild pass (`ShapeCustom`-class operation). The compound is rebuilt from modified children, but the rebuild loses the source compound's location attribute and any cached context state attached to root.

Reproducer recipe

Compound containing one solid at non-identity location; pass through shape-rebuild. Output compound has identity location.

Expected kernel behavior

Heal and accept: rebuild operations preserve the input shape's TopLoc location; cached context propagates from input to output. Must not silently lose location chain.

Notes

**See also**: A067, A073. Defect manifests at runtime (TopLoc state is API-level); fixture establishes the input precondition (compound with solid at non-identity placement via REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION). Synonyms: "assembly transform lost on rebuild", "compound rebuild drops child placement", "non-identity transform ignored on REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION", "child SHAPE_REPRESENTATION placed at wrong location after rebuild".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(9) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 4
  • face[0].surface_type == "plane"
  • n_vertices_total >= 8
