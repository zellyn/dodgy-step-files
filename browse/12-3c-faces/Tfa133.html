Description

Face with a counter-clockwise outer wire and two clockwise inner wires crashes the reader (SIGSEGV) as soon as the extra bound wire is present; loads cleanly with only the outer wire — ShapeFix_Face::FixOrientation is never reached

Reproducer recipe

Expected kernel behavior

Notes

Corrected 2026-07-17 (truth-in-labeling audit): retitled/redescribed — original claimed ShapeFix_Face::FixOrientation flips the outer wire's winding, breaking the inner wires' relative-consistency; that method is never reached because the file crashes (SIGSEGV) during shape translation before any wire-level healing pass runs. Isolation testing (stripping the extra bound wire) confirms the outer-bound-alone face loads cleanly; the crash is reproduced by restoring the additional wire. Part of the ~127-entry `ShapeFix_Face`/`ShapeAnalysis_CheckSmallFace` misnomer family — see `BACKLOG.md` Q14. Synonyms: "multi-bound face crashes reader, outer-alone loads clean", "inner wires crash reader regardless of relative winding, outer-alone loads clean".
