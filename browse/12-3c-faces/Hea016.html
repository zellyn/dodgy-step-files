Hea016 — Empty solid output from STEP export of complex body, despite STL succeeding

§12.3c faces / shape healing

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-3c-faces/Hea016.stp

Sources

  • FreeCAD #20396
  • bug-reporter language: "Models exported to STEP crash or produce empty objects", "appears to export fine but results in an empty object", "STL and 3MF export work, STEP doesn't".

Sender

FreeCAD writer pipeline where the STL/3MF tessellator succeeds but the STEP B-rep emitter encounters a face it cannot represent in B-rep form.

Description

A body that exports cleanly to STL/3MF emits a STEP file that imports as zero objects. The producer's writer reaches a face whose underlying surface is a degenerate `B_SPLINE_SURFACE_WITH_KNOTS` (collapsed control-point net producing a zero-area surface), silently skips the face, and the resulting open shell is wrapped as `MANIFOLD_SOLID_BREP` whose underlying topology has zero closed shells; the receiver's shape-healer cannot recover any solid.

Reproducer recipe

STEP file with one `MANIFOLD_SOLID_BREP` whose `CLOSED_SHELL` references zero `ADVANCED_FACE`s — an empty shell wrapped as a solid.

Expected kernel behavior

writer rejects empty-shell wrap before emission; receivers must reject `CLOSED_SHELL` with no faces with a clear diagnostic.

Notes

**See also**: A074. Synonyms: "STEP empty object despite STL working", "writer drops degenerate face and emits empty shell", "zero-face CLOSED_SHELL", "step export silently empty".

Expected validation

occt=shape(1)/shape(1) gmsh=empty ifc=schema_n/a

Byte assertions

  • contains(b'CLOSED_SHELL')
  • contains(b'MANIFOLD_SOLID_BREP')

Tier-3 assertions

  • load == "ok"
