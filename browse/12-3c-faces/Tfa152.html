Description

Degenerate zero-area face loads as encoded (no classification applied); spot-face checking is never invoked on an ordinary read

Reproducer recipe

Expected kernel behavior

Accept: a face whose four inner-wire corners all collapse to a single point (an exact-zero-area loop) must still load with the face present exactly as encoded, matching load == ok — a plain read must never apply any small-area or degeneracy classification to decide whether to keep or drop geometry; that judgment, if ever made, belongs only to an explicitly requested healing pass that can weigh the zero area against the model's manufacturing tolerance rather than treating exact zero as automatically disqualifying.

Notes

Corrected 2026-07-17 (truth-in-labeling audit): retitled/redescribed — original claimed spot-face checking's threshold check can't distinguish tolerance from true zero-area degeneracy; that checker is never invoked on an ordinary read, so no classification (correct or mistaken) is ever produced. Part of the ~127-entry face-repair/small-face-check misnomer family — see `BACKLOG.md` Q14. Synonyms: "zero-area face loads without classification", "spot-face check never invoked at exact-zero area".
