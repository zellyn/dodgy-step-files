Hea007 — Transferring parameter values between 3D curve and pcurve when EDGE_CURVE has B_SPLINE_CURVE_WITH_KNOTS in 3D and a LINE pcurve with non-affine reparam

§12.3 (sub-class: shape-healing) — parameter transfer

P1 — silent data loss

topology

View raw fixture (.stp) step-examples/12-3c-faces/Hea007.stp

Sources

  • OCCT `ShapeAnalysis_TransferParameters::Perform` (`ShapeAnalysis_TransferParameters.hxx:63`)

Description

An EDGE_CURVE whose 3D curve and pcurve are correctly shaped but whose parameter ranges differ by a non-affine reparam (e.g., 3D representation is a non-uniform B_SPLINE_CURVE_WITH_KNOTS with non-uniform knot vector while the pcurve is a uniform LINE). Transferring a list of sample parameters from one representation to the other is non-trivial; naive linear remapping produces wrong sample points; a point at parameter t on one curve doesn't correspond to the same arc-length point on the other.

Reproducer recipe

An EDGE_CURVE whose 3D representation is a non-uniform B_SPLINE_CURVE_WITH_KNOTS and whose pcurve is a uniform LINE — 3D arc-length and pcurve U-distance follow different monotone functions of the underlying parameter.

Expected kernel behavior

apply the actual reparameterization map (often via numerical inversion); reject the transfer if the inversion is ill-conditioned.

Notes

Used internally by other gap-bridging and seam-fixing healers. Synonyms: "non-affine reparam between 3D and pcurve", "naive linear remap produces wrong sample points", "B-spline 3D with line pcurve different parameter spacing", "parameter transfer requires non-affine mapping".

  • contains(b'uniform_pcurve')
  • contains(b'B_SPLINE_CURVE_WITH_KNOTS(')
