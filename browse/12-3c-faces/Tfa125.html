Spherical-surface ADVANCED_FACE with a degenerate south-pole (v=0) loop is wrapped in a GEOMETRIC_CURVE_SET; the reader never builds a live face at all (shape comes back empty)

Reproducer recipe

Expected kernel behavior

Accept: a spherical-surface ADVANCED_FACE with a degenerate south-pole loop wrapped inside a GEOMETRIC_CURVE_SET is, per the schema, a geometric-curve-set entity rather than a face-topology entity, so a read correctly yields an empty shape (shape.IsNull() == True, n_faces == 0) — there is no periodic-degenerate seam handling to perform because the face is never built from the curve-set wrapper.

Notes

Corrected 2026-07-17 (truth-in-labeling audit): retitled/redescribed — original claimed periodic-degenerate seam repair handles V-degenerate surfaces but assumes the U parametric direction is always non-degenerate; that checker/fixer is never invoked because the face never survives translation (the `GEOMETRIC_CURVE_SET` wrapper is a type the builder dispatch skips). The `shape_null == True` / `occt=empty/empty` Expected-validation line below was already correct; only the mechanism attribution was wrong. Part of the ~127-entry face-repair/small-face-check misnomer family — see `BACKLOG.md` Q14. **See also**: Tfa121, Tfa160, Tfa169 (same `GEOMETRIC_CURVE_SET`-orphaning pattern). Synonyms: "GEOMETRIC_CURVE_SET wrapped face never translates", "spherical south-pole degenerate face orphaned in curve set".
