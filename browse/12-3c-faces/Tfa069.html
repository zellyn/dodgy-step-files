Tfa069 — Lettering bottoms not closed in exported STEP (text-on-surface non-solid result)

§12.3c faces / sewing / free bounds

P1 — silent data loss

topology

Sources

  • FreeCAD #20588
  • bug-reporter language: "STEP Export does not contain all the geometry", "Gear16 looks OK in FreeCAD and passes geometry check but exports to a non-solid", "all the bottoms of the lettering is not closed".

Sender

FreeCAD with Draft-text or Sketcher-derived text features applied as Pad/Pocket on a surface.

Description

A body with embossed lettering ("text on surface" PartDesign feature) emits a STEP where the bottom faces of each letter pocket — the inner-floor planar faces — are missing from the shell. The receiver loads but the geometry-check pass reports "shell has free edges" (open shell). The on-disk symptom is a `MANIFOLD_SOLID_BREP` whose face count is exactly N short of expected, where N is the number of letter glyphs, each missing exactly the bottom face. The faces are emitted but their `FACE_OUTER_BOUND` `EDGE_LOOP` is missing one of the boundary edges, leaving a partial floor.

Reproducer recipe

STEP solid with 3 small rectangular pocket-floors where one pocket-floor face's `EDGE_LOOP` has 3 edges instead of the required 4 — a missing edge produces an open-bound floor.

Expected kernel behavior

writer validates `EDGE_LOOP` closure before emission; receivers should sew open boundaries when a missing edge is reconstructable from adjacent geometry, or warn.

Notes

**See also**: P015. Synonyms: "lettering bottoms not closed", "text feature pocket floor missing", "embossed text exports as non-solid", "EDGE_LOOP one edge short on STEP export".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(7) ifc=schema_n/a

Byte assertions

  • count_entity_def(b'EDGE_LOOP') >= 1
  • contains(b'FACE_OUTER_BOUND')
