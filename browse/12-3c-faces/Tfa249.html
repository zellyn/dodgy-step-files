Description

`ADVANCED_FACE` on a `PLANE`: outer 4-edge 10×10 square wire where edge A(0,0,0)-B(10,0,0) is ONE uninterrupted `EDGE_CURVE` (never pre-split), plus an inner `FACE_BOUND` triangle wire (V1-V2-V3) whose vertex V1 is a NEW, independent `VERTEX_POINT` at (5.0, 0.0, 5.0E-8) — geometrically on the interior of edge AB (within its default 1e-7 tolerance) but topologically unrelated to it (V1 is only ever an endpoint of the two inner-wire edges, never of edge AB). The 5e-8 Z-offset is deliberate: the checker's own projection call skips an EXACT zero-distance hit (Sources, line 539), so a vertex placed mathematically exactly on the curve would NOT trigger the mechanism — it must be near-but-not-exactly on it, inside the tolerance zone.

Reproducer recipe

`ADVANCED_FACE` whose `FACE_OUTER_BOUND` wire has an uninterrupted edge A-B, plus a `FACE_BOUND` (or second wire) whose own vertex V is a distinct `VERTEX_POINT` entity (never referenced by edge A-B) placed within tolerance of, but not exactly on, A-B's curve interior. Runtime invocation (live-verified 2026-07-12, OCP 7.8.1): reconstruct the face directly via `BRepBuilderAPI_MakePolygon`/`BRepBuilderAPI_MakeFace` from this file's raw vertex/edge coordinates, then call `ShapeAnalysis_CheckSmallFace().CheckSplittingVertices(face, mapEdges, mapParam, allVertCompound)` with an explicit `SetTolerance(1e-4)` — returns 2 (V1 visited once per adjacent inner-wire edge by the face's un-deduplicated vertex walk, both times identified as splitting edge AB's interior), with `mapEdges` binding V1 to edge AB. TWO pitfalls, both live-confirmed: (1) the checker's precision member is never initialized by its constructor, so omitting `SetTolerance` silently returns 0 regardless of geometry; (2) loading this file through the standard `STEPControl_Reader().TransferRoots()` pipeline does NOT preserve the untouched topology — every STEP face translation is unconditionally routed through `XSAlgo_AlgoContainer::ProcessShape` (`STEPControl_ActorRead.cxx` ~line 1660), which even with no resource sequence configured (and with no `Interface_Static` switch able to disable it) falls back to running `ShapeFix_Shape::Perform()` unconditionally, resolving the same T-junction via a different, already-covered wire-level repair first (observed: edge AB arrives already split in two at (5,0,0), i.e. V1 is by then a genuine shared endpoint — the fate of all 17 misnamed fixtures). Reproducing THIS mechanism requires bypassing that mandatory per-face default-healing pass.

Expected kernel behavior

the small-face analyzer's splitting-vertex check should flag V as a splitting vertex of edge A-B; the face-splitting repair should divide the face into two regular sub-faces along a synthetic edge from V to its projection.
