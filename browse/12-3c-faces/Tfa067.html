Tfa067 — Top face dropped after STEP import (CLOSED_SHELL cube whose top FACE_OUTER_BOUND edge has 3D LINE vs B_SPLINE_CURVE_WITH_KNOTS pcurve mismatch)

Description

A solid imported from STEP loses one or more faces during translation. Common cause: the face's `FACE_OUTER_BOUND` references an EDGE_LOOP whose edge translation fails silently — e.g., a 3D LINE going one way while the associated PCURVE is a degree-2 B_SPLINE_CURVE_WITH_KNOTS with control points that dip in V, producing a 3D-curve / pcurve mismatch beyond tolerance — so the entire face is dropped. Visible in viewers as a hole in the otherwise-solid part.

Reproducer recipe

A CLOSED_SHELL six-face cube where the top face's EDGE_LOOP has one edge whose 3D LINE (e.g., (0,0,1)->(1,0,1)) and PCURVE (a B_SPLINE_CURVE_WITH_KNOTS in UV with a 0.1 dip in V) disagree by ~0.1 mm. STEP reader silently drops the top face; resulting shell has 5 faces.

Expected kernel behavior

face-translation failures must be reported as diagnostics (not silently dropped); if all bounds cannot be resolved, mark the face as invalid but preserve it in the topology so downstream code can heal or report.

Notes

**See also**: Tsh001, Tsh044. Synonyms: "top face missing after STEP import", "cube imported missing one face", "FACE_OUTER_BOUND has 3D LINE but pcurve B-spline mismatch", "import drops face due to curve type mismatch".

Expected validation

occt=shape(1)/shape(1) gmsh=shape(27) ifc=schema_n/a

Tier-3 assertions

  • n_edges_total >= 24
  • face[0].surface_type == "plane"
  • face[5].surface_type == "plane"
